# Время и окружение Pine

Выпуск `pine-environment-20261024.1` закрепляет отдельный профиль
`openpine.environment.vN.1` для каждой версии. Окружение использует существующий
UTC/24×7 календарь и записанные события. Часовой пояс компьютера и текущие
часы не участвуют в вычислении Pine.

Основа — импортированные версионные записи wiki и официальные описания
[времени](https://www.tradingview.com/pine-script-docs/concepts/time/),
[состояний бара](https://www.tradingview.com/pine-script-docs/concepts/bar-states/)
и [инструмента](https://www.tradingview.com/pine-script-docs/concepts/chart-information/).
Неполные старые сигнатуры и правила наблюдаемого исполнения являются явно
принятыми реконструкциями. Точная сверка с движком TradingView выделена отдельно.

## Версии и значения

| Возможность | Принятый срез |
| --- | --- |
| `time`, `year/month/dayofmonth/dayofweek/hour/minute/second` | v1–v6; переменные и функции календарного поля от числового timestamp |
| `timestamp(year,month,day,hour,minute[,second])` | v2–v6; в v1 явный `ENVIRONMENT_VERSION` |
| `time_close` | v4–v6 |
| `barstate.islast/isrealtime` | v2–v6 |
| `barstate.isfirst/ishistory/isnew/isconfirmed` | v3–v6 |
| `barstate.islastconfirmedhistory` | v4–v6 |
| `period`, `isintraday/isdaily/isweekly/ismonthly`, `ticker/tickerid` | исторические имена v1–v3; `tickerid` также в v4 |
| `timeframe.period/multiplier/is*`, `syminfo.ticker/tickerid` | v4–v6; закрытый список находится в bundle |
| `syminfo.prefix/root/session/mintick/pointvalue` | v1–v6 |
| `syminfo.timezone` | v3–v6 |
| `syminfo.currency/basecurrency/type` | v4–v6 |

В v1/v2 вызовы новых календарных функций позиционные; с v3 допускаются
проверенные имена аргументов. Строковые формы timestamp, произвольные часовые
пояса, DST, торговые сессии и `timenow` в этот срез не входят. День недели
нумеруется от воскресенья=1 до субботы=7.

`time` — фактическое открытие текущей свечи в Unix-миллисекундах. `time_close`
— исключающая верхняя граница её календарного интервала. Она не заменяется
временем следующей имеющейся свечи. Для месяца учитывается реальная длина
месяца, включая високосный февраль. Поддерживаются минуты 1…1440 и D/W/M;
открытия должны соответствовать закреплённому UTC-календарю.

Дата timestamp проверяется строго: неверный день/месяц/час даёт
`ENVIRONMENT_DATE`, без нормализации на соседний месяц. Используется диапазон
существующего календаря `[0,253402214400000)` миллисекунд. Числовой `na`
сохраняется как `na`. Числовые и bool поля бара поддерживают историю `[]`.

## Неизменяемые сведения об инструменте

Идентификатор, префикс и тикер берутся из квалифицированного `EXCHANGE:TICKER`.
В текущем spot/custom профиле `root` равен тикеру; корни производных инструментов
не восстанавливаются эвристикой. `session` равен `24x7`, `timezone` — `UTC`.
`timeframe.*` берётся из контекста; свойства инструмента/интервала имеют
qualifier simple, время и флаги — series.

Шаг цены, стоимость пункта, валюты и тип требуют явного описания. Для файлов
доступен `openpine.market-input.1`: обычные OHLCV находятся в `data`, а
`environment` содержит:

```json
{
  "schema_version": "openpine.instrument-environment.1",
  "instrument": {
    "mintick": "0.25",
    "pointvalue": "1",
    "currency": "USD",
    "basecurrency": "ENV",
    "type": "custom"
  }
}
```

Готовый полный файл: [input.json](../examples/environment/input.json). Его
принимают веб-загрузка, CLI job, подготовка запуска и исследования. Обычный
OHLCV-файл по-прежнему подходит для времени и календаря. Запрос недостающего
свойства инструмента даёт `ENVIRONMENT_METADATA`, без подстановки нуля.

Положительные числовые свойства задаются каноническими десятичными строками
длиной до 128 символов; exponent/NaN/Infinity не допускаются. Валюты/тип имеют
ограниченную длину. После нормализации Python-описание тоже неизменяемо.

Binance Spot сохраняет сведения каталога в provenance нового снимка. RunPlan
закрепляет их через content ID снимка; срезы исследований сохраняют provenance.
Worker читает снимок, а не актуальный каталог. Для стратегии этот же mintick
становится шагом брокера. Противоречащий явно заданный шаг или pointvalue,
отличный от 1 для существующей модели брокера, даёт `ENVIRONMENT_BROKER`.
Настройки количества и комиссии сохраняют прежний контракт.

## История и наблюдаемые обновления

Исторический запуск знает полный размер закреплённого входа. `islast` и
`islastconfirmedhistory` истинны на его последнем баре, независимо от размера
порции чтения, страницы графика, паузы или точки продолжения. Исторические
бары имеют `ishistory/isnew/isconfirmed=true`, `isrealtime=false`.

В replay конфигурация может содержать `environments` с элементом для каждого
контекста: `instrument` и `history_last_ms`. Граница прогрева закрепляется
явно. В её пределах принимаются одиночные подтверждённые close-события.
После неё события являются наблюдаемыми realtime-событиями даже при
воспроизведении офлайн. Без объявленной границы все события — наблюдаемые.

| Наблюдаемая фаза | isnew | isconfirmed | isrealtime |
| --- | --- | --- | --- |
| Первое open | true | false | true |
| Очередное update | false | false | true |
| Close после open/update | false | true | true |
| Первый полученный одиночный close | true | true | true |

Preview работает на отдельной ветке состояния. Флаги не отменяют rollback:
`var`, история, массивы и ядра возвращаются к подтверждённой границе.
Стратегия сохраняет существующий расчёт на close. `isfirst` относится к
индексу бара, поэтому сохраняется на всех его обновлениях.

Live фиксирует метаданные и серверную границу прогрева при создании сессии.
`islastconfirmedhistory` отмечает объявленное последнее открытие прогрева;
если при разрешённых пропусках этого бара нет, замещающий бар не создаётся.
При отсутствии объявленной истории флаг ложен. Состояние рынка и наличие
биржевых выходных не угадываются по локальным часам.

## Контексты и восстановление

Числовые time/calendar/mintick/pointvalue и multiplier в `security` либо
`request.security` получают окружение запрошенного контекста. Строковые
результаты и `barstate` внутри запросов пока явно отклоняются `REQUEST_SCOPE`.

Программы с окружением используют typed IR `.10`; совместное применение с
массивами, циклами, inputs и составными результатами сохраняет их проверки.
Runtime-state `.6` закрепляет hash окружения: инструмент, интервал, метаданные,
режим и полную границу входа. Подменённое окружение отклоняется до присвоения
состояния. Replay identity закрепляет все контексты и переносится вместе с
записью и backup. Старые bundles и структурные формы прежнего IR сохранены.

## Примеры и команды

Шесть [calendar-ticks](../examples/environment/) стратегий объединяют даты,
часы, день недели, старший контекст, EMA и защиту в тиках. Для v1 отсутствие
timestamp не маскируется: границы задаются числовыми UTC-параметрами.
Отдельные phase-примеры показывают историю, открытие и подтверждение свечи.

```sh
python -m apps.openpine compile --source examples/environment/calendar-ticks-v6.pine --profile historical --output .runtime/environment-ir.json
python -m apps.openpine job --artifact .runtime/environment-ir.json --bars examples/environment/input.json --contexts examples/environment/contexts.json --state-dir .runtime/environment-demo
```

Обычный CLI `run --bars` сохраняет прежний контракт чистых historical-bars;
описанный контейнер с метаданными используется через job или веб.
Проверки и границы готовности: [план приёмки](ENVIRONMENT_PLAN.md).
