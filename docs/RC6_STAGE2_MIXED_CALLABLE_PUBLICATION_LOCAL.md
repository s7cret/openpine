# OpenPine — смешанные функции и методы: локальная накопительная поставка

**Публикации не было. Весь этап 2 остаётся in_progress.**

## Реальный результат

Обычные функции и методы с одним именем в явной форме вызова выбираются одним
существующим SignatureResolver из общей source-bound группы. Нет приоритета
«обычная функция всегда побеждает» и нет выбора по последней записи таблицы имён.
Dot-вызов по-прежнему рассматривает только методы. Новая библиотечная проекция
`same_version_mixed_callables_v7` поддерживает Pine 5/6 и сохраняет exact-source,
public/private, прямую/транзитивную видимость и исходные идентичности.

При `f(float x)=>x+0.5` и `method f(int self)=>self+1`, `f(2)` даёт 3,
а `f(2.0)` — 2.5. Две очередности объявлений, несколько кандидатов обоих видов,
required arity, named/default arguments, скаляры, коллекции, UDT и tuple results
проверены. Неоднозначный вызов не превращается в случайный выбор.

Исправлены общие ошибки инференса: локальный return не переопределяется типом
одноимённой переменной другого тела после выхода из блока; поле записи и receiver
фиксируются в своей области; методические параметры берутся из выбранного binding,
не по смещённому индексу; промежуточные function/method markers не мешают уточнению
типа транзитивного результата. Это не подмена runtime или отдельный evaluator.

Новый compiler feature `mixed_user_callable_families_v1` вычисляется по AST и
восстановленному контексту. Bounded admission отклоняет подменённые выборы деклараций,
типы аргументов и const facts после повторного пересчёта хешей. Во время исполнения
нет нового runtime-dispatcher или новой операции PineLib.

## Состояние и интеграция

Раздельные written-call counters: 1/2/3 и 10/20/30, повторения одного места вызова
в цикле — 3/6/9. Для обычных и varip полей объекта realtime-пары идут 22/22, 22/33,
22/44; midbar JSON restore совпадает. Приватная int-декларация не перехватывает
публичный float-вызов библиотеки. Обе стороны source boundary проверены.

Артефакт сохраняется и повторно читается с диска, затем стратегия использует
значения 3 и 30 и отправляет реальный entry qty=33 на bar 2: цена 102 на закрытии
или 103 на следующем открытии. Проверены v5/v6, local/imported, оба транспорта и
fill-recalculation. In-process compare_modes не выдаётся за protected worker.

## Первоначальные ошибки и границы

Сохранены исходное воспроизведение ошибочного приоритета, первые неудачные тесты
инференса и два прерванных коротким внешним тайм-аутом диагностических прогона.
В первоначальном parser packaging отсутствовал настоящий wheel dependency; он
установлен из offline wheel и весь набор повторён. В первом host-запуске не хватало structlog,
а у Contracts возник конфликт пространств имён вспомогательных тестов; реальные зависимости и пути
тестового стенда исправлены, project assertions/ожидания не менялись.

Поддержка различимых смешанных сигнатур проверена инженерными сценариями. Точная
семантика всех одинаковых function/method signatures и optional-only коллизий
**не подтверждена отдельным исполнением TradingView**. Нельзя объявлять весь
STATE-02 или IMPORT-03 accepted; они остаются partial с новым реализованным профилем.
Межверсионные библиотеки, полный каталог и численные контракты остаются открыты.
Старые UNVERIFIED v5 str.tonumber ожидания не менялись.

Не выполнены Python 3.11, полный host/optimizer, новый CI, полный builtin-index
текущих pins, browser/frontend и общий benchmark. Старый успешный CI не присваивается
новым исходникам. Все исходные четыре критерия и 16 пакетов остатка сохранены.
