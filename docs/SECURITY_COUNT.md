# Ограниченное окно request.security

В историческом профиле Pine v5/v6 явный `calc_bars_count` принимает целочисленный литерал от 1 до 10 000 000. Аргумент можно передать по имени, пропустив `currency`. Для восьми позиционных аргументов седьмой задаёт native currency пустой строкой. Выбор рынка и интервала допускает настройки. Без лимита действует прежний контракт. В v1–v4 явный параметр отклоняется.

Историческое окно заканчивается на последней вторичной свече, закрытой к концу первичного снимка. Пропуски по времени не занимают место в окне. Два запроса с одинаковой парой и режимом lookahead делят чтение снимка. Вычисление каждого выражения и его история начинаются с первой выбранной для него свечи. В ручном примере пять закрытых цен равны 100, 10, 20, 30 и 40. Для EMA длины 3 и лимитов 2 и 4 последние значения равны 35 и 31,25. Будущая цена 999 за пределами исполнения не участвует.

В replay передайте `security_warmup` в файле контекстов CLI или теле запроса создания replay. Для каждого выбранного и привязанного контекста с явным лимитом задайте число фактических закрытий и конец исходной истории UTC в миллисекундах:

```json
{"security_warmup":{"second":{"count":5,"end_ms":720000}}}
```

Для открытой ленты с заведомо пустым начальным префиксом укажите count 0 и границу перед первым закрытием. По мере поступления новых закрытий вычисления продолжаются с зафиксированного старта. Отсутствие необходимых сведений и противоречие между событиями и границей вызывают ошибку. Для подтверждённо неизвестной цели с разрешённым пропуском префикс не нужен. Изменение префикса требует нового запуска. При восстановлении проверяются идентичность контекста, курсоры, частное состояние выражений и история видимости.
