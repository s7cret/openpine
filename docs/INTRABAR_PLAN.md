# Приёмка расчёта на обновлениях

- [x] Контракт v1–v6, свидетельства параметра заголовка и varip.
- [x] Разделение подтверждённого состояния, rollback и varip; массивы и запросы.
- [x] Расчёт стратегии на основном обновлении через общий evaluator.
- [x] Командные пачки и исполнение новых заявок на следующем наблюдении.
- [x] Checkpoint внутри свечи, атомарная публикация, backup/restore.
- [x] CLI/HTTP, веб, предварительные выходы и перенос записи.
- [x] Независимые ожидания, полная регрессия, нагрузка, браузер и CI.

База: `0a53983`, 909 тестов / 98 модулей, 2074 conformance-наблюдения.
Все прежние test IDs сохраняются. Три прежних отказа `v4-varip`, `v5-varip`,
`v6-varip` становятся положительными проверками тех же исходников; это
намеренное расширение поддерживаемой конструкции. Остальные наблюдения,
включая отказы ранних версий, должны совпасть с принятой базой.

Проверки: все версии, обе модели времени, каждый разрез ленты, независимые
счётчики, UDF, алиасы и замена массивов, дополнительные контексты, создание,
изменение/отмена и защита на обновлениях, плотная незакрытая свеча,
падение до/после публикации, новый worker, backup и офлайн перенос.
Нагрузка — 100 тысяч и миллион наблюдений, с независимой арифметикой сделок,
комиссий, проходов и подтверждённых рядов. Поставка — исходник и установленный
общий wheel, Python 3.14.8, Windows/Linux. Эквивалентность TradingView отдельно.

Расчёт использует только полученные обновления. Параметр заголовка подтверждён
с v2, varip — с v4; явный режим v1 является реконструкцией OpenPine.
`calc_on_order_fills` и `process_orders_on_close` остаются отдельным этапом.
Неизвестные тики не восстанавливаются, биржевые заявки не отправляются;
эквивалентность TradingView проверяется отдельно. Прежние сессии с несовместимой
implementation identity требуют новой компиляции и новой сессии.

После квалифицированного коммита публикуются только документация, доказательства
и сгенерированные отчёты conformance; исполняемый исходник остаётся тем же.
