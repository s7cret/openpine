# Базовая математика и чистые цели запросов

`openpine.numeric-targets.1` расширяет [scalar-цели](SCALAR_TARGETS.md) отдельным
overload suffix `.numeric.scalar.function.primary.prepared`. Общий интерфейс
`packages/contracts/scalar_registry.py` связывает контракты, допуск и исполнение
числовых и строковых операций. Runtime adapters не содержат второй реализации.

```pine
//@version=6
indicator("Computed interval")
minutes=input.float(60.0)
interval(value) => str.tostring(math.max(1, math.round(value)))
plot(request.security(syminfo.tickerid, interval(minutes), math.sqrt(math.pow(close,2))))
```

## Версии и ABI

| Операции | v1–v2 | v3–v4 | v5–v6 |
|---|---|---|---|
| floor/ceil | глобальные, результат float | глобальные, результат int | math.*, результат int |
| sign/sqrt/pow/log/log10/exp | глобальные, результат float | глобальные, результат float | math.*, результат float |
| abs/min/max/round, int/float, na/nz | прежний ABI | прежний ABI | прежний ABI, включая math.* aliases |

Числовые аргументы новых функций принимают int/float; результат получает
максимальный qualifier аргументов. Const/input overloads современных версий
есть в сохранённых артефактах; пробелы ранних qualifiers восстановлены явно.
Имена pow: x/y в v1–v2, base/exponent с v3. Остальные новые функции принимают
x до v5 и number с v5. Именованные аргументы разрешены с v3.

Исходные записи и тексты Wiki закреплены в `spec/numeric-functions-evidence.json`.
Различие float/int у floor/ceil подтверждено ранним архивным примечанием,
а не выведено из современного API. v2 использует сохранённый compatibility
baseline v1, полнота которого ограничена. Решения и хеши находятся в
`spec/numeric-targets-profile.json`.

`spec/numeric-legacy-abi.json` содержит все прежние числовые CallContract:
69 на версию v1–v5 и 73 в v6. При установке каталога проверяется полное равенство
допущенного ABI этой копии, включая parameter IDs, signature hashes, qualifiers,
result rules и legacy bool-варианты. Старые bundles, source lock и профили целей
сохранены. Перемещение кода не расширяет правила старых evaluator.

## Числовая модель

Прежние abs, int/float, na/nz, min/max и round вычисляются общим числовым ядром.
Сохраняются усечение int к нулю, eagerly вычисляемые аргументы nz, NA и
версионная доступность bool. Min/max по-прежнему ограничены 2..32 аргументами.

Round сохраняет прежнее decimal-округление половин к положительной бесконечности:
`round(-1.5) = -1`, `round(1.5) = 2`, precision в -15..15. Строковый formatter
остаётся отдельным: `str.tostring(-1.5,"#") = "-2"` по принятому HALF_UP.
Их алгоритмы не объединены механически.

Новые sign, sqrt, pow, log, log10, exp возвращают float. NA распространяется.
В принятой модели sqrt отрицательного, log/log10 неположительного,
отрицательная база с дробной степенью и ноль в отрицательной степени дают NA.
`pow(0,0) = 1.0` — явно принятое решение. Переполнение даёт NUMERIC_OVERFLOW;
конечное underflow до нуля допускается. Новые integer результаты ограничены int64.

Pow вычисляет модуль через binary64 math.pow; отрицательный знак при целой
степени определяется по её чётности, включая точный int64 exponent. Огромные
Python integer powers не создаются. Конечные float-результаты проверяются;
бесконечности и NaN не публикуются как обычные числовые значения.

Это ограниченная модель по артефактам. Не все крайние domain/overflow правила
доказаны историческим исполнением; точная сверка с TradingView выделена отдельно.

## Цели и запрошенные контексты

Новый профиль допускает только закрытый числовой ABI и прежний строковый subset,
чистые ациклические UDF, immutable captures/locals, const/input/simple значения.
Все аргументы, инструкции и ветки проверяются до загрузки свечей. Series,
состояние, история, циклы, коллекции и вложенные запросы в целях исключены.
Сохраняются 128 узлов, глубина 16 и 12 UDF-вызовов. Классификатор исходного DAG
мемоизирован; новая математика не возвращает экспоненциальное раскрытие aliases.

Сырые inputs, наследование пустых целей и primary metadata сохранены. Граф
фиксирует конкретные kernels, функции/call sites и program hash. Интервалы
данных остаются каноническими минутами и одиночными D/W/M.

Те же числовые ядра разрешены в numeric/bool выражениях security и lower-TF.
Они читают уже связанное значение из запрошенного рынка, используют его частное
состояние и не обращаются к скрытому основному контексту. Строковые результаты
или промежуточные строковые операции внутри requested body этим этапом не добавлены.

Общий ScalarBudget применяется ко всем вложенным числовым/строковым вызовам
нового numeric program: 262144 единицы на вычисление цели или bar одного контекста.
Стоимость — base cost и один шаг на аргумент; pow/log/log10/exp стоят 32,
sqrt — 8, floor/ceil/sign — 2, legacy numeric — 1. Стоимость строк и preallocation
проверки сохраняются. Один UDF не получает новый бюджет. Legacy-only program
сохраняет прежние ограничения работы; доступность нового реестра сама по себе
не вводит ему новый числовой лимит.

## Проверки и поставка

`conformance/numeric-targets` использует независимые целочисленные ожидания,
простые тождества, domain NA, decimal ties и ручное сопоставление контекстов.
Для иррациональных значений указан допуск 1e-12; unit oracles используют Decimal
с повышенной точностью, а не те же math kernels как эталон.

`tools.numeric_targets_flow` проверяет file/saved IR, worker pause/resume,
durable replay restart, offline и lower-TF v5/v6. `tools.numeric_targets_soak`
проверяет миллион событий и каждую точку по отдельным циклическим/треугольным
формулам, включая restart незавершённого младшего окна.

Установочный CI делится на research и targets; все прежние helpers выполняются
ровно один раз. Numeric helper добавлен к targets. Это 16 установочных наборов
на каждую ОС и 49 заданий общей приёмки, без удаления прежних тестов или helpers.
