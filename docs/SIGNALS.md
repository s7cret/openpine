# События, накопление и взвешенные окна

Выпуск `pine-signals-20261024.1` закрепляет профиль `openpine.signals.vN.1`
для каждой версии v1–v6. Источники — версионные записи импортированной wiki;
пробелы старых сигнатур и правила ограниченного исполнения раскрыты как
реконструкция. Внешнее исполнение в TradingView не подтверждалось.

| Функция | v1–v4 | v5–v6 | Результат |
| --- | --- | --- | --- |
| Давность события | `barssince(condition)` | `ta.barssince` | series int |
| Значение события | `valuewhen(condition,source,occurrence)` | `ta.valuewhen` | тип source: int/float/bool, series |
| Накопление | `cum(source)` | `ta.cum` | series float |
| Скользящая сумма | `sum(source,length)` | `math.sum` | series float |
| Взвешенное среднее | `wma(source,length)` | `ta.wma` | series float |
| Среднее по объёму | `vwma(source,length)` | `ta.vwma` | series float |
| Изменение и процент | `mom/roc(source,length)` | `ta.mom/roc` | series float |
| Новое высокое/низкое значение | `rising/falling(source,length)` | `ta.rising/falling` | series bool |
| Смещение экстремума | `highestbars/lowestbars([source,]length)` | `ta.highestbars/lowestbars` | series int |

Именованные аргументы допускаются с v3. Числовые source для окон приводятся
к float; `valuewhen` сохраняет разрешённый исходный тип, включая точные int64.
Строки, цвета и коллекции в valuewhen не входят в этот профиль.

## События и пропуски

`barssince` возвращает na до первого true, 0 на событии и увеличивается на
каждом последующем достигнутом вызове. False и исторический bool na не
создают событие. `valuewhen` нумерует срабатывания от нуля: 0 — последнее,
1 — предыдущее. True с source=na всё равно считается событием и сохраняет na.
Недостаточная история даёт na; bool-результат в v6 вместо na даёт false.

Occurrence — simple int 0…99999, фиксированный для места вызова и контекста.
Сохраняются только последние occurrence+1 значений. Длины окон — simple int
1…100000, также фиксированные. Изменение параметра после первого вызова
отклоняется `SIGNAL_PARAMETER_CHANGED`; неверный диапазон — `SIGNAL_PARAMETER`.

Cum игнорирует na, удерживает накопленное значение и даёт na до первого
числа. Sum/WMA используют последние length определённых значений; до полного
прогрева результат na, пропуск удерживает результат. У WMA веса растут от 1
для старейшего значения до length для нового. VWMA использует пары source/volume
из своего контекста; пропуск любого компонента пропускает пару. Нулевой объём
участвует в окне; нулевой общий знаменатель даёт na. Отрицательный объём
отклоняется `SIGNAL_VOLUME`.

Mom/ROC используют значение length достигнутых вызовов назад, включая дыры na.
Недостающий компонент даёт na; ROC при нулевой базе также даёт na. Rising/falling
строго сравнивают текущее значение со всеми предыдущими length определёнными
значениями после полного прогрева. Это проверка всего окна; равенство не проходит.
Для v1–v5 неизвестный bool остаётся na, для v6 — false.

Highestbars/lowestbars рассматривают последние length достигнутых вызовов,
включая дыры na. Доступный экстремум публикуется уже при прогреве. Результат
равен 0 на текущем экстремуме и отрицателен для прежнего; равные кандидаты
выбираются по последнему появлению. При полностью пустом окне результат na.
Один аргумент выбирает физический high либо low запрошенного контекста.

Эти правила прогрева, пропусков и неполных перегрузок — явно принятый
ограниченный контракт, а не заявление о точном совпадении со всеми Pine API.
Официальные описания [barssince](https://www.tradingview.com/pine-script-docs/faq/functions/)
и [событийной логики](https://www.tradingview.com/pine-script-docs/faq/techniques/)
указаны также в review выпуска.

## Владение состоянием и контексты

Каждое написанное место вызова имеет собственное состояние в каждом контексте.
Пропущенный вызов не обновляет его. Повторные итерации цикла считаются достигнутыми
вызовами. Ленивые `and/or` в v6 сохраняют эту семантику. В прикладных примерах
stateful TA вычисляются перед логическим условием, чтобы обновляться на каждом баре.

Новый выпуск запросов `pine-requests-20261024.5` допускает ограниченные сравнения,
логические условия и bool-ядра как аргументы числовых выражений. Например:

```pine
higher = request.security("TEST:SIGNAL","4",ta.valuewhen(close > open,close,0))
```

Вычисление идёт на свечах старшего контекста с отдельной очередью событий.
Корневой результат остаётся числом либо плоским числовым tuple. Динамические,
вложенные и локальные запросы, UDF/captures, barstate и строковые результаты
сохраняют прежние ограничения. Версионные lookahead/gaps не меняются.

Новые функции используют существующие скалярные CallIR. Специальная версия
структуры IR для них не нужна; смешанная программа с окружением остаётся `.10`.
Новые kind состояния проверяются закрытым codec вместе с программой, типом
результата, числом вызовов, длиной окна, последовательностью слотов и общим
бюджетом. Восстановление присваивает состояние только после полной проверки.
Идентичности спецификации и сборки исключают незаметную подмену старой программы.

Точные целочисленные накопители предотвращают промежуточное переполнение и
потерю малых слагаемых при сокращении больших. Непредставимый конечный float
даёт `SIGNAL_VALUE_RANGE`. Память ограничена общим бюджетом 1 млн ячеек;
preview использует изменённые ячейки, не копируя всю историю. Суммы/WMA/VWMA
обновляются за O(1), смещения и проверки тренда — за O(log length).

## Сквозной пример

Шесть [event-trend](../examples/signals/) стратегий объединяют все 12 семейств,
событие старшего контекста, параметры и защитные уровни. Файлы содержат собственные
синтетические свечи; их можно загрузить через обычную веб-форму.

```sh
python -m apps.openpine compile --source examples/signals/event-trend-v6.pine --profile historical --output .runtime/signal-ir.json
python -m apps.openpine job --artifact .runtime/signal-ir.json --bars examples/signals/input.json --contexts examples/signals/contexts.json --state-dir .runtime/signal-demo
```

Experiments, search/holdout и walk-forward используют ту же сохранённую подготовку.
Прогресс приёмки: [план этапа](SIGNALS_PLAN.md).
