# Вычисляемые контексты до первого бара

Относительные цели и пустые typed inputs добавлены отдельным профилем:
[основной контекст](PRIMARY_TARGETS.md). Описанные ниже ограничения относятся к
сохранённому `openpine.computed-targets.1`; его контракт остаётся прежним.

`openpine.computed-targets.1` расширяет [подготовленные запросы](PREPARED_REQUESTS.md).
Граф определяется по замороженным параметрам до получения истории, создания
заданий или подписок. Точная эквивалентность TradingView отдельно.

```pine
//@version=6
indicator("Computed contexts")
prefix=input.string("TEST:")
choose=input.bool(true)
sym=prefix+(choose ? "A" : "B")
tf=choose ? "2" : "1"
plot(request.security(sym,tf,close))
```

Для v1–v4 используются существующие generic `input` и `security`; для v5/v6 —
также typed inputs и `request.security`. v5/v6 допускают вычисляемые цели
`request.security_lower_tf`. Правила gaps/lookahead каждой версии сохраняются.

## Допуск и вычисление

Разрешены литералы, inputs, неизменяемые обычные глобальные объявления и их
транзитивные зависимости с qualifiers const/input. Допускаются существующие
арифметика, сравнения, логика, унарные операции, числовые преобразования Binder,
условное выражение и конкатенация строк. Весь граф, включая обе ветки условия,
проверяется до выбора значения. Мутации, var/varip, series, история, вызовы UDF,
запросы, циклы и локальные значения в целях отклоняются.

Скалярные бинарные правила общие с runtime: версия целочисленного деления,
NA-сравнения и логическая семантика сохраняются. `?:` вычисляет выбранную ветку;
v6 сохраняет lazy and/or. Указание зависимости относится ко всему графу, а не
только к выбранной ветке. Одно глобальное значение вычисляется один раз на цель.

Лимиты одной цели: 128 посещённых узлов, глубина 16, строка до 4096 символов;
числа ограничены прежним int64/конечным float. Итоговый инструмент — явный
квалифицированный символ до 256 символов, без пробелов и пустых частей;
интервал — прежний канонический UTC-интервал. Сохраняются 8 контекстов и
16 написанных запросов. Изменение параметров требует новой подготовки.

## Специализированные inputs

Сохранённые каталоги подтверждают функции `input.symbol` и `input.timeframe`
в v5/v6. `input.symbol` в каталоге v4 — константа, поздняя функция ему не назначается.

```pine
sym=input.symbol("BINANCE:BTCUSDT")
tf=input.timeframe("60",options=["15","60"])
```

Они имеют отдельный profile ID `openpine.target-inputs.vN.1`, сохраняются в
input schema/settings как symbol/timeframe, а значение IR имеет базовый тип string.
Defaults, каждый option и выбранное значение проверяются. Options поддерживаются
для timeframe; symbol options отсутствуют в артефакте и отклоняются. Прежние
title/tooltip/inline/group и v6 active сохраняются. Display и интерактивный confirm
вне среза. Пустое значение явно отклоняется: неявного выбора основного графика нет.

## Совместимость и приложение

Вычисляемые цели получают отдельные overload IDs `.computed.prepared`.
Обычные aliases продолжают получать `.prepared` с прежним бюджетом 64 узла,
включая ранее допустимые цепочки глубже 16. Старые контракты и их alias-only
resolver сохранены; literal-only контракты не изменены. Используются существующие
узлы Typed IR .11, схема графа и settings. Immutable bundles и spec/lock сохранены.
Изменение реализации, как раньше, требует перекомпиляции старого артефакта.

Один resolver обслуживает допуск IR, requirements/history-spec, подготовку
worker, исследования и replay/live. Каждый вариант получает собственные settings
и snapshot bindings; отсутствие данных отклоняет всю группу до создания заданий.
Ни источник, ни сохранённый IR при выборе параметров не переписываются.
Граф входит в конфигурацию, checkpoint/запись и переносимый офлайн-повтор.

Веб показывает вычисленные symbol/timeframe и влияющие inputs. Новые параметры
сбрасывают готовность; устаревшие карточки очищаются, ответ защищён LatestRequest.
Неверные значения показывают причину отказа до загрузки истории.

## Воспроизведение

```sh
python -m tools.computed_targets_spec --check
python -m tools.computed_targets_flow --directory .runtime/computed-flow
python -m tools.computed_targets_soak --directory .runtime/computed-soak --lower-candles 800000
```

[Корпус](../conformance/computed-targets/cases.json) использует ручное отображение
закрытий A2, последовательность B1 100…107 и суммы 406/422; runtime не создаёт
ожидания. Flow проверяет файл → IR → worker с паузой → восстановление replay
v1–v6, свежий офлайн-каталог v1/v6 и lower-TF v5/v6 с UDF/SMA/накоплением.
[План и приёмка](COMPUTED_TARGETS_PLAN.md).
