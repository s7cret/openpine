# Пользовательские функции и значения блоков

Все пять частей этого этапа доступны в профилях v1–v6: объявление/вызов функции `=>`, последнее выражение как результат, `if/else` со значением, лексические области видимости и независимое состояние каждого написанного вызова. Правила закреплены в `pine-functions-20261021.1` поверх четырёх прежних неизменяемых выпусков.

```pine
//@version=6
indicator("Function state")
accumulate(float source) =>
    var float total = 0
    total := total + source
    total
first = accumulate(close)
second = accumulate(1)
value = if close > 20
    first + second
else
    first
plot(value)
```

Для close `10,20,30,40` первый вызов накапливает `10,30,60,100`, второй — `1,2,3,4`, итоговый plot — `10,30,63,104`.

Более полный пример с вложенным вызовом, SMA, историей параметров, локальным var и возвращающим if:

```sh
python -m apps.openpine run --source conformance/functions/v6-combined.pine --bars conformance/functions/fixed.json
python -m apps.openpine run --source conformance/functions/v1-combined.pine --bars conformance/functions/fixed.json
python -m apps.openpine compile --source conformance/functions/v6-combined.pine --profile historical
python -m tools.release_gate
```

У полного примера результат `10,40,90,141`; для каждой из шести версий есть собственная программа с соответствующими именами встроенных функций.

## Объявления, параметры и результат

`double(x) => x * 2` объявляет однострочную функцию. Многострочная функция использует блок с четырьмя пробелами на уровень и возвращает последнее выражение или значение последнего if. Предшествующие инструкции выполняются по порядку. Последняя декларация/переприсваивание не заменяет возвращаемое выражение; такая функция получает `FUNCTION_RETURN`.

Поддержаны scalar int, float, bool, string, функции без параметров, обязательные позиционные/именованные аргументы, вложенные и повторные вызовы. Выражения аргументов вычисляются ровно один раз в исходном порядке, затем связываются с параметрами. После именованного аргумента позиционные запрещены; повторы, неизвестные/недостающие/лишние параметры диагностируются до исполнения.

Параметр может иметь тип: `scale(float x, int factor) => x * factor`. Без аннотации он специализируется по базовому типу аргумента; одна функция может использоваться отдельно с int, float, bool или string, если её тело допускает такие операции. Int → float представлен явным преобразованием; float → int и string/bool → число автоматически не выполняются. Нетипизированный аргумент na требует явного типа параметра.

`simple int length` принимает const/input/simple; `series float source` явно задаёт series. Без qualifier используется qualifier аргумента, усиленный до series при чтении истории параметра. Simple параметр с историей или series аргументом получает `FUNCTION_ARGUMENT_QUALIFIER`. Результат консервативно учитывает qualifier всех аргументов и зависимостей тела, включая неиспользованный stateful результат; зависимость от баров не может скрыться внутри const аргумента indicator.

Имена функций уникальны, определения находятся в глобальной области. Определения до indicator допустимы и не являются исполняемыми инструкциями. Forward-вызовы разрешены в ациклическом графе, включая вызов функции из ранее объявленной функции. Прямая и косвенная рекурсия отвергается даже в неиспользованных определениях.

## Значение `if/else`

`value = if condition ... else ...` и завершающий if функции возвращают значение выбранной ветки. Поддержаны `else if`, вложенные value-if, локальные декларации/переприсваивания перед последним выражением. Обе ветки проверяются статически; выполняется только выбранная. Int/float результаты приводятся к общему float; bool/string должны быть согласованы по типу.

Если else отсутствует, числовой результат — na на невыбранных барах; bool — na в v1–v5 и false в v6. Для string нужен явный else. Переменные ветки не доступны другой ветке и не выходят из блока. Невыбранная ветка не изменяет var и состояние SMA/EMA, не создаёт задним числом историю.

Условия и логика сохраняют прежние политики версий: числовые условия и strict and/or в v1–v5, bool условия и lazy and/or в v6.

## Лексические области видимости

Параметры и локальные переменные принадлежат своей функции. Декларации в одном блоке уникальны; вложенный блок может затенить внешнее имя, а его инициализатор читать внешний владелец. Переприсваивание локальной переменной изменяет ближайшего владельца. Читать локальную переменную до декларации или после выхода из её блока нельзя.

Функция читает глобальные переменные, видимые в точке её **определения**, по binding ID. Их значение берётся в точке вызова; они должны быть инициализированы до него. Локальные переменные вызывающего блока не становятся захватами функции. Вызванная из функции другая функция использует собственные глобальные захваты.

Изменение глобальной переменной или параметра внутри функции запрещено (`FUNCTION_WRITE`); изменяемую копию можно объявить локально. Indicator/study и plot остаются глобальными вызовами. Неиспользованные определения проверяются на структуру, имена, записи, запрещённые эффекты и циклы; полная проверка типов тела происходит при специализации каждого написанного вызова, включая вызовы в статически невыбранных ветках.

## Состояние и история

Compiler специализирует тело для каждой написанной цепочки вызовов. У каждой инстанции отдельные ID параметров, локальных переменных, var и stateful builtin call sites. Два `accumulate(...)` не разделяют счётчик. Два вызова outer, внутри которой написан один inner, получают разные состояния inner/SMA/EMA. Повторное чтение переменной с результатом функции не вызывает её заново.

Var инициализируется при первом достигнутом исполнении своей декларации в данной инстанции. Пропущенный вызов не обновляет её состояние; пропущенный var initializer не повторяет вложенные вызовы. Новый запуск начинает с чистого состояния.

История использует прежнюю модель [SERIES.md](SERIES.md): привязку к барам, итоговые значения переменных, пропуски неисполненных выражений/обычных локальных переменных, сохранение уже инициализированного var. История параметра при пропущенном вызове содержит пропуск, даже если текущий аргумент снова доступен. Встроенный `close[1]` продолжает читать полную историю входных баров. История написанного выражения внутри функции разделена по инстанциям.

## Контракты и границы

Typed IR версии `openpine.typed-ir.5` содержит FunctionContract/ParameterContract, таблицу bindings с namespace, UserCallIR с уже связанными аргументами и специализированным телом, BlockIR и EvaluateIR. Runtime проверяет весь IR до первого эффекта: определение и цепочку вызова, типы и порядок аргументов, захваты, области, запрет записей, принадлежность state/history IDs, тип результата. Исходные имена повторно не разрешаются; Python eval/codegen не используется.

Root lock закрепляет новый manifest и `function_profile_ids` каждой версии. Читатель проверяет хеши, связь с core/version/language/series, evidence записей своей версии и JSON Schema. Runtime отдельно сравнивает policy с реализованной формой. `python -m tools.function_spec --check` воспроизводит bundle офлайн и не генерирует тестовые ожидания.

Границы профиля: 64 определения, 16 параметров, глубина вызовов 12, 128 инстанций, 8192 узла развёрнутого IR, глубина IR 128. Прежние лимиты исходника, токенов, выражений, блоков и истории сохраняются. Рекурсия, вложенные определения, overloads, defaults параметров, tuple/коллекции в параметрах, коллекции в результате, методы и функции как значения не входят в этот выпуск. Точная историческая эквивалентность TradingView проверяется отдельным этапом; реконструированные правила старых версий записаны в review.

Плоские составные результаты и распаковка добавлены [составным профилем](COMPOSITE.md) с typed IR `.7`. Этот IR используется и для новых variance/stdev; программы без новых конструкций и вызовов сохраняют прежние формы.

## Проверки

[Профиль циклов](LOOPS.md) добавляет `for`/`while` как последнее значение UDF
в соответствующих версиях. Состояние написанного вызова разделяется итерациями;
`break` и `continue` не выходят из функции в вызывающий цикл.

`conformance/functions` содержит **108 случаев: 60 успешных программ и 48 ожидаемых отказов**, по 18 на версию. Десять положительных программ проверяют параметры, многострочные результаты, value-if, состояние, вложенные SMA/EMA, историю, глобальные захваты, scalar специализации, пропущенные вызовы и совместный пример всех пяти пунктов. Ожидания записаны вручную, независимо от исполнения.

31 unittest дополнительно проверяет порядок однократного вычисления аргументов, типы/qualifiers, первые бары и пропуски, сквозную изоляцию состояний и новых запусков, отсутствие будущих данных, рекурсию/лимиты, подмену IR/контрактов, воспроизводимость bundle, сохранение прежних выпусков и реальные CLI процессы v1/v6. Общий gate выполняется на Python 3.14.8.
