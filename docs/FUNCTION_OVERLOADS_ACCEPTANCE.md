В v5/v6 перегрузка выбирается в Binder по форме, типам и допустимым qualifiers.
Точные типы предпочтительнее int-to-float; равные кандидаты дают диагностику.
v5 различает определения по всем параметрам, v6 — по обязательным. В v1–v4
разные сигнатуры одного имени явно отвергаются. Никакого fallback на v6 нет.

Аргументы связываются один раз в исходном порядке; закрытые defaults добавляются
после выбора определения. Typed IR `.12` хранит конкретный function ID и маску
обязательных параметров. Обычные функции сохраняют прежний wire-формат.

Проверены captures по ID определения, рекурсия, независимость написанных вызовов,
var/varip, история, массивы, private request graphs, frozen request targets,
rollback и checkpoints. Дополнительно локально проверены tuples/loops с `.12`
и восстановлением во всех трёх внутренних разрезах четырёх программ v5/v6.
Восемь новых целых программ прошли обычные workers, saved IR, history/replay,
восстановление нативного состояния и ручные ожидания equity/комиссий.

Каталог допускает до 128 записей / 256 KiB; один запуск — до 64 программ,
отчёт — до 2 MiB. CLI и UI предлагают конечные пакеты. Параллелизм воркеров,
лимиты RAM/диска и правила допуска не увеличены.

В первой попытке Windows-suite exits получил `JOB_TIMEOUT` 120 секунд в
прежнем pending-stop v2 без UDF: восстановленный worker дошёл до 361/400 свечей.
После завершения остальных jobs повторён только этот suite и зависимая
приёмка. Повтор прошёл на том же исходнике, wheel и лимите 120 секунд.
Успешные jobs повторно не запускались; первая ошибка сохранена в истории CI.
Receipts скачаны с проверкой GitHub SHA-256; полная приёмка отдельно повторена
локально из этих receipts.

Это принятый ограниченный профиль OpenPine. Методы, пользовательские типы,
общие default-выражения и точная эквивалентность исполнению TradingView
остаются отдельными этапами. Вычислительная идентичность обновлена;
старые результаты читаются, старые checkpoints требуют своей сборки.
