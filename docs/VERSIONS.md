# Текущий срез Pine v1–v6

Все шесть версий проходят один compiler/runtime через свои реестры. Реализованы переменные с выводом и аннотацией типа, арифметика, `:=`, сравнения, `?:`, `if/else`, `var`, абсолютная величина, `close`, EMA и ограниченный `study`/`indicator`/`plot` harness. [Профиль конструкций](STATEMENTS.md) определяет согласованную модель по артефактам; точное сравнение с TradingView является отдельным этапом.

| Версия | Декларация | Модуль | EMA | Параметры EMA | Политика начального состояния |
|---|---|---|---|---|---|
| v1 | `study` | `abs` | `ema` | `x,y`, позиционно | SMA seed, реконструкция |
| v2 | `study` | `abs` | `ema` | `x,y`, позиционно | SMA seed, реконструкция |
| v3 | `study` | `abs` | `ema` | `source,length` | SMA seed по примеру документации |
| v4 | `study` | `abs` | `ema` | `source,length` | SMA seed по примеру документации |
| v5 | `indicator` | `math.abs` | `ta.ema` | `source,length` | Первый доступный source |
| v6 | `indicator` | `math.abs` | `ta.ema` | `source,length` | Первый доступный source |

Без `//@version` выбирается v1. Имена другой эпохи не становятся alias: например, `ta.ema` в v4 и `ema` в v5 отклоняются. Архивные позиции `x,y` не доказывают поддержку именованных вызовов; `ema(x=...,y=...)` v1/v2 даёт `PROFILE_UNCOVERED/NAMED_ARGUMENT_UNVERIFIED`. Позиционные вызовы работают.

## Что подтверждено, а что восстановлено

Переименование `study` → `indicator` и namespace функций подтверждается [официальной миграцией v5](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-5/). [Руководство v3](https://www.tradingview.com/pine-script-docs/v3/quickstart-guide/) показывает `study`, `ema(close, length)` и `plot`. [Миграция v2](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-2/) описывает обратную совместимость с v1. Имена параметров v1/v2 сохранены из архивных metadata в закреплённом каталоге.

**Есть реальное расхождение источников:** сохранённые официальные примеры EMA v3/v4 инициализируют среднее через SMA; пример v5 и принятый v6 контракт — через source. Из одного этого нельзя заключить, что нативный движок TradingView действительно менял seed между версиями: иллюстративный код не является записью исполнения встроенной функции. Для v1/v2 архив вообще не восстанавливает seed. Независимого запуска старых Pine-версий в TradingView здесь нет.

Поэтому OpenPine предоставляет явно квалифицированные профили: v3/v4 следуют сохранённому примеру; v1/v2 используют ту же политику как **реконструкцию**, а не подтверждённый исторический факт. Старое NA-поведение также не подтверждено: в этих профилях определена политика пропуска NA, выбранная для текущего среза. Начальные пропуски остаются NA, первые `length` доступных source дают SMA, далее действует рекуррентное обновление; последующий NA сохраняет предыдущую EMA. Это различие и отсутствие внешнего oracle включены в `identity.compatibility_notes`, а не спрятаны в реализации.

На source 10,20,30,40 длина 3 даёт:

- v1–v4 в объявленных профилях: `[null,null,20.0,30.0]`;
- v5/v6: `[10.0,15.0,22.5,31.25]`.

Честная граница: **текущий срез исполняется во всех версиях, но точная историческая совместимость seed/NA для v1–v4 остаётся неподтверждённой**. Политика вынесена в отдельные правила/kernel; внешнее наблюдение можно принять новым review release и исправить её без переписывания frontend или общего цикла баров.

## Структура и проверка

`pine-language-20261021.1` добавляет профиль конструкций для каждой из шести версий. Все пять новых возможностей включены сразу во всех версиях модели. Деление int/int в v1–v5 усекается к нулю, в v6 возвращает float; логические and/or вычисляют оба операнда в v1–v5 и сокращённо в v6. Числовые условия разрешены в v1–v5; в v6 нужен bool. Эти выбранные правила проверяются как часть модели, а не как новая заявка на историческую совместимость. Корпус `conformance/language` содержит отдельные исполнения каждой версии.

Исходный `pine-spec-20261020.1` сохранён побайтово. Новый `pine-versions-20261020.1` содержит по 15 принятых утверждений ограниченного профиля v1–v5, отдельные решения, ссылки и hashes каталожных записей, уровни evidence и оговорки. Здесь accepted/corroborated означает принятую **политику явно оговорённого профиля OpenPine**, а не независимое подтверждение всех исторических деталей Pine. Общие 4631 справочных записи не стали исполняемыми автоматически. Три неопределённых default `calc_bars_count` v5 сохранены неопределёнными.

Root lock закрепляет оба manifest и профили. Читатель проверяет hashes, scope, связь с базовым снимком, принадлежность каталожных источников, решения и выбранные значения. Каждый IR несёт собственные язык, semantic profile/hash и оговорки. Runtime использует разрешённые IDs; его вычисления не разрешают исторические имена повторно. Состояние принадлежит запуску и месту вызова/контексту.

```sh
python -m apps.openpine run --source conformance/versions/v1-ema.pine --bars conformance/versions/fixed.json
python -m apps.openpine run --source conformance/versions/v5-ema.pine --bars conformance/versions/fixed.json
python -m tools.release_gate
```

Новые возможности следует сразу проводить через все шесть строк матрицы: свой контракт и исполняемый пример либо обоснованное отсутствие/неопределённость с проверенным отказом. Для текущих реализованных семейств gate требует исполненные случаи каждой версии в `conformance/versions`. Успешное совпадение с нашим арифметическим oracle не следует обозначать как внешний Pine conformance.

## OHLCV и ряды во всех версиях

`pine-series-20261021.1` добавляет отдельный `openpine.series.vN.1` для каждого профиля. OHLCV, история числовых/bool рядов, na/nz, floor-modulo, min/max/round/casts и SMA/change/cross работают во всех шести версиях модели. Legacy имена сохраняются до v5, затем применяются math/ta namespaces. Недоступная bool история — na в v1–v5 и false в v6; bool na/nz перегрузки доступны только до v6. Неполные старые записи, включая casts, bar_index и отдельные сигнатуры/defaults, имеют явные реконструкции. Полные правила и таблицы проверок: [SERIES.md](SERIES.md).
