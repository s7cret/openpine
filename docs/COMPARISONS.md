# Сравнение закреплённых запусков

Сравнение читает готовые публикации, не исполняет Pine и не доказывает эквивалентность
программ или TradingView. Поддержаны успешные исторические задания со streamed result
и replay с опубликованным checkpoint. В replay учитываются подтверждённые выходы
и журнал опубликованного префикса; preview и ещё не обработанный хвост исключены.

## Закрепление и совместимость

При создании один раз сохраняются две content-addressed стороны: идентификаторы
программы, языка, CFE и спецификации, IR, исходный input, точный план/конфигурация,
параметры, модель исполнения, snapshot или sequence/hash-chain префикса, выходы и
ссылки на опубликованные ряды/журнал. Повтор того же `request_id` возвращает прежние
стороны, даже если исходный replay продвинулся. Другой запрос под тем же ID запрещён.

Разные исходники, inputs, выпуски языка и CFE отображаются в изменениях метаданных.
Разные модели исполнения — например, history и observed replay, другая политика
брокера, calculation profile, Magnifier или интервал оценки — дают
`not_comparable`. Для намеренного сопоставления данных есть явный `data_only`.
Его положительный результат называется `data_equal`; он не утверждает совместимость
моделей. В отчёте присутствуют компактные `pinned_metadata`; большие значения
заменяются размером и checksum, полная сторона остаётся отдельным неизменяемым объектом.

## Порядок и точность

Сравниваются последовательно выходные ряды, события брокера и итоговая статистика.
Первое расхождение содержит канал, индекс, путь поля, бар, время, основные контексты,
ограниченные исходные значения и типизированные представления. `na`, bool, int,
float и знаки нуля различаются. Числового допуска нет.

Выходы сопоставляются по порядку деклараций, а их заголовки/типы остаются в метаданных.
Для разных программ generated order/fill/trade ID проверяется по формуле исходного
брокера `digest(program, kind, sequence)` и заменяется проверенным порядковым номером.
Письменный call site проверяется по закреплённому IR и сопоставляется по порядку
simulation-узлов с сохранением операции. Пользовательские entry/exit/OCA ID, цены,
количества, комиссии и порядок событий сохраняют значение. Неизвестная формула или
call site вызывает явную ошибку, не успешный отчёт. Это сравнение конкретных данных,
поэтому одинаковые результаты не доказывают тождественность разных программ.

Память не зависит от числа баров: существующие Parquet readers, один бар выходов,
небольшие страницы журнала и цепочки hash. Для старых ссылок broker ID используется
восстанавливаемый SQLite-индекс в `comparison-work/ID`, до 64 MiB. Он пересоздаётся
после рестарта; пользовательский каталог не является scratch. Общий предел —
50 миллионов сопоставленных записей. Достижение предела даёт `limited` без вывода
о полном совпадении. Одновременно работает один контроллер с общим бюджетом подготовки,
двумя однопоточными readers и дисковой резервацией. Другой запрос сохраняется как
`waiting_resources` и продолжается явно.

Курсор и цепочки сохраняются каждые 512 записей и на границе каналов. Пауза/отмена
сохраняет прогресс; после остановки координатора доступен `resume`. Состояние
`interrupted`, `failed`, `waiting_resources` или `limited` не означает совпадение.

## Трасса и объяснение

При расхождении с известным баром команда `trace` создаёт по одной независимой
диагностике существующими воркерами. Входы и план закреплены; replay использует
точный опубликованный префикс. Целые архивные блоки разделяются, частичный последний
блок проверяется и копируется чанками до 1024 событий, без копирования SQL-индекса.
Прогрев исполняется с начала, запись ограничена соседними барами и обычными лимитами трассы.

Исходник, source spans, значения, ветви и события брокера поступают из реального
наблюдателя. Автоматического вывода о причинности за пределами этих полей нет.
Для чужого CFE возвращается `COMPUTATION_INCOMPATIBLE`: старые данные остаются
сравнимыми, но их нельзя молча перекомпилировать. Для воспроизведения нужна соответствующая
сборка. Старые результаты без закреплённого IR или поддержанного streamed ABI
отклоняются явно. Удалённая трасса помечается `TRACE_DELETED`.

## CLI и HTTP

```text
openpine compare run --server http://127.0.0.1:8765 --left job:LEFT_ID --right job:RIGHT_ID --id REQUEST_ID --wait
openpine compare run --server http://127.0.0.1:8765 --left replay:LEFT_ID --right replay:RIGHT_ID --mode data_only --wait
openpine compare list --server http://127.0.0.1:8765 --start 0 --limit 25
openpine compare status --server http://127.0.0.1:8765 --id ID --output comparison.json
openpine compare trace --server http://127.0.0.1:8765 --id ID
openpine compare explanation --server http://127.0.0.1:8765 --id ID --side 0 --limit 50
openpine compare pause --server http://127.0.0.1:8765 --id ID
openpine compare resume --server http://127.0.0.1:8765 --id ID
openpine compare cancel --server http://127.0.0.1:8765 --id ID
```

Чтение также доступно с `--state-dir` при остановленном сервере. Offline-команды
не запускают сравнение или воркеры. Запись и управление требуют `--server`.
HTTP: `POST /api/comparisons`, `GET /api/comparisons?start=&limit=`,
`GET /api/comparisons/ID`, `POST /api/comparisons/ID/{pause,resume,cancel,trace}`,
`GET /api/comparisons/ID/explanation?side=&start=&limit=` и
`GET /api/comparisons/ID/chart?side=&start=&limit=`. График читает закреплённую
публикацию, включая старый replay prefix, до 500 баров за запрос.

Веб позволяет выбрать стороны, открыть сохранённый отчёт, экспортировать JSON,
перейти к бару, запросить трассы и выбрать событие с подсветкой исходной строки.
Изменение выбора инвалидирует незавершённые запросы; запоздавшие ответы и ошибки
не заменяют текущую сторону. Исходный редактор не меняется.

## Каталог и удаление

Схема SQLite остаётся **16**, записи диагностики используют существующий settings.
Сравнения удерживают исходные job/replay и точные старые публикации. Обычные prune,
market maintenance, GC и backup учитывают эти ссылки.

`diagnostic-catalog list --kind trace|comparison` выводит страницы до 100 записей.
`policy`, `set-policy --keep-days N` и `candidates` управляют сроком хранения;
отсутствующий `--keep-days` отключает срок. По умолчанию срок отключён. Это список
кандидатов для явного удаления, а не скрытый фоновый TTL. Старые записи без даты
не считаются просроченными автоматически.

```text
openpine diagnostic-catalog delete-preview --server http://127.0.0.1:8765 --kind trace --id ID
openpine diagnostic-catalog delete-apply --server http://127.0.0.1:8765 --kind trace --id ID --preview-id SHA256
```

HTTP: `GET /api/traces`, `GET|POST /api/diagnostics/retention`,
`GET /api/diagnostics/{trace,comparison}/candidates`,
`POST /api/diagnostics/KIND/ID/{delete-preview,delete-apply}`.
Preview выполняет ту же мутацию метаданных в откатываемом savepoint и рассчитывает
только потерявшие последнего владельца объекты/байты. Apply проверяет свежий fingerprint;
активные записи и удерживаемые другим сравнением источники удалить нельзя.
Request ID остаётся зарезервированным после удаления. Реестры завершённых потоков
очищаются перед следующей работой и при удалении. Scratch удаляется только внутри
проверенного собственного каталога. Общие IR, свечи и другие результаты сохраняются;
физическое удаление объектов выполняет существующий offline GC после остановки сервера.

## Проверка масштаба

`python -m tools.comparison_soak --output scale.json` сравнивает реальные Parquet
публикации по 100 тысяч, миллиону и 10 миллионам строк с проверкой числа записей,
цепочек и измерением RSS. Это нагрузка на чтение и сравнение, не новый прогон Pine.
Pine, native resume и модели исполнения дополнительно проверяются существующим
корпусом и установочными сценариями.
