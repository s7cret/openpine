# Неизвестный символ в security

В Pine v4 функция `security` и в v5/v6 функция `request.security` принимают шестой аргумент `ignore_invalid_symbol`. Флаг принимает литерал `true` или `false`. Рынок и интервал можно задать строковыми литералами, неизменяемыми алиасами и выражениями выбора по настройкам. В v4 доступен generic `input`, в v5/v6 также `input.symbol` и `input.timeframe`. План фиксирует только выбранную пару до первого бара. Новый запуск может использовать тот же IR с другими настройками. Оба способа передачи аргумента, позиционный и по имени, поддерживаются. Вызов без флага сохраняет прежний контракт IR. В v1–v3 этот параметр вне профиля.

Основной снимок формата `openpine.market-input.3` содержит свечи и `symbol_catalog`. Каталог содержит версию `openpine.symbol-catalog.1`, источник `source` и отсортированный список уникальных квалифицированных имён `unknown_symbols`. Источник отвечает за это утверждение на момент создания снимка. Replay принимает тот же объект каталога в файле контекстов. Изменение источника или списка меняет идентичность снимка и replay.

| Состояние второго рынка | Флаг опущен или false | Флаг true |
| --- | --- | --- |
| Есть снимок нужного символа и интервала | Обычный ряд | Тот же ряд |
| Каталог явно указывает неизвестный символ | Ошибка входа | Пропуск на каждом баре |
| Нет снимка нужного интервала и нет записи об отсутствии символа | Ошибка входа | Ошибка входа |
| Каталог противоречит предоставленному рынку | Ошибка входа | Ошибка входа |

У пропущенного вызова нет потока свечей или состояния EMA. В числовом ряду получается `na`, в булевом ряду v6 получается `false`. К кортежу правило применяется поэлементно. На существующем рынке действуют обычные правила gaps, lookahead и проверки покрытия. Все вызовы одного задания разрешаются до первого бара, включая строгие вызовы того же символа.

Для примера из корня репозитория выполните

```text
python -m apps.openpine job --source examples/optional-symbols/indicator.pine --bars conformance/optional-symbols/market.json --contexts conformance/optional-symbols/contexts.json --plan-only
```

Поле `plan.symbol_resolutions` связывает каждый вызов с идентификатором снимка или с подтверждённым отсутствием рынка и хешем каталога. Для запуска уберите `--plan-only`. Стратегия из соседнего файла выставляет заявку на втором первичном баре и получает исполнение на открытии третьего по цене 3.

Ручной оракул и границы версии находятся в [корпусе](../conformance/optional-symbols/cases.json). Сверка с TradingView остаётся отдельным этапом.
