# Independent array.concat host examples

The corpus at `verification/builtin-array-concat-v1/manifest.json` expands the original 30 manually authored rows into 50 source cases: namespace calls in Pine v4/v5/v6 and method calls in v5/v6. The original table bytes remain unchanged (SHA256 `20d833ca9c31265c48c250dbec7edc5a9da3f9b2885e098fd0196e4d4e86ee9e`). Its 50-case corpus hash is `sha256:9b08b8cbd14d94b4df58b978dd274d821797f01301d70006d5b7bc6b0c686d54`.

The [v4](https://www.tradingview.com/pine-script-docs/v4/essential/arrays/#concatenation) and [current v6](https://www.tradingview.com/pine-script-docs/language/arrays/#concatenation) documentation states the first-array return and demonstrates mutation through that alias. The table uses literal ordered arrays; self-concat and empty-edge results are explicitly identified as consequences of that alias model. These are engineering fixtures, not TradingView execution exports. The expansion copies the table's literal snapshots without importing or calling Pine2AST, AST2Python or PineLib to construct expected values.

Each source persists three array bindings across four bars. Bar 0 initializes them; bar 1 assigns the result of concat to `c`; bar 2 pushes through `c`; bar 3 checks the unchanged state. The test reads all elements of `a`, `b` and `c`, plus reference equality. It therefore detects equal-size wrong contents and returned copies. Exact JSON scalar types are compared separately, so `False` cannot equal `0` and a float cannot silently replace an integer. Functions use reversed named `id2`/`id1` arguments; methods use named `id2`.

The runner uses the existing producer admission, compiler lowering and emitted `GeneratedScript` execution. It does not alter generated code or interpret Pine. An observation adapter links admitted global declaration IDs through the compiler's source map to actual `declare_reference_v1` argument literals in the emitted Python AST. It then uses public `SeriesStorage.read()` and `RuntimeReferenceHeap.read_payload()` APIs. It does not guess a generated storage prefix or inspect Python local variable names.

Five execution paths run in both full and compact transcript modes: direct ABI, generated historical callbacks, generated realtime trial/final callbacks, generated abort/same-sequence retry, and generated checkpoint continuation. Abort controls verify unchanged successful sequence/transcript and restored prior contents, then perform JSON checkpoint restoration before retrying. The checkpoint path restores between concat and the later push through its returned alias. Direct ABI setup uses the same public reference declaration, array construction and mutation APIs; it contains no implementation of concatenation.

This gives 500 execution examples (50 cases × 5 paths × 2 transcript modes), 2,000 final snapshots, 600 additional realtime trial snapshots and 400 JSON restore controls. Seven additional tests lock table provenance and reject wrong typed values, wrong order, changed alias identity and length mismatch. Reports use the existing builtin surface and evidence report owners, retaining the full denominator; the examples cover exactly five canonical versioned concat tuples and do not accept all builtins or all Stage2 behavior.

Committed tests read actual dependency identities from `docs/RC6_LIFECYCLE_SOURCES.json`, following the host's existing constant-metadata tests. Formal CI must run after those declared pins are updated to the published concat integration and independently verified. Local validation uses separate archived source directories, immutable concat source overlays and the actual compiler commit `7be8a705a1285d73401677a3589e96c6ecfcbd38`. Its launcher labels the result `frozen_content_snapshot`; it does not claim that uncommitted producer/runtime overlays are published Git commits. No local path override appears in the committed tests.

The pre-change control uses isolated Git archives of producer `5b90a733e548a13bd5dc88c922e7ca397059c456`, runtime `ff3fda01541795c793068bced47a0d195bf27e37` and the same compiler. Original failures, local source identities and final execution observations are preserved separately. Local results and immutable file digests are recorded in `verification/array-concat-host-local-review.json`; coordinated Linux execution with the final published pins remains a separate gate.

This corpus does not extend the mutation algorithm, heap lifecycle, compiler semantics or existing production runner. It does not establish UDT/enum array elements, mixed types, missing array handles, nested request execution or the host's outer checkpoint publication boundary. Those remain separate contracts. `full_stage2_accepted` remains false.
