# Пакетная разработка R6

Разработку и приёмку ведём на Python 3.14.8. Для пачки фиксируем
исходники, контракты, новые сценарии и их ожидаемые результаты.
Статическая матрица обновляется до коммита.

```text
python -m tools.semantic_matrix
python -m tools.release_gate --fast --changed-from HEAD --timings .runtime/batch-feedback
```

Для пачки из нескольких уже созданных коммитов укажите SHA перед пачкой
вместо `HEAD`. В GitHub Actions базу берём из события push или PR.
При переименовании учитываются оба пути. Быстрый контур
проверяет синтаксис изменённых Python-файлов, границы пакетов,
закреплённые контракты, матрицу и изменённые генераторы. Для каждого
выбранного профиля запускается один сценарий исполнения с приоритетом
изменённого `.pine` или ожидаемого результата. По умолчанию берётся
сценарий исполнения для самой новой версии профиля. Если пачка меняет случай
отказа, проверяется и один такой случай. Изменённые unittest-модули
запускаются отдельно. Общий код Binder, IR и runtime затрагивает все
профили. Несопоставленный путь или недоступная база diff явно выводятся
в журнале и тоже включают все профильные smoke.

[Статическая матрица](PINE_FUNCTION_COVERAGE.md) показывает каждую
перегрузку закреплённого справочника для её версии. В неё попадают
допущенные контракты и специальные формы компилятора. `FULL` требует
разбора полного закреплённого контракта. Совпадение имени и параметров
показывает допущенный срез, а не полноту. Инвентарь сценариев содержит
ожидаемые исходы. Проверки исполнения и сравнение с TradingView имеют
свои свидетельства.

После завершения блока, изменения общего контракта, checkpoint или
хранения, а также перед RC, запускаем приёмку техническим тегом на
выбранном SHA в `r6-rebuild`. Пример для одного кандидата

```text
git tag r6-accept/batch-01 <sha>
git push origin refs/tags/r6-accept/batch-01
```

Тег фиксирует кандидата. Полный CI проверяет его на Windows и Linux,
строит один общий wheel и сохраняет результаты conformance, нагрузочных
проверок и восстановления. После независимого аудита публикуем отчёт с
SHA кандидата и ссылкой на CI. До этого `conformance/results/` хранит
последние принятые результаты. Отчёты приёмки перечислены в
[матрице семантики](SEMANTIC_COVERAGE.md).
