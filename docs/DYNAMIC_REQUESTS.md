# Динамические запросы

## Основание для версионных правил

Сигнатуры ниже взяты из `entries[].parameters` закреплённого [справочника](../spec/bundles/pine-spec-20261020.1/reference). Позиции считаются от единицы, значения по умолчанию взяты из `default_claim.spellings`. Таблица описывает артефакты языка. Статус реализации ведётся в матрице покрытия.

| Pine | Декларация и режим | Инструмент и интервал |
| --- | --- | --- |
| v1 | Для `study` архивная запись, для `strategy` неподтверждённая. Основания включать динамический режим нет. | Архивная запись `security`, квалификаторы не установлены. |
| v2 | Для `study` сведения о совместимости, для `strategy` пример. Основания включать динамический режим нет. | Версионный пример `security`, квалификаторы не установлены. |
| v3 | В первичных записях `study` и `strategy` параметр отсутствует. | `security(symbol, resolution, …)`, оба аргумента имеют тип `string` без явного квалификатора. |
| v4 | В первичных записях `study` и `strategy` параметр отсутствует. | Те же два аргумента `string`. |
| v5 | `dynamic_requests` — `const bool`, по умолчанию `false`. Позиция 16 в `indicator`, 32 в `strategy`. | У `request.security` и `request.security_lower_tf` первые два параметра допускают написания `const/input/simple/series string`. |
| v6 | Те же тип и позиции, по умолчанию `true`. | У обеих функций те же квалификаторы. |

Для v5/v6 значение по умолчанию существенно при чтении программы без явного аргумента. Выбор рынка через замороженный `input` уже реализован в [профиле вычисляемых целей](COMPUTED_TARGETS.md). Набор квалификаторов в сигнатуре сам по себе не определяет момент выбора рынка, правила первого обращения на realtime или наследование контекста вложенного запроса.

## Декларация и сохранённый IR

Компилятор принимает именованный `dynamic_requests` и позиционный аргумент 16 у `indicator` или 32 у `strategy`. Явный режим записывается в идентичность программы. У прежнего IR режим определяется версией Pine. Команда `job --plan-only` показывает фактическое значение в поле `dynamic_requests`. При выключенном режиме серия строк в позиции рынка или интервала даёт `ARGUMENT_QUALIFIER`.

Для длинной позиционной записи имена предшествующих полей берутся из сигнатуры выбранной версии. У опций за пределами исполнительного профиля принимается только нейтральное значение. Например, у `indicator` допустим текущий интервал (`""` или `timeframe.period`), а явный интервал `"240"` в этой декларации даёт `DECLARATION_OPTION`. Такая запись не включает исполнение самого индикатора на другом интервале.

## Изменения в прежнем корпусе

В Pine v6 режим включён по умолчанию. В корпусах `computed-targets`, `prepared-requests`, `function-targets` и `primary-targets` прежние проверки отказа для серии теперь проходят компиляцию. Эти сценарии передают только свечи основного графика. Для исполнения требуется набор запрошенных рынков, поэтому ожидается `INPUT_INVALID/CONTEXT_INPUT`. В `numeric-targets/v6-series-target` интервал вычисляется из текущей цены. Для такого выражения статический план пока не может перечислить интервалы, и ожидается `PROFILE_UNCOVERED/REQUEST_SCOPE`. Исходники и идентификаторы этих сценариев сохранены. Парные сценарии v5 используют выключенный по умолчанию режим и сохраняют прежний `ARGUMENT_QUALIFIER`.

Когда оба аргумента запроса зависят от одной неизменяемой булевой переменной графика, план учитывает совместный выбор. Для пар A/1 и B/2 достаточно снимков A/1 и B/2. Две независимые переменные в тех же выражениях дают четыре потенциальные пары.

## Контрольный пример смены рынка

Из корня репозитория запустите пример на Python 3.14.8. Файл `contexts.json` ссылается на три локальных набора минутных свечей. Для повторения с контрольной точкой добавьте `--pause-after 3`, затем выполните `python -m apps.openpine job --resume <job_id>` с тем же каталогом состояния.

```powershell
python -m apps.openpine job --source examples/dynamic-requests/rotation.pine --bars examples/dynamic-requests/primary.json --contexts examples/dynamic-requests/contexts.json
```

На тех же свечах [history-selector.pine](../examples/dynamic-requests/history-selector.pine) выбирает рынок A, когда средняя двух последних закрытий основного графика превышает 1 и предыдущее закрытие равно 1. Иначе выбирается B. На втором баре средняя равна 1,5, предыдущее закрытие графика равно 1, а предыдущее закрытие выбранного A равно 10. При восстановлении после первого бара эти два значения истории и окно средней нужны уже для первого расчёта. Ожидаемые цены шести баров — 30, 12, 35, 41, 18, 48. Предыдущие цены выбранного рынка — na, 10, 37, 35, 14, 36.

Три рынка имеют по одной подтверждённой свече на каждое закрытие основного графика, с одинаковыми временем, интервалом и валютой. Выражение запроса возвращает `close` и `close[1]`. На втором посещении рынка история должна относиться к предыдущей свече этого рынка. Следующая таблица рассчитана непосредственно по входным ценам.

| Бар | A | B | C | Выбор | Ожидаемый close | Ожидаемый close[1] |
| ---: | ---: | ---: | ---: | --- | ---: | ---: |
| 0 | 10 | 30 | 80 | A | 10 | na |
| 1 | 12 | 37 | 70 | B | 37 | 30 |
| 2 | 16 | 35 | 90 | C | 90 | 70 |
| 3 | 14 | 41 | 66 | A | 14 | 16 |
| 4 | 18 | 36 | 86 | C | 86 | 66 |
| 5 | 20 | 48 | 88 | B | 48 | 36 |

Для ряда A с EMA(3), инициализированной первой ценой, значения на барах 0–3 равны 10, 11, 13,5 и 13,75. Возврат к A на баре 3 различает расчёт на истории A и расчёт только по двум посещениям A, который дал бы 12. Этот пример задаёт ожидаемое поведение исторического профиля OpenPine.
