# Динамические запросы

## Основание для версионных правил

Сигнатуры ниже взяты из `entries[].parameters` закреплённого [справочника](../spec/bundles/pine-spec-20261020.1/reference). Позиции считаются от единицы, значения по умолчанию взяты из `default_claim.spellings`. Таблица описывает артефакты языка. Статус реализации ведётся в матрице покрытия.

| Pine | Декларация и режим | Инструмент и интервал |
| --- | --- | --- |
| v1 | Для `study` архивная запись, для `strategy` неподтверждённая. Основания включать динамический режим нет. | Архивная запись `security`, квалификаторы не установлены. |
| v2 | Для `study` сведения о совместимости, для `strategy` пример. Основания включать динамический режим нет. | Версионный пример `security`, квалификаторы не установлены. |
| v3 | В первичных записях `study` и `strategy` параметр отсутствует. | `security(symbol, resolution, …)`, оба аргумента имеют тип `string` без явного квалификатора. |
| v4 | В первичных записях `study` и `strategy` параметр отсутствует. | Те же два аргумента `string`. |
| v5 | `dynamic_requests` — `const bool`, по умолчанию `false`. Позиция 16 в `indicator`, 32 в `strategy`. | У `request.security` и `request.security_lower_tf` первые два параметра допускают написания `const/input/simple/series string`. |
| v6 | Те же тип и позиции, по умолчанию `true`. | У обеих функций те же квалификаторы. |

Для v5/v6 значение по умолчанию существенно при чтении программы без явного аргумента. Выбор рынка через замороженный `input` уже реализован в [профиле вычисляемых целей](COMPUTED_TARGETS.md). Набор квалификаторов в сигнатуре сам по себе не определяет момент выбора рынка, правила первого обращения на realtime или наследование контекста вложенного запроса.

## Контрольный пример смены рынка

Три рынка имеют по одной подтверждённой свече на каждое закрытие основного графика, с одинаковыми временем, интервалом и валютой. Выражение запроса возвращает `close` и `close[1]`. На втором посещении рынка история должна относиться к предыдущей свече этого рынка. Следующая таблица рассчитана непосредственно по входным ценам.

| Бар | A | B | C | Выбор | Ожидаемый close | Ожидаемый close[1] |
| ---: | ---: | ---: | ---: | --- | ---: | ---: |
| 0 | 10 | 30 | 80 | A | 10 | na |
| 1 | 12 | 37 | 70 | B | 37 | 30 |
| 2 | 16 | 35 | 90 | C | 90 | 70 |
| 3 | 14 | 41 | 66 | A | 14 | 16 |
| 4 | 18 | 36 | 86 | C | 86 | 66 |
| 5 | 20 | 48 | 88 | B | 48 | 36 |

Для ряда A с EMA(3), инициализированной первой ценой, значения на барах 0–3 равны 10, 11, 13,5 и 13,75. Возврат к A на баре 3 различает расчёт на истории A и расчёт только по двум посещениям A, который дал бы 12. Этот пример задаёт ожидаемое поведение исторического профиля OpenPine.
