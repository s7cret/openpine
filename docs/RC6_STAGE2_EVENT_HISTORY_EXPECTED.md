# Event-history expected corpus

This engineering corpus contains 20 Pine v5/v6 cases derived from ten independently authored rows: six `ta.barssince` patterns and four canonical float `ta.valuewhen` patterns with literal occurrence zero. Four versioned callable tuples receive examples. This is not whole-function parity or Stage2 acceptance.

The original manual table is preserved byte for byte at `verification/builtin-event-history-v1/event-history-manual-expected.json` (SHA256 `53ea9e00e9bdfbc21404937b343ba850a6df2d0dc5de288dc2c71238f41167f8`). Its separate index-selection review and version-specific primary reference excerpts are retained alongside it. Expected values are copied from that table, with exact integer/float/NA tags. No runtime output generates expectations.

The original four uncertain rows remain unchanged in `authority-gaps.json`: insufficient occurrence and source-NA behavior are unverified. Their eight version cases and 64 candidate events are unassigned. Both original 28-case/224-event ABI observations are retained, including numerical matches that do not establish authority. The current occurrence metadata companion changes modern `occurrence` admission to simple int; int/bool/color valuewhen overloads remain outside this corpus.

The formal test uses `NativeRC6CompilerAdapter`, its actual admitted consumer bundle, emitted Python, artifact, source map, and exact versioned target binding. Conditions enter through positive/negative `open` values and samples through `close`; these are inputs rather than expected outputs embedded in the script. The result and condition are observed through the admitted declaration's actual emitted storage literal, selected by its source map. This adapter parses generated Python as data and executes the unchanged generated module. It does not guess storage IDs. Exact result types reject bool/int/float confusion and nonfinite values.

Each case runs on five paths, with full and compact transcripts: direct ABI, generated historical, realtime trial/final, two successive aborts with the same callback sequence followed by retry, and JSON checkpoint continuation. Abort trials change both the condition and sample. Each abort and restore compares the entire checkpoint; all final events are compared with the independent table. This gives 200 observations and 1600 final events, plus 840 trial records and 880 whole-checkpoint restores. Ten additional controls protect typed observation, literal conversion, and the closed authority-gap ledger (210 tests total).

Formal source annotations come from `docs/RC6_LIFECYCLE_SOURCES.json`, with actual component pins verified by coordinated CI. Local validation against an explicitly indexed frozen composition must identify itself as a content snapshot. On Windows, the real Native route may fail because the existing strategy-host owner imports `fcntl`. A separately labelled direct `build_consumer_bundle` → `compile_consumer_bundle` → runtime control can verify the same inputs and lifecycle; it is not a Native pass or a replacement for Linux execution. No shim, skip, expected-failure marker, or production change is introduced here.

Reports assign only the primary operation's executed canonical binding, never setup comparisons or plotting helpers. Full builtin acceptance and full Stage2 acceptance remain false. These manual primary-definition examples do not constitute a TradingView execution oracle.
