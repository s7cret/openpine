# Приёмка мест вывода меток и OHLC в R6

[Исходник bee61607f02e](https://github.com/s7cret/openpine/commit/bee61607f02e0dc037619fc0d2e5ac4aa81a46d8) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42582410407) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42582410347)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 920 тестов. Conformance охватывает 4 382 сценариев, корпус — 180 программ.

- В Pine v5–v6 проверены расширенный `display`, арифметика набора
  и выбор через замороженный булев input для пяти функций
  `plotshape`, `plotchar`, `plotarrow`, `plotbar` и `plotcandle`.
  Для v4 подтверждены границы двоичного режима.
- Прошли 17 браузерных сценариев. В статусе и окне
  данных проверены булевы значения, числовой ноль, пропуски, O/H/L/C,
  `show_last` и привязка к исходной свече при `offset`. На шкале
  проверены последний `close` OHLC, переключение между превью и
  подтверждением, отсутствие метки для стрелок и независимость автошкалы.
- Установленный wheel на обеих ОС подтвердил сохранение выбора и
  типизированных данных после смены пресета и возобновления worker.
  Пройдено чтение Parquet на разных страницах и сравнение полного
  результата CLI и HTTP.
- На Windows прошло 1 920 тестов, на Linux — 1 919.
  На Linux ожидаемо пропущена проверка псевдонимов файлов Windows 8.3.
  Обе ОС использовали один wheel. Прошли четыре сценария восстановления.
- Сохранены наблюдения 4 370
  прежних сценариев. Два ожидаемых отказа `plotarrow` с теми же
  исходниками перешли к исполнению. Добавлено 10
  сценариев. Отчёты совпали между Windows и Linux. Внешняя сверка
  с TradingView проводится отдельно.
