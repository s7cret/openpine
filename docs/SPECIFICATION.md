# Первый этап R6: спецификация

Этот документ описывает первоначальный импорт. Текущая реализация расширена
отдельными профилями: [актуальная карта семантики v1–v6](SEMANTIC_COVERAGE.md).

Исходная поставка: Pine Wiki, commit `d381665f53561bc44b9d886db6614b19daeb18b7`.
В ней выбран bundle `pine6.core-mvp.1-20261020.r2`, выпущенный из ревизии `8468e06dac821bec2785d0a39c3a0d381916b3ca`.
Это происхождение импортированных данных, а не SHA реализации OpenPine.

Все необходимые данные находятся в [spec](../spec/README.md). Подключения дополнительных репозиториев, submodules и зависимостей на прежние пакеты нет. Новый [lock](../spec/lock.json) закрепляет спецификацию; implementation pin старого reference consumer в него не перенесён.

## Версии и покрытие

| Pine | Справочные записи | Принятые утверждения в выбранном профиле | Исполнение OpenPine |
|---|---:|---:|---|
| v1 | 315 | 15 | Numeric/historical срез, частичная реконструкция |
| v2 | 365 | 15 | Numeric/historical срез, частичная реконструкция |
| v3 | 361 | 15 | Профиль по документации, SMA seed EMA |
| v4 | 626 | 15 | Профиль по документации, SMA seed EMA |
| v5 | 1444 | 15 | Numeric/historical срез, первый source как seed |
| v6 | 1520 | 55 | Частичные literal/historical профили: close, EMA; см. conformance |

Это число записей и утверждений, а не процент совместимости. Справочник v1/v2 исторически неполный; более поздние каталоги являются сохранёнными снимками. Исходные оговорки и спорные источники находятся в `source_issues` каждой версии.

Правила имеют явную область применимости. В общей модели можно переиспользовать факт между версиями только при подтверждённой области и явном включении в нужный профиль. v6 не служит неявным fallback для v1–v5. Для отсутствующей аннотации выбирается v1 согласно [правилу версии Pine](https://www.tradingview.com/pine-script-docs/language/script-structure/#version).

Имена и семантика версий могут различаться: например, `ema()` v4 стала `ta.ema()` в v5 ([таблица миграции](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-5/)). В `pine-versions-20261020.1` добавлены пять отдельных ограниченных реестров, review decisions, источники и оговорки. Исходный v6 bundle не изменён. Корроборация в этом расширении означает принятие явно описанной политики профиля OpenPine, а не доказанную идентичность старому движку TradingView. [VERSIONS.md](VERSIONS.md) объясняет реконструкцию и расхождение seed EMA.

Сохраняются три неопределённых default `calc_bars_count` v5: `request.security`, `request.security_lower_tf`, `request.seed`. Их нельзя получить как принятое значение. Неподходящая версия/контекст даёт `PROFILE_UNCOVERED`, отсутствие разрешённого факта — `SPEC_UNRESOLVED`.

Профиль v6 ограничен шестью программами и их зависимостями. В частности, `indicator`/`plot` имеют ограниченный harness-контракт; это не полный API графических handles. Стратегии, пользовательские функции, циклы, realtime и прочие исключённые конструкции не получают поддержку от самого импорта. Полный перечень ограничений сохранён в исходном registry.

## Проверяемая граница

`packages/compiler/semantic/specification.py` читает и допускает данные; `tools/specification.py` сохраняет совместимые импорты для инструментов обслуживания. `Snapshot.resolve()` выдаёт только принятое значение с подходящей версией и контекстом; он не восстанавливает значение из prose, названия или текстовой сигнатуры. Этот модуль читателя отделён от parser, Binder и runtime.

Общий gate: `python -m tools.release_gate`. Он требует Python 3.14.8, проверяет снимок, запускает unittest и сквозной conformance. CI использует тот же gate на Windows и Linux. Сеть требуется для подготовки Python и установки зависимостей; чтение данных и запуск примеров не обращаются к исходному сайту.

Первый путь Pine → compiler → runtime → результат описан в [FIRST_EXECUTION.md](FIRST_EXECUTION.md). Успехи исходного consumer и внешние Pine-наблюдения остаются отдельными видами свидетельств.
