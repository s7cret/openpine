# Разбор исполнения v1–v6

Диагностический запуск повторяет закреплённую подготовку либо сохранённый
префикс replay. Он использует тот же evaluator, брокер, очередь, supervisor
и лимиты ресурсов. Наблюдатель записывает фактические вычисления; второго
интерпретатора для объяснения результата нет. Проверяется собственная модель
OpenPine; совпадение с TradingView остаётся отдельным этапом.

В вебе выберите сохранённую подготовку или replay, задайте диапазон основных
баров и нажмите «Разобрать исполнение». Индексы начинаются с нуля, конец
диапазона исключён. События показывают исходную строку, контекст, фазу, ветку,
значение и детали. Выбор события подсвечивает сохранённый исходник. Двойной
щелчок по графику выбирает бар. Можно открыть трассу по её ID, получить следующую
страницу, скачать JSON, приостановить, продолжить или отменить диагностику.

```sh
openpine trace run --server http://127.0.0.1:8765 --launch-id ID --start-bar 10 --end-bar 12 --wait
openpine trace run --server http://127.0.0.1:8765 --replay-id ID --end-bar 2 --line 7 --wait
openpine trace events --server http://127.0.0.1:8765 --id TRACE_ID --start 0 --limit 100
openpine trace status --state-dir .runtime/jobs --id TRACE_ID
```

Для офлайн-чтения каталог должен быть освобождён сервером. Команда не запускает
работу. В POST можно передать собственный `--id` для повторяемого создания;
устаревший `--binding-sha256` отклоняется. HTTP использует `/api/traces`,
`/api/traces/ID`, `/events`, `/source`, `/pause`, `/resume`, `/cancel`.

Контракт `openpine.trace.1` связывает трассу с программой, RunPlan, входами,
binding, заданием и реальной попыткой. Событие содержит последовательный номер,
основной бар, контекст и его курсор/время, source span, site/binding/function ID,
фазу и идентификатор ветки; выражения — invocation/parent ID и фактический
типизированный результат. `ir_type` описывает IR, поле `value.type` — конкретное
наблюдение: например, результат выбора ветви — bool. `void` отличается от `na`.

Записываются присваивания, вычисленные операнды и UDF, выбранные условия,
выходы, видимость requested значений, preview/commit/discard, перенос `varip`,
проходы strategy cycle, модельные точки Magnifier, фактические намерения и события
брокера. Доступные скалярные счётчики TA-ядра читаются из первых 64 состояний;
это ограниченный снимок, а не полная выгрузка внутренней памяти. Невидимые
данные запроса не становятся доступными из-за включённой трассы.

Полное вычисление и прогрев происходят обычным способом; сохраняется только
выбранный диапазон. Максимум 1000 основных баров, 128 строк и 128 sites;
по умолчанию 10 000 событий и 8 МиБ, предел 100 000 событий и 32 МиБ.
Лимит байтов относится к сериализованным событиям; manifest, JSON-обрамление
и обычные входы/результаты задания учитываются отдельно.
Предпросмотр массива — по умолчанию 8, максимум 16 элементов и два уровня;
строка — 256 символов, отдельное событие — максимум 16 КиБ. Страницы API
содержат до 500 событий. Чанки примерно по 32 КиБ записываются потоково.
Лимит или ошибка записи явно помечают усечение; это не ошибка расчёта Pine.
После конца диапазона или остановки записи evaluator возвращается к прямому
пути. При выключенной трассе обычные выражения обходят наблюдатель.

Историческая диагностика получает отдельное задание с тем же неизменяемым
планом; исходная подготовка и её результат сохраняются. Native checkpoint
продолжается только с выровненным trace-префиксом. Утрата префикса явно
отмечается, чужие попытки не склеиваются. Replay фиксирует config, длину и
конечную hash chain на момент создания. Архивные Parquet-блоки разделяются
через ссылки; небольшой незапечатанный хвост сохраняется отдельно. Миллионы
строк индекса SQLite не копируются. Воркер проверяет блоки, цепочку и курсоры;
исходный replay может независимо продолжать live-работу. Диагностика проверяет
свой зафиксированный префикс и не подтверждает исполнение всей программы.

Каталог остаётся на схеме **16**. Ссылки на трассы и frozen tape входят в
существующий обход объектов для GC и резервных копий. Диагностические записи
сохраняются в каталоге; отдельного автоматического срока их удаления пока нет.
Общий лимит диска применяется и к ним.

Наблюдаемые hooks изменяют вычислительную идентичность этой сборки. Старые
результаты читаются, но native checkpoint предыдущей вычислительной версии
не продолжается молча: действует штатный отказ `PLAN_IMPLEMENTATION` и явный
перезапуск с перекомпиляцией на закреплённых исходных входах.
