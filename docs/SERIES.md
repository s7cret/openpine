# OHLCV, история и простые индикаторы

Все пять возможностей этого этапа работают в профилях v1–v6: OHLCV, история `[]`, `na/nz`, числовые операции и SMA/изменения/пересечения. Семантика согласованной модели закреплена в `pine-series-20261021.1`; исходные три bundle сохранены побайтово.

Пример, объединяющий все пять пунктов:

```pine
//@version=6
indicator("Series")
typical = (high + low + close) / 3
average = nz(ta.sma(typical, 2), close)
delta = ta.change(close)
signal = ta.crossover(close, average)
plot(average)
plot(nz(delta))
plot(nz(close[1]))
plot(math.min(math.max(volume, 0), 350))
plot(signal ? 1 : 0)
plot(math.round(nz(delta) / 3, 2))
```

```sh
python -m apps.openpine run --source conformance/series/v6-combined.pine --bars conformance/series/ohlcv.json
python -m apps.openpine run --source conformance/series/v1-combined.pine --bars conformance/series/ohlcv.json
python -m tools.release_gate
```

На fixture close `10,20,null,30,40` средняя в этом примере равна `10,15,15,25,35`, сигнал — `0,1,0,0,0`. Для каждой версии есть собственная программа `vN-combined.pine`.

## Данные

Поддерживаются два точных формата с общими полями `schema_version`, `context_id`, `symbol`, `timeframe`, `bars`:

| Schema | Поля каждого бара |
|---|---|
| `openpine.historical-bars.1` | `time`, `close` |
| `openpine.historical-bars.2` | `time`, `open`, `high`, `low`, `close`, `volume` |

Все пять ценовых/объёмных значений — конечные числа или `null`; bool и нечисловые строки отвергаются. Числа нормализуются в float. Объём неотрицателен; определённые цены удовлетворяют `low <= open/close <= high`. Допускается частично отсутствующий OHLCV, его значения остаются na. Формат `.1` сохраняет прежний hash нормализованного контракта; новые слоты при его исполнении равны na.

`open/high/low/close/volume` имеют тип series float; `bar_index` — series int, начинается с нуля. Индекс определяется порядком переданных баров, без заполнения временных промежутков. В нашем профиле он включён для всех шести версий; отсутствие старой справочной записи явно отмечено как реконструкция. Контекст один на запуск; вход до 8 MiB и 100000 баров. SHA данных `.2` включает весь OHLCV.

## История `[]`

Индексирование поддерживает числовые и bool ряды: `close[1]`, `x[2]`, `(close * 2)[1]`, `ta.sma(close, 2)[1]`. Индекс — int, в том числе series int, от 0 до 100000. `[0]` возвращает значение в текущей точке исполнения. Отрицательные/слишком большие/неопределённые индексы дают диагностику, не читают будущие данные. Float и bool как индекс отвергаются статически. Индексирование литерала, строк и повторное `x[1][1]` не входят в этот профиль.

Встроенные данные сохраняются для каждого бара. История переменной сохраняет её **итоговое значение в конце бара**, независимо от точки чтения её прошлого значения. Даже переменная с постоянным инициализатором получает series qualifier при использовании истории. Обычная локальная переменная на пропущенном баре имеет пропуск; уже инициализированный локальный var сохраняет значение.

История написанного выражения фиксирует результат при его достигнутом выполнении. На пропущенном баре остаётся пустое место; последующее обращение не запускает выражение задним числом. Вызов под `[]` выполняется один раз на достигнутом баре, включая `[0]`; прошлая запись читается отдельно. Прочитанная переменная не повторяет свой инициализатор.

Недоступная числовая история — na. Bool история в v1–v5 возвращает na, в v6 — false. В v1–v5 `not na` остаётся na; `and/or` используют трёхзначную логику: false определяет `and`, true определяет `or`, иначе пропуск сохраняется. При выборе ветки отсутствующий bool трактуется как false. Прежние version policies strict/lazy вычисления операндов сохраняются.

Истории создаются только для используемых источников. Буферы индексируются по барам; общее хранилище историй и SMA/change ограничено 1000000 ячеек на запуск. Превышение даёт `HISTORY_STORAGE` и закрывает неуспешный запуск.

## Пропуски и числа

- `na(x)` проверяет числовой пропуск; bool поддержан в v1–v5.
- `nz(source, replacement)` возвращает замену при na; без замены используется 0 соответствующего числового типа или false для legacy bool. Числовые source/replacement приводятся к общему int/float; оба аргумента вычисляются eagerly. Bool перегрузки в v6 отвергаются.
- `int(x)` усекает float к нулю; `float(x)` преобразует int в float. Числовой na сохраняется, qualifier исходника сохраняется. Строковые и bool преобразования этим профилем не добавлены.
- `%` использует остаток с floor quotient: `-5 % 3 == 1`, `5 % -3 == -1`. Нулевой делитель и числовой na дают числовой na.
- `min/max` принимают 2–32 позиционных числовых аргумента. При смешении int/float все приводятся к float; результат получает самый сильный qualifier аргументов. Na распространяется.
- `round(number)` возвращает int; `round(number, precision)` — float. Precision — int от -15 до 15. При равенстве половине округление идёт к положительной бесконечности: `-2.5 -> -2`, `2.5 -> 3`. Модель использует десятичное представление конечного входного значения; na распространяется. Python banker's rounding не применяется.

Существующие ограничения конечных float и signed 64-bit int сохраняются; выход за диапазон возвращает диагностику `VALUE_RANGE`.

## SMA, change и пересечения

| Функция | Политика модели |
|---|---|
| `sma(source, length)` | Среднее последних length значений source, отличных от na. До их накопления — na; входной na не добавляет образец. Length принимает series int 1..100000, изменение длины использует сохранённые образцы |
| `change(source, length=1)` | Разность текущего и отстоящего на length достигнутых вызовов значения; для bool — факт изменения. Пропуски включаются. Length принимает series int 0..100000; для 0 числовая разность равна 0, если source определён |
| `crossover(a,b)` | Текущее `a > b` и предыдущее `a <= b` |
| `crossunder(a,b)` | Текущее `a < b` и предыдущее `a >= b` |
| `cross(a,b)` | Любое из двух направлений |

Пересечения без предыдущей пары или с na возвращают false; текущая пара всё равно становится предыдущей для следующего достигнутого вызова. Первый bool change — na в v1–v5 и false в v6.

Каждый написанный stateful вызов имеет собственное состояние в контексте текущего запуска. Пропущенные вызовы, включая пропущенный var initializer, не обновляют его. Для SMA/change/cross «предыдущий» относится к достигнутым вызовам; у оператора `[]` отдельная привязка к барам. Новые запуски и контексты изолированы.

SMA суммирует точные двоичные значения float в целых единицах `2**-1074` и округляет только итоговое среднее. Кольцо префиксных сумм даёт O(1) доступ при изменяющейся длине, сохраняет малые значения при компенсации больших и не переполняет промежуточный float sum.

## Версии, спецификация и проверки

В v1–v4 используются `study`, `min/max/round`, `sma/change/cross/crossover/crossunder`; в v5/v6 — `indicator`, `math.*`, `ta.*`. `na/nz/int/float` остаются глобальными. У SMA/change параметры v1/v2 — `x,y`, затем `source,length`; у cross — `x,y` до v5, затем `source1,source2`. `nz` использует `x,y` до v5, затем `source,replacement`. В v1/v2 новые API допускают только позиционные вызовы. Реконструкции недостающих сигнатур/optional defaults записаны в review нового bundle.

Root lock закрепляет новый manifest; каждый профиль выбирает собственный `series_profile_id`. Читатель проверяет JSON Schema, hashes, принадлежность каждой ссылки на каталог своей версии и имени, а Runtime — реализованную форму policy. Импортёр сохраняет новый pin. `python -m tools.series_spec --check` воспроизводит bundle без исполнения runtime и без генерации тестовых ожиданий.

Typed IR версии `openpine.typed-ir.4` содержит явный HistoryIR с источником, индексом и ID хранилища. Допуск IR проверяет типы, принадлежность источников и IDs до эффектов. Runtime получает только очередной BarFrame и собственное состояние.

Корпус `conformance/series` содержит **96 случаев: 54 успешные программы и 42 ожидаемых отказа**, по 16 на версию. Девять успешных программ каждой версии включают общий пример всех пяти пунктов. Ожидания заданы вручную, отдельно от реализации. Unittest дополнительно проверяют SMA через независимые Fraction суммы, отсутствие будущих данных, порядок записей, пропуски блоков, legacy bool, границы хранения, подмену IR и спецификации, изоляцию запусков и CLI. Сравнение с TradingView остаётся отдельным этапом.
