# OpenPine — библиотеки в обычном compile/validate: локальный результат

**Код не опубликован. Весь этап 2 не принят.** Кумулятивная поставка включает прежние
numeric/index и explicit-methods блоки. Предыдущие архивы поверх неё накладывать не нужно.

## Что реализовано

Один потребительский путь: явные locked библиотеки → существующий linker/compiler →
сохранение → проверенное чтение артефакта → действующий runtime/broker. Python API,
CLI и HTTP используют одних владельцев допуска, диагностик и сохранения.

Исправлен прежний реальный блокер: библиотека компилировалась, но ArtifactStore
сравнивал исходный root с виртуальным связанным Pine и отвергал сохранение. Теперь
оба представления проверяются отдельно через sealed context; проверяются точные
зависимости и заново выводимая карта original-source. Подмена root, библиотек,
receipt, dependency hashes и даже повторно захешированного sidecar отклоняется.

Доступны `openpine pine compile`, прежний alias `pine-compile` и новый `pine validate`,
флаги `--library-lock`, `--expected-library-lock-hash`, JSON диагностика validate.
HTTP принимает необязательный inline body `libraries`, не путь на сервере; старые
клиенты без body сохранены. При подготовке нет latest/network resolver и обхода
LibraryStore. Неуспешная компиляция сохраняется отдельно и не активируется.

Исходник и библиотеки фиксируются до постановки compile на выполнение. Сам compiler
работает вне HTTP event loop; SQLite остаётся на прежнем потоке. При редактировании
root за время компиляции результат сохраняется, но не активируется. Это локальная
проверка одного gateway-процесса, не полноценная межпроцессная версия очереди/lease.

Ошибки frontend и compiler finding с точным node_id отображаются в координатах
исходной библиотеки. Неизвестные координаты не угадываются. Успешный source map
сохраняется sealed как прежде; добавлена проверяемая sidecar-проекция. Столбцы —
нормализованные Unicode-позиции, не raw UTF-8 offsets. Full runtime traceback и
подсветка browser/editor этим блоком не объявляются готовыми.

## Исполнение и тесты

Библиотечный артефакт сначала сохраняется и читается с диска. Два счётчика с шагами
1 и 10 на третьем баре дают 3 и 30, стратегия реально отправляет qty=33, fill price
102 на закрытии либо 103 на следующем открытии. Проверены v5/v6, fill-recalculation,
оба транспорта и JSON restore. In-memory transport harness не выдаётся за sandbox;
четыре самостоятельных новых теста требуют настоящего Bubblewrap.

Все шесть оставшихся отказов — Bubblewrap отсутствует (четыре новых и два прежних
stage1 worker). Ноль skips/errors в итоговых наборах. Все 601 Provider-case без пяти
live-network прошли в этом окружении; прежние EIO не маскировались и fsync не отключён.
Полный parser включает ранее проблемные packaging fixtures: настоящий offline PyPA
build доступен, эти тесты теперь выполнены. Это локальный результат, не новый CI.

Новых тестов **101: 97 passed, 4 failed**. Помимо них десять старых проверок
compile_pipeline включены в постоянный affected-path список; это не десять новых
тестов. Все прежние 21 446 IDs сохранены, обязательный inventory теперь **21 557**.
Полное collection выполнено, но collection не является исполнением всех 21 557.

Ruff, compileall, архитектура и экспорт полной OpenAPI схемы успешны. Заново собраны
wheel/sdist двух изменённых пакетов (Pine2AST и OpenPine); остальные шесть пар
сохранены из предыдущей согласованной поставки. В новом venv **без system-site-packages**
установлены только настоящие wheels и их зависимости из offline-кеша. `pip check`
успешен. Вне рабочих исходников с `python -I` повторно выполнен весь новый корпус:
**97/101 passed**, те же четыре Bubblewrap отказы. Эти повторы к итоговым XML не
прибавлены. Сопоставлены 535 production Python-файлов четырёх изменявшихся пакетов.

Сохранены начальные ошибки и исправления: неверные строки библиотечного test fixture,
ошибка имени AST-kind в fault injection, три прежних defensive admission отказа,
первоначальная неверная tests-import среда Contracts и отсутствовавшие build identity
в fake CLI / fresh-wheel HTTP запуске. Код не подбирался под ослабленные assertions.
Настоящие текущие producer/build IDs заданы существующей конфигурацией для финального
прогона; общий произвольный fallback identity не добавлен.

## Граница завершения

IMPORT-04 теперь **implemented_local_pending_joint**, не accepted. 16 пакетов,
четыре исходных критерия и номера OP сохранены. Численный index текущих producer pins
не прогонялся; прежние UNVERIFIED ожидания str.tonumber v5 не менялись и не объявлены
исправленными. Также не выполнены Python 3.11, полный host/optimizer, GitHub CI,
Node/browser и измерение производительности. Межверсионные импорты остаются открыты.

Девять прежних runtime-файлов request/config/checkpoint/worker/strategy/optimizer и
UI-дерево побайтно совпадают с опубликованной базой. Публикация — по отдельной команде.
Текущий результат — полный накопительный код, история и проверки, не production-инсталлятор.
