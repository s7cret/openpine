# Приёмка видимости визуальных рядов R6

[Исходник 6640395c4b4b](https://github.com/s7cret/openpine/commit/6640395c4b4b6d2a9f612cb5bb3782c953601eaf) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42522508353) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42522508543)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 916 тестов. Conformance охватывает 4 360 сценариев, корпус — 180 программ.

- В Pine v4–v6 проверены `display.all` и `display.none` у `plot`,
  `plotshape`, `plotchar`, `plotarrow`, `plotbar` и `plotcandle`.
  В v5–v6 также проверены `hline`, `bgcolor`, `barcolor`, обычные
  заливки и градиентный `fill` между двумя `plot`.
- Прошли 16 браузерных сценариев. Скрытые ряды остались
  доступны для видимых заливок. Проверены автошкала, легенда, подсказки,
  смещения и окна отображения в истории и replay.
- Установленный wheel на обеих ОС подтвердил, что после изменения пресета
  и возобновления worker сохраняется видимость исходного запуска. Значения
  скрытых рядов доступны через Parquet, API диапазона и полный экспорт.
  Полные результаты CLI и HTTP совпали.
- На Windows успешно выполнено 1 916 тестов, на Linux — 1 915.
  На Linux ожидаемо пропущена проверка псевдонимов файлов Windows 8.3.
  Обе ОС использовали один wheel. Проверены четыре сценария восстановления.
- Сохранены наблюдения всех 4 328 прежних сценариев.
  Добавлено 32 новых. Все отчёты совпали между Windows
  и Linux. Сверка с TradingView относится к отдельному этапу.

В первой приёмке тест обнаружил поле display в dataclasses.asdict() прежнего PlotOutput. Для явного display введена отдельная форма результата, а прежний PlotOutput сохранил свой набор полей.
