# Лоты и наращивание позиции

`pine-lots-20261024.1` закрепляет `openpine.lots.vN.1` для v1–v6.
Новый профиль выбирается положительным литералом `pyramiding` либо явным
`close_entries_rule` в `strategy`. Остальные объявления сохраняют прежние
контракты и брокеры, включая явный `pyramiding=0` без нового правила закрытия.

```pine
//@version=6
strategy("Lots",pyramiding=3,close_entries_rule="ANY",default_qty_type=strategy.fixed)
if bar_index==0
    strategy.entry("A",strategy.long,qty=2)
if bar_index==1
    strategy.entry("B",strategy.long,qty=3,limit=100)
if bar_index==4
    strategy.close("B",qty=1)
plot(strategy.position_size)
plot(strategy.position_avg_price)
plot(strategy.equity)
```

В локальном каталоге v1 нет полной сигнатуры заголовка. Pyramiding присутствует
в v2–v6, close_entries_rule — в v4–v6. Пробелы v1 и правила выбора v1–v3
восстановлены явно; это ограниченная модель по артефактам. Внешнее исполнение
TradingView не использовалось как oracle.

## Лоты и позиция

`simulation/ledger/lots.py` хранит отдельную запись каждого активного входного
fill: исходное количество, остаток, цену, исходную и распределённую комиссию,
время и идентичности fill/order. Текстовый ID входа может повторяться у
нескольких лотов. Замена pending-входа с тем же ID сохраняет уже открытые лоты.

Общая позиция вычисляется из лотов: подписанное количество, стоимость остатка
и взвешенная средняя цена. Комиссии учитываются отдельно от средней цены.
Все активные лоты имеют одно направление. Pyramiding ограничен 0…16;
0 разрешает один лот. Предел проверяется при допустимом исполнении входа,
лишняя заявка получает причину `pyramiding_limit`. Общий объём ограничен 1e24.

Новый брокер использует ledger как отдельный компонент и общие функции
валидации, округления количества и пересечения entry-уровней. Он не наследует
цепочку market → protective → partial → pending брокеров.

## Выбор закрываемых лотов

Количество close/exit сначала вычисляется по текущему остатку лотов с нужным
ID входа: qty имеет приоритет над qty_percent, затем объём округляется вниз
до quantity_step и ограничивается доступным количеством.

| Правило | Закрепляемые лоты |
| --- | --- |
| `FIFO` | Самые ранние активные лоты всей позиции |
| `ANY` | Самые ранние активные лоты с указанным ID входа |

Market-close закрепляет конкретные lot ID и количества в момент команды.
Несколько закрытий на одном баре получают непересекающиеся остатки в порядке
исходника. Замена команды освобождает её прежние targets. Исполнение на
следующем open ограничивается сохранившимся остатком этих лотов и никогда
не закрывает будущие входы вместо исчезнувших targets.

Защитный exit выбирает существующие лоты с нужным ID, иначе закрепляет точный
pending entry order. После его fill выбираются конкретные лоты по FIFO/ANY,
с учётом уже существующих резервов. В FIFO это могут быть более ранние лоты.
Далее привязка фиксирована: она не переходит к будущему входу с тем же ID.
Резервирование не может дважды занять один объём лота. После другого закрытия
резерв уменьшается без автоматического расширения на другие лоты.

Противоположный entry закрывает все старые лоты одним exit fill, затем
открывает запрошенное новое количество отдельным entry fill. Защита старых
лотов отменяется. Cancel/cancel_all отменяет соответствующие pending-команды
и защиту; открытые лоты остаются открытыми.

## Комиссии и журнал

Каждый fill получает одну округлённую комиссию. Один выходной fill может
создать несколько записей trade, по одной на закрываемую часть лота.
Выходная комиссия распределяется накопительно между этими частями; последняя
получает остаток. Входная комиссия каждого лота также распределяется
накопительно по его исходному количеству, включая последнюю закрытую часть.

`fill.entry_id` обозначает ID команды. `trade.entry_id` и `trade.lot_id`
обозначают фактически закрытый вход, а `requested_entry_id` сохраняет ID
команды закрытия. Это позволяет проследить FIFO-закрытие другого входа.
`remaining_quantity` относится к лоту; `position_remaining_quantity` — ко всей
позиции. `lot_closed`, `closed_lots` и `closed_positions` различают закрытие
лота и полное опустошение позиции. `trades` считает закрытые части.

Используется подтверждённая OHLC-модель [отложенных входов](PENDING_ENTRIES.md):
известные open-исполнения, затем защита, затем не более одного фактического
внутрисвечного входа. Внутрисвечная активация stop-limit откладывает его limit
до следующего бара. Защита внутрисвечного входа также ждёт следующий бар.

## Состояние и приложение

`openpine.broker-state.5` содержит только активные лоты, текущие очереди,
targets, резервы и накопительные итоги. Закрытые части хранятся в журнале,
а не в растущем checkpoint. Reader проверяет весь кандидат до присваивания:
идентичности, границы времени, шаг количества, распределение комиссий,
резервы, счётчики, агрегированную позицию и равенство cash учётной модели.
Прежние состояния .1–.4 автоматически не мигрируют в новую схему.

`openpine.simulation.5` экспортирует лоты и новую policy. Контейнер RunPlan
сохраняет свою схему; полная lot policy проверяется отдельным закрытым reader.
`openpine.chart-window.5` передаёт состав позиции на mark и точные targets
выходов в выбранном диапазоне. Сохраняется ограничение 5000 событий.

Веб показывает таблицу лотов на выбранном подтверждённом закрытии: ID, бар
входа, направление, остаток, цену и остаток входной комиссии. Таблица событий
связывает закрытые части с лотом и показывает остаток всей позиции.
Worker, CLI/HTTP, saved IR, experiments, search/holdout и walk-forward используют
тот же профиль.

## Примеры и границы

[18 примеров](../examples/lots/) включают FIFO, ANY и сочетание limit/stop-limit
с частичным закрытием и изменением защиты, для каждой версии v1–v6.
Параметр `Partial quantity` принимает 1 или 2; по умолчанию 2.
При значении 1 FIFO/ANY дают капитал 2146 на 360 барах, conditional — 4510.5
на 400 барах. Полные ряды рассчитаны независимо в `tools/lot_oracle.py`.
[Корпус](../conformance/lots/cases.json) содержит 114 исполнений и 36 отказов.
Конкретные execution IDs проверяются отдельно от семантической проекции корпуса.

За пределами выпуска: strategy.order, произвольные OCA-группы, встроенный
trailing, sizing в деньгах/процентах капитала, margin, объёмные частичные
исполнения входа и защитное исполнение на незакрытой наблюдаемой свече.
[План и приёмка](LOTS_PLAN.md).
