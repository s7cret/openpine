# Приёмка единой памяти R6 · 2026-10-28

Все семь пунктов приняты для исходника `606e0af98e00e5606d4343ee210ff408a7ee84b9`:

1. Инвентаризированы владельцы: баровая история, SMA/change, фиксированные и меняющиеся окна, прогрев EMA, массивы, private contexts, varip, preview, restore, IO и временные буферы.
2. Доказанная глубина распространяется на SMA, change и `[]` во всех версиях Pine 1–6; неизвестные границы сохраняют весь разрешённый горизонт.
3. Универсальная плата заменена типизированными стоимостями. Лимит логических ячеек остаётся отдельным.
4. Общая политика распределяет память состояния/restore, IO и служебный резерв внутри прежнего лимита процесса. Проверка 8 рынков и 16 запросов проходит при 512 МиБ.
5. В requirements и `resources.json` различаются статическая оценка, причины retention, фактические логические ячейки, byte ledger и образец RSS; owner включает private request site.
6. Пройдены 1,000,002 события, 10,000,020 численных проверок и столько же сохранённых значений на трёх рынках. Использованы два разных процесса, дисковый checkpoint и production Parquet sink; проверены уникальные полные диапазоны output.
7. Сохранены все 1230 прежних test ID, добавлены 17 проверок. Все 2419 прежних наблюдений совпадают. Helper перераспределены внутри прежних 18 suites/ОС; CI остаётся из 53 заданий.

[CI: 53/53 с первой попытки для принятого исходника](https://github.com/s7cret/openpine/actions/runs/40704942820).
На каждой ОС: 1247 тестов в 141 модуле, 2419 наблюдений — 1601 исполнение и 818 ожидаемых отказов.
Linux и Windows используют один общий wheel; его члены побайтно совпали с локально проверенным wheel.
Локально дополнительно пройдены полная спецификация, все шесть native shards и установочные suites core/windows/signals/contexts вне checkout.

Большой сценарий: peak RSS 147730432 байт (140.9 МиБ), peak charged 37080384 байт,
checkpoint 4668844 байт, 602.829 с. PID тестовых процессов: [70192, 62100].
Числа относятся к смешанному сценарию с ростом длины до 4096; их нельзя переносить на произвольный скрипт.

Повторная полная приёмка потребовалась после `88bea79`: первая четверть IO-бюджета оказалась слишком мала для максимального числа readers.
В принятом исходнике IO получает треть общего бюджета, состояние/restore — половину, остальное — базовые и временные расходы.
Общий лимит не увеличен. Промежуточный CI 40701587432 отменён и не засчитывается как успешный.

Изменены два ресурсных ожидания с сохранением ID: проверки хранения используют типизированные платы;
трёхъячеечная квота теперь проверяется на `close[4]`, поскольку `close[1]` после доказательства глубины занимает одну ячейку.

Неизменяемые Wiki bundles и остальные нормативные spec-файлы сохранены; изменён только внутренний профиль хранения.
Зарезервированные байты не являются RSS. Большой restore может быть отклонён по совокупному живому владению до публикации.
Неизвестный прогрев старой EMA отдельно помечается неполной статической оценкой. Точное соответствие TradingView остаётся отдельным этапом.
