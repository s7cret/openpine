# Подготовка запусков и приёмка

Этап сокращает повторную подготовку при сохранении существующих версионных правил Pine.

## Спецификация и варианты

`compiler.semantic.snapshot_cache` хранит до двух частных проверенных шаблонов.
Ключ включает абсолютный корень, Python и хеши содержимого всех файлов `spec/`:
lock, профили и версионные справочники. Время изменения файла не заменяет хеш.
Ошибочная проверка не создаёт запись кеша; изменение файлов во время первоначальной
проверки отклоняется. Каждая Session получает глубокую копию Snapshot и собственный
Catalog. Изменяемые каталоги, runtime, TA/UDF, история и брокер не разделяются.
Явно переданный Snapshot сохраняет прежний путь и диагностики проверки.

`Preparation.batch()` ограничен потоком и одним вызовом подготовки. Он закрепляет
идентичность кода/spec, проверяет её перед завершением и освобождает кеш при успехе
или исключении. Переиспользуются неизменяемые IR и ссылки на уже опубликованные
входы: до 16 небольших IR размером до 512 КиБ каждый. Большие программы читаются
обычным путём. При повторном использовании байты объектов проверяются по content ID.

Настройки, выбор снимков и RunPlan строятся для каждого варианта отдельно.
Все варианты проверяются до публикации группы. Форматы IR и RunPlan сохраняются.

## HTTP и интерфейс

Закрытый список POST-чтений использует бюджет чтения:

- `/api/launches/requirements`;
- `/api/launches/history-spec`;
- `/api/launches/{id}/research-base`.

`research-base` читает уже готовую подготовку и не продвигает её состояние.
Python-клиент и браузер допускают ограниченные повторы этих чтений при временном
COORDINATOR_BUSY либо потере соединения. Смешанные ошибки хранилища и окончательные
отказы не повторяются. Сохраняются число попыток, deadline, Retry-After и отмена.
Создание и управление без ключа идемпотентности не получают автоматических повторов;
создание исследований использует прежний устойчивый request ID.
`LatestRequest` отменяет устаревший запрос требований; поздний ответ либо ошибка
не заменяют состояние новых параметров.

## Измерения

```sh
python -m tools.preparation_benchmark --directory .runtime/preparation-benchmark
python -m tools.preparation_flow --directory .runtime/preparation-flow
python -m tools.ui_race_check --port 0
```

Benchmark сохраняет cProfile, время, чтения спецификации, декодирования внутри
Preparation и логические настройки/снимки для 1/32/256 вариантов. Холодная и повторная
Session измеряются отдельно. Время относится к данной машине и одинаково
инструментированным прогонам, а не к скорости Pine на любых программах.

Flow загружает исходник из файла, сохраняет IR, выбирает другой контекст, исполняет
UDF с SMA и накопительным состоянием, приостанавливает worker и восстанавливает
replay после перезапуска. v1/v6 дополнительно воспроизводятся из IR и ленты в новом
офлайн-хранилище; v5/v6 проверяют младшие массивы. Ожидания выведены через Fraction.
Браузерная fixture `/preparation` проверяет восемь сценариев повторов и гонок.

CI использует шесть тестовых частей на ОС, один wheel и все 15 установочных наборов
на каждой ОС. Feedback/build идут параллельно; итоговая приёмка требует успешного
feedback и всех остальных этапов. [План и результаты](PREPARATION_PLAN.md).
Сверка с TradingView остаётся отдельным этапом.
