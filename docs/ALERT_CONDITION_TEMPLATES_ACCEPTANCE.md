# Приёмка подстановок `alertcondition()` в R6

[Исходник 3134ee8974c8](https://github.com/s7cret/openpine/commit/3134ee8974c8eb2b8d34742978e94b2d0a943c51) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/43259315264) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/43259316915)

SHA 3134ee8974c8. CI 57/57, Python 3.14.8. В реестре каждой ОС 2 006 тестов. Conformance охватывает 4 591 сценариев, корпус — 180 программ.

- Профиль `openpine.alertcondition-templates.1` проверен на Pine v4–v6. Сообщения используют OHLCV, закреплённый контекст и часы ленты. Числовые `plot()` читаются по имени и индексу из того же расчёта, включая скрытый вывод после объявления условия.
- Проверены буквальное сообщение v2–v3, предел индекса, неоднозначное и отсутствующее имя, значение `na`, неизвестный токен, отсутствие публикации на историческом префиксе и граница 4 096 байт UTF-8.
- На общем wheel в Windows и Linux сравнили HTTP-журналы непрерывного replay и replay с перезапуском внутри второй свечи. Совпали готовые тексты, порядок оповещений и буквальное сообщение `alert()`.
- На Windows прошли 2 006 тестов, на Linux — 2 005. На Linux пропущена проверка коротких путей Windows 8.3. Подтверждены четыре отчёта восстановления.
- Сохранены 4 586 прежних наблюдений. Добавлены пять проверок сохранения исходного шаблона в метаданных Pine v2–v6. Отчёты conformance совпадают между Windows и Linux.

В первом прогоне Windows-группа `lots` остановилась с `JOB_TIMEOUT` после возобновления ANY v2 на 144-й из 360 свечей. Сценарий сохранял checkpoint на каждой свече. Повтор прошёл на том же SHA и wheel с исходными лимитами. [Первый журнал](https://github.com/s7cret/openpine/actions/runs/43259316915/job/131343321973) · [Повтор](https://github.com/s7cret/openpine/actions/runs/43259316915/job/131407953710)

На локальной Windows группа `lots` прошла на том же wheel. ANY v2 возобновился и завершился за 32 секунды при лимите 120 секунд.

Сверка с исполнением TradingView проводится отдельно.
