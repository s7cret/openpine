# Приёмка переменных в сообщениях об исполнении R6

[Исходник 137a860c9503](https://github.com/s7cret/openpine/commit/137a860c950318b745cecdebfac5dc8ca7f2780a) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/43215623003) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/43215623022)

SHA 137a860c9503. CI 57/57, Python 3.14.8. В реестре каждой ОС 2 003 теста. Conformance охватывает 4 586 сценариев, корпус — 180 программ.

- В Pine v4–v6 сообщения читают закреплённые скалярные входы, чистые глобальные выражения и глобальные скаляры `var`. С v5 те же выражения доступны в сообщениях защитных выходов.
- Проверены чтение `var` до расчёта стратегии и исполнение после расчёта закрытия. Сделки и капитал совпали с контрольным replay. Отдельный сценарий проверил исполнение до первой подтверждённой свечи.
- На общем wheel в Windows и Linux сравнили HTTP-журналы непрерывного replay и replay с перезапусками между отложенным входом и защитным выходом. Совпали тексты, `order_id`, `fill_id` и порядок рядом с `alert()`.
- На Windows прошли 2 003 теста, на Linux — 2 002. На Linux пропущена проверка коротких путей Windows 8.3. Подтверждены четыре отчёта восстановления.
- Сохранены 4 583 прежних наблюдений. Добавлены три проверки границ для локальной переменной, ссылки на историю через глобальное имя и изменяемой обычной переменной. Отчёты conformance совпадают между Windows и Linux.

Сверка с исполнением TradingView проводится отдельно.
