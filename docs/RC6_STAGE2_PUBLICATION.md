## Что реализовано

### Once, скалярные блоки и возвращаемые значения

Добавлена именно условная структура `once` v6: lexer → AST → semantic facts → checked lowering → существующие транзакционные slots PineLib. Условие необязательно; блок не становится значением или новым режимом объявления переменной. Старые версии не получают новую конструкцию и сохраняют возможность обычного идентификатора `once`.

Каталог расширен явным дополнением версии. Архивный migration input не переписан ради нового ключевого слова. Добавлены отрицательные формы: старая версия, не-bool условие v6, попытка присвоить void и запрещённые вызовы из локальных блоков.

`if`/`switch` могут возвращать скалярное значение, в том числе в конце UDF. Последнее объявление или присваивание функции также возвращает своё значение, а не Python `None`. При отсутствии подходящей bool-ветки v6 получается false; старые версии сохраняют NA. Значения NA выпускаются как канонический sentinel PineLib, а не неявная Python truthiness.

### Области записанных вызовов и история

Каждый записанный вызов UDF получает независимый путь состояния. Два вызова одного счётчика не делят `var`; один и тот же вызов внутри цикла не создаёт новое состояние на каждую итерацию. Параметры, скалярные локальные переменные, история выражений и stateful TA-вызовы привязаны к своему контексту. Поддержаны позиционные/именованные аргументы и defaults в проверенном скалярном поднаборе.

История локального ряда фиксируется по выполненным барам. Если вызов на баре пропущен, искусственная запись в его историю не добавляется; несколько итераций одного вызова используют одну локальную историю. Глобальная обычная история сохраняет прежние правила. Новый policy локальных рядов явно сериализуется; формат существующих each-bar рядов не изменён.

Проверены shadowing без изменения одноимённой глобальной переменной, вложенные вызовы, доступ UDF к поддержанным глобальным скалярам и независимые SMA-аккумуляторы. Не объявляется универсальная поддержка generic/reference/UDT-параметров и захвата любых объектов.

### Порядок вычислений и диапазоны

Генератор теперь следует версионной политике, а не автоматически наследует поведение Python: eager ternary в v1–v3, lazy ternary с v4; eager логические выражения старых версий и lazy v6. В официальных release notes v4 отдельно проверено изменение ternary июля–августа 2019 года; исходная политика каталога сохранена, ошибочный одинаковый генератор исправлен.

`for ... to ... by ...` поддерживает включённые границы и направление по start/end. Верхняя граница фиксирована для старых версий и пересчитывается в v6. Шаг проверяется, диапазон получает явный лимит итераций. Это не полное решение суммарного бюджета произвольного callback и не приёмка всех выражений-циклов с break/continue.

### Транзакции и восстановление

Once использует обычный, не varip, слот: неокончательные realtime-вычисления могут откатываться. Тесты покрывают условие на закрытии бара, исключения/abort, отдельные varip-эффекты и JSON restore. Локальные истории и callsite-state восстанавливаются через имеющийся checkpoint, без второго формата брокера или интерпретатора.

Ограничение существенное: полная семантика once при исторических fill-recalculation ещё не принята. Четыре процессных ордерных теста внутри once дополнительно проверяют `strategy.position_size == 0`; они доказывают этот сценарий, а не безусловную гарантию ровно одного необратимого ордера при любых пересчётах. Замена completion-slot на varip не используется как обход, поскольку сломала бы realtime rollback.

## Найденная и устранённая регрессия интеграции

Первый совместный run `34066724346` выполнил 4 986 случаев на Python 3.13: 4 982 прошли, четыре существующие host-проверки упали. Все библиотечные наборы прошли. Скачанный XML сохранён отдельно, отказ не переименован в успешный результат.

Причина: host распознавал NA только как `ast.Constant(None)`, тогда как новый compiler корректно выдавал импорт канонического sentinel. Из-за этого `max_position_size(na)` не отклонялся статически, а явно неактивные trailing-параметры ошибочно конфликтовали с фиксированным stop.

Теперь отсутствующим считается только подтверждённый стабильный module import `pinelib.core.values.na` либо прежний literal None. Совпадение имени недостаточно. Переопределения, shadowing, относительный/чужой/wildcard import не угадываются как NA. Ноль, false, пустая строка и неизвестное выражение не превращаются в отсутствие аргумента. Динамические значения не вычисляются статическим анализатором. Добавлена 31 регрессия; четыре исходных assertion не ослаблены.

## Остаток и миграция

Полный этап 2 остаётся `in_progress`: полный version-exact каталог, reproducible Pine library imports, generic/reference/UDT-формы, сложные control-flow/loop-result формы, complete once fill-recalculation и независимые ожидаемые данные для всей заявленной поверхности builtins ещё не приняты. Скалярный UDF не означает автоматическую поддержку UDF capture в request.*. Этапы 3–8 и исходные OP-критерии не объявлены закрытыми.

Обновлять нужно согласованный набор библиотек вместе с host/worker и перекомпилировать артефакты. Старый checkpoint не считается совместимым только по строке версии: изменились runtime policy и ABI identities. Ускорение в этом блоке не измерялось; дополнительная изоляция состояния может иметь стоимость, которая относится к этапу 6.

Архив поставки содержит исходники восьми компонентов, патчи и доказательства. Это не автономный production-установщик. Патчи уже интегрированы в RC6 и не должны повторно накладываться поверх неё.
