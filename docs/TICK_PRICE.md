# Округление цены до шага инструмента

| Pine | Округление | Строка с точностью шага |
| --- | --- | --- |
| v1–v3 | Недоступно | Недоступно |
| v4 | `round_to_mintick(x)` | `tostring(x, format.mintick)` |
| v5–v6 | `math.round_to_mintick(number)` | `str.tostring(value, format.mintick)` |

Округление и форматирование используют десятичный шаг закреплённого
инструмента. Форматирование сохраняет завершающие нули и принимает
`format.mintick` напрямую или через неизменяемый псевдоним, сводимый
к константе при компиляции. Обычные строковые шаблоны сохраняют свой
профиль округления. [Заметки о выпуске v4](https://www.tradingview.com/pine-script-docs/v4/release-notes/#june-2021) ·
[Справочник v5](https://www.tradingview.com/pine-script-reference/v5/#const_format.mintick).

На точной половине выбирается больший соседний уровень. Для шага `0.25`
цены `100.125` и `-100.125` дают строки `100.25` и `-100.00`.
Аргумент `series` даёт результат `series`, остальные числовые
квалификаторы дают `simple`. Если значение `na`, числовая форма
возвращает `na`, строковая форма — `NaN`. Для определённой цены без
метаданных выдаётся `ENVIRONMENT_METADATA`.
[Справочник v5](https://www.tradingview.com/pine-script-reference/v5/#fun_math.round_to_mintick) ·
[ADR](adr/0067-tick-price.md).

В [примере с двумя инструментами](../examples/tick-price/two-tick-grids.pine)
расчёт внутри `request.security()` получает шаг запрошенного инструмента.
Основной контекст форматирует цену для оповещения по своему шагу.
[Пример стратегии](../examples/tick-price/limit-price.pine) выставляет
лимит по шагу того же снимка, который использует брокер.
Сравнение с исполнением TradingView остаётся отдельным этапом.
