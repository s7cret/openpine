# Приёмка порядка слоёв R6

[Исходник 4518a14c3674](https://github.com/s7cret/openpine/commit/4518a14c3674661d6cb2e94154bc16ad1135c980) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42653083248) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42653083616)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 932 теста. Conformance охватывает 4 417 сценариев, корпус — 180 программ.

- `explicit_plot_zorder` поддерживается в Pine v4–v6,
  `behind_chart` в v5–v6. Проверены значения по умолчанию,
  неподдерживаемые версии, совместимость со шкалами и числовым форматом,
  сохранённый IR и чтение прежних записей.
- Прошли 19 браузерных сценариев. Порядок проверен
  для заливок, рядов, уровней, маркеров, объектов и рыночных свечей.
  Сценарий проверяет перекрытие на реальном canvas, оба положения
  независимой шкалы, диапазоны истории и предварительный бар replay.
- Установленный wheel на обеих ОС подтвердил сохранение `visual_order`
  при паузе и возобновлении worker, в экспорте и в окне графика.
  Сохранены вычисленные значения и согласованность CLI и HTTP.
- На Windows прошло 1 932 теста, на Linux — 1 931.
  Linux пропустил проверку псевдонимов файлов Windows 8.3.
  Прошли четыре сценария восстановления.
- Сохранены наблюдения всех 4 406
  прежних сценариев. Добавлено 11 сценариев.
  Отчёты conformance совпадают между Windows и Linux.

Первый запуск Linux contexts получил повторяемый HTTP 503 COORDINATOR_BUSY при втором POST advance. Журнал зафиксировал занятый слот подготовки. Повтор использовал те же исходники, wheel и лимиты.
