## Реализовано

Нормализованный exact target компилятора сохраняет квалификатор каждого параметра,
а не только имя. Новый формат `ast2python.target_manifest.v2` содержит полную
неизменяемую карту `parameter_qualifiers`; она участвует в хеше. Старый reference
v1 сохранён, старый exact v1 необходимо перегенерировать.

При lowering и генерации кода фактический аргумент должен укладываться одновременно
в ограничение producer и target: `const < input < simple < series`. Это включает
именованные, позиционные и все вариативные аргументы, а также особый путь inputs.
Проверка действует при передаче source-free consumer bundle через существующую
семантическую приёмку producer. Статический анализ не выдумывает значения series.

Отдельный аудит проверяет включение всей области квалификаторов producer в target.
Он не смешан с проверкой конкретного вызова. Например, старый MACD с константными
длинами допустим, но более широкий исторический контракт не объявляется полностью
совместимым. Отсутствие метаданных означает UNVERIFIED, не произвольный series.

`build_builtin_surface` возвращает `qualifier_contract` каждой сигнатуры,
`qualifier_counts` и явную область доказательства. `build_capability_graph` добавляет
то же свидетельство к точным signature bindings. Старые structural status/reasons
и весь знаменатель сохранены: BOUND не означает совместимость квалификаторов или
численной семантики. Формат compile_meta указывает нормализованную схему и проверку
`producer_and_exact_target`.

Две записи PineLib для уже поддержанных fixed-per-run risk-команд согласованы с
producer/host: const → simple. Остальные поля и численные эталоны не менялись.
Метаданные и identity-only пересчёт старых snapshot guard выделены явно.

## Границы

Это контроль квалификаторов явных параметров, не универсальное доказательство
типов, defaults, возвращаемых значений, UDT/generic receiver или численного Pine.
Обычная типизация и receiver admission остаются у существующих владельцев.
Полный включающий аудит может показывать INCOMPATIBLE при допустимом частном
вызове с константой. Исторические профили не переписываются ради зелёного отчёта.

`resolution` связывается с `timeframe` только для уже существующей ABI-инъекции
request и версий v1–v4. Пропущенные defaults обрабатываются прежними механизмами
callee/input metadata. Нет общего alias, runtime fallback или понижения series.

## Проверка и использование

Новые регрессии находятся в `rc6_tests/test_rc6_qualifier_boundary.py` и sibling
наборах compiler/runtime. Они включены в обычный полный RC6 inventory и постоянный
lint. Новые protected-worker случаи остаются обязательными даже там, где локальная
среда не содержит Bubblewrap: исключать их для приёмки нельзя.

Нужно обновлять согласованный набор `RC6_LIFECYCLE_SOURCES.json`, затем
перекомпилировать артефакты. Этот локальный файл pin-ревизий не означает, что
соответствующие новые коммиты уже доступны на GitHub. Отчёты новых локальных тестов
отделены от прежнего успешного CI 20 259 случаев.

Официальная основа порядка квалификаторов:
https://www.tradingview.com/pine-script-docs/language/type-system/#qualifiers
