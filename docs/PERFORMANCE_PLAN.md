## Результаты приёмки 2026-10-26

Все семь пунктов закрыты на Python 3.14.8 для исходников
`70411254a78f2ee2820c90cba9f655905d11ce92`.
Исполняемая сборка совпадает с `26b02d0`; последующий коммит исправляет
только нормализацию ожидаемого пути в Windows-тесте. Сам индекс уже
использовал канонический путь. Модуль проверен повторно, CI выполнен заново.

- Локально прошли 855 тестов в 92 модулях. Те же 855 тестов прошли отдельно
  на Windows и Linux; [CI — 29/29](https://github.com/s7cret/openpine/actions/runs/40244240617).
  Один локальный шард продолжен после кратковременного `503 COORDINATOR_BUSY`
  в прежнем HTTP-тесте walk-forward. Исходный сбой сохранён в evidence;
  отдельный повтор, упавший модуль и все оставшиеся модули прошли без изменения
  кода или лимитов. Ограничение: CLI возвращает занятость координатора
  вызывающей стороне, автоматического повтора чтения в нём пока нет.
- В 25 корпусах проверены 2074 примера: 1381 исполнение и 693 ожидаемых
  отказа. Новая часть — 36 исполнений и 14 отказов. Все 2024 прежних
  наблюдения, включая 1345 успешных исполнений, и 77 файлов прежних
  immutable bundles совпадают с принятой стадией риска.
- Восемь общих переменных работают в v1–v6; 15 числовых методов отдельных
  сделок — в v5/v6. Для v1–v4 соответствующие вызовы отклоняются явно.
  Закрытая сделка — выделенная закрытая часть лота; прибыль учитывает
  распределённые комиссии входа и выхода. Это закреплённая локальная модель.
- 18 примеров (три семейства × v1–v6) проходят по 160 свечам. Независимая
  арифметика проверяет частичные закрытия, паузу после убытка и длительность
  позиции. Проверены 48 восстановлений в памяти, реальные worker для всех
  18 настроенных примеров, совместимость с risk, запечатанный журнал,
  незапечатанный хвост, backup и отклонение подменённых checkpoint.
- Один построенный wheel проверен вне checkout во всех 11 группах.
  CI проверяет те же группы на обеих ОС; RECORD и SHA всех членов
  локального wheel сверены с замороженной сборкой. История доступна
  постранично через HTTP и CLI с локальным каталогом либо loopback-сервером.
- В браузере проверены v1 partial, v4 cooldown и v6 duration. Из SQLite /
  CAS / Parquet независимо сверены 4640 выходных точек, 70 закрытых частей
  и комиссии 120 исполнений. Проверены отсутствие будущих закрытий,
  переходы к барам входа/выхода, восстановление исходника и Units=3;
  недоступный метод v4 отклоняется без создания нового задания.
- Эксперименты, поиск с holdout и два walk-forward окна сверены с
  независимым расчётом. Победитель `Units=2`; каждый отложенный участок
  в четыре цикла даёт net profit `68`. Закрытый и открытый результат
  представлены отдельно; прежняя метрика net_profit сохраняет смысл
  изменения капитала с учётом открытой позиции.
- Масштабирование: 1 000 000 основных + 250 000 старших свечей,
  250 000 закрытых частей и 5 000 000 выходных точек. Пик RSS worker —
  143.82 MiB при бюджете 512 MiB. Независимо проверена каждая закрытая
  часть и полная цепочка хешей. Итог: equity `500000`, комиссия `500000`,
  закрытый net profit `-500000`, позиция `0`. После принудительного падения
  worker, перезапуска координатора и восстановления backup результаты
  совпадают с непрерывным прогоном. Индекс SQLite восстанавливается
  потоково из журнала, а checkpoint не накапливает список закрытых сделок.
