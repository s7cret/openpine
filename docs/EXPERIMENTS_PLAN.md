# Параметризованные запуски и сравнение экспериментов R6

Этап после непрерывных сессий — пользоваться одной
компиляцией с разными параметрами и воспроизводимо сравнивать результаты на
одном снимке. Все модули остаются в текущем монорепозитории, Python 3.14.8.
Точное сопоставление с TradingView остаётся отдельным этапом.

До расширения нужен зелёный CI Windows/Linux. На `3447f22` Windows прошёл,
Linux остановился в подготовке точки падения coordinator. В аварийной приёмке
устранена зависимость от скорости timed tick: проецируются ровно 16 raw-записей
на сессию, сохраняются оба хвоста и выводится traceback дочернего процесса.
Локальная повторная проверка и GitHub CI `39742007538` прошли на Windows/Linux.
Реализация текущего этапа описана в [INPUTS.md](INPUTS.md).

## Последовательность

- [x] 1. **Контракты `input` для v1–v6.** Матрица реально доступных в каждой
  версии форм, типов, defaults, qualifier и ограничений по локальным артефактам.
  Первый срез: int/float/bool/string и выбор поддержанного OHLCV source, где
  это подтверждено или явно принято реконструкцией. Неизвестные формы отвергать.
- [x] 2. **Параметры в Typed IR.** Стабильные идентификаторы объявлений,
  метаданные для формы, типизированные значения по умолчанию и ограничения.
  Проверять overrides до запуска worker; изменение значения не требует новой
  компиляции. Схемы и профили версионировать, старые bundles не менять.
- [x] 3. **Неизменяемые настройки исполнения.** Разделить идентичности программы,
  настроек и запуска. Закрепить нормализованные значения/хеш настроек в RunPlan,
  checkpoint и результате. Продолжение с другими параметрами отклоняется;
  изменение настроек создаёт новый запуск. Старые wire-формы и их хеши сохранять
  отдельными читателями, несовместимое исполнение явно диагностировать.
- [x] 4. **Одна цепочка CLI → HTTP → worker → replay/live.** Параметры проходят
  общий прикладной контракт, входят в экспорт записи сессии и офлайн-повтор.
  Если параметр влияет на symbol/timeframe запроса, разрешить и закрепить
  зависимости контекстов до старта; динамические запросы на каждом баре в этот
  срез не включать. Существующий порядок получения и видимость не менять.
- [x] 5. **Форма параметров и пресеты в вебе.** Строить поля по метаданным IR,
  показывать defaults/ошибки, сохранять именованные пресеты с привязкой к
  совместимой схеме программы. Запуск сохраняет отдельный снимок значений;
  редактирование пресета не меняет уже созданные задания.
- [x] 6. **Ограниченная серия экспериментов.** Явный список вариантов или
  небольшая сетка, один IR и общие снимки данных. Состав группы сохраняется
  до исполнения; дочерние задания поступают через имеющийся scheduler в рамках
  общего бюджета. Статусы, отмена, восстановление и таблица результатов;
  проверенный завершённый вариант не запускать повторно при восстановлении.
- [x] 7. **Сквозная приёмка.** v1–v6: defaults/overrides, разные типы и ошибки,
  равенство CLI/HTTP, повторное использование IR, независимость вариантов,
  несовместимые параметры при resume, падение посреди серии, backup/restore,
  экспорт/офлайн-повтор, установленный wheel и общий gate Windows/Linux.

## Критерий готовности

Один `.pine` компилируется один раз; несколько вариантов его настроек
исполняются на одном закреплённом наборе данных. После рестарта продолжаются
оставшиеся задания; каждый результат объясняется своим IR, параметрами,
данными и профилем исполнения. Пользователь видит и сравнивает варианты в вебе
и может повторить любой из них офлайн.

Автоматический поиск параметров в `optimizer` строится после этого контракта.
Первый этап сравнения использует обычные задания и существующие метрики брокера.
