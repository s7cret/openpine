# Статистика стратегии и история сделок

Профиль `openpine.performance-broker.1` соединяет чтение торгового результата
с существующими ledger, комиссиями, OCA, trailing и необязательным RiskController.
Он выбирается при использовании новых переменных или функций. Прежние профили,
схемы и наблюдения сохраняются. Companion `pine-performance-20261026.1`
содержит отдельные контракты и свидетельства каждой версии.

## Единицы учёта

Заявка может дать несколько исполнений. Открытая сделка — оставшийся входной
лот; частичное закрытие уменьшает его количество. Закрытая сделка — одна
закрытая часть конкретного лота, уже записанная событием `trade` в ledger.
Один выход из нескольких лотов создаёт несколько закрытых сделок.
Количество полностью закрытых лотов и количество переходов позиции в ноль
остаются отдельными показателями `closed_lots` и `closed_positions`.

Порядок открытых сделок соответствует порядку оставшихся входов и меняется
после удаления лота. Индексы закрытых сделок последовательны от нуля,
сохраняются после перезапуска и не обрезаются до последних N записей.

## Переменные и функции

Все версии v1–v6 поддерживают следующие series-переменные:

| Переменная | Принятое значение |
| --- | --- |
| `strategy.netprofit` | Сумма net profit закрытых частей |
| `strategy.openprofit` | Нереализованный результат оставшихся лотов минус оставшаяся входная комиссия |
| `strategy.grossprofit` | Сумма положительных net profit закрытых частей |
| `strategy.grossloss` | Абсолютная сумма отрицательных net profit закрытых частей |
| `strategy.wintrades`, `strategy.losstrades` | Количество положительных и отрицательных закрытых частей |
| `strategy.opentrades`, `strategy.closedtrades` | Количество открытых лотов и закрытых частей |

Нулевой net profit относится к отдельному внутреннему счётчику `evens`.
В exact ledger выполняется равенство:

`equity = initial_capital + netprofit + openprofit`.

В v5/v6 доступны `strategy.opentrades.*(trade_num)` и
`strategy.closedtrades.*(trade_num)` с числовыми полями `size`, `entry_price`,
`profit`, `commission`, `entry_bar_index`, `entry_time`. У closedtrades также
есть `exit_price`, `exit_bar_index`, `exit_time`. `size` имеет знак направления;
у открытого лота это оставшееся количество. Время — Unix-миллисекунды,
индексы баров относятся к выполняемому входному диапазону.

Аргумент — series int. `na`, отрицательный или ещё не существующий индекс
возвращает `na`; float/string не приводятся к индексу. На одном баре допускается
до 4096 чтений. Числовые переменные и результаты функций допускают обычную
историю `[]`, условия и UDF. В v1–v4 функции чтения не подставляются задним
числом; выдаётся диагностика отсутствующей сигнатуры.

Официальные [описание торговых данных](https://www.tradingview.com/pine-script-docs/concepts/strategies/#individual-trade-information)
и [справочник](https://www.tradingview.com/pine-script-reference/v6/) подтверждают
семейства API, типы и индексацию. Формулировки о profit и пример с вычитанием
commission не устраняют неоднозначность всех исторических соглашений.
В нашей модели **profit — после распределённых комиссий**, commission при этом
показывается отдельно как уже учтённая сумма. Для открытой части сохраняется
только нераспределённый остаток входной комиссии. Это явное решение по модели;
точная внешняя эквивалентность требует отдельной проверки.

## Видимость и восстановление

Данные доступны после исполнений текущего бара и перед расчётом основного
скрипта. Заявки, созданные этим расчётом, не становятся исполнениями раньше
предусмотренного брокером момента. История не содержит будущих закрытий.
Запрошенные indicator-контексты не получают состояние основного брокера.
Прогрев сохраняет прежний запрет торговли до начала окна оценки.

SQLite-индекс истории — временный производный кеш на диске с LRU на 128 строк
и ограниченным SQLite page cache. Источник истины — неизменяемый журнал
Parquet и его закреплённый CSV-хвост. На восстановлении индекс строится потоком
из этого префикса. Количество, цепочка SHA-256, суммы и счётчики сверяются
с checkpoint до изменения состояния брокера. Файл индекса не нужно включать
в backup: он восстанавливается из уже сохраняемого журнала.
У worker индекс принадлежит каталогу конкретной попытки: после нормального
закрытия удаляется, после принудительного падения учитывается обычной политикой
удержания и очистки попыток. Случайные глобальные каталоги worker не создаёт.

Broker-state, simulation и chart-window нового профиля имеют версии `.10`.
Trade-journal и trade-prefix `.2` добавляют диапазоны закрытых индексов каждого
блока. Старые форматы других профилей не меняются. Runtime и simulation
не импортируют SQLite: execution получает фабрику адаптера через порт,
приложение и ResultSink подключают `packages.storage.trade_index.TradeIndex`.
При прямом использовании `Session` адаптер передаётся явно:

```python
session = Session(profile_id=HISTORICAL_PROFILE_ID,
                  trade_history_factory=TradeIndex)
```

## Приложение и отчёты

`GET /api/jobs/ID/trades?start=0&limit=100` возвращает страницу закрытых частей,
их постоянные индексы, `total` и `next`; предел — 200 строк на запрос.
Данные берутся только из подходящих блоков журнала.

Та же страница через CLI: `openpine trades --id JOB_ID --state-dir DIRECTORY`.
При работающем сервере используется `--server http://127.0.0.1:PORT`; это
сохраняет одного владельца каталога. Доступны `--start` и `--limit`.

UI показывает показатели выбранного бара, закрытые к этому бару части и
кнопки перехода к барам входа/выхода. Смена бара или задания отменяет применение
устаревшего ответа. Обычное окно графика сохраняет бюджет событий 2 MiB.

В отчётах `net_profit` по-прежнему означает изменение капитала, включая
открытую позицию. Новый профиль отдельно показывает `closed_net_profit` и
`open_net_profit`; названия не меняют значение прежних метрик и выбор победителя.
Счётчики и суммы отчёта проверяются по тому же журналу. Дневной риск сохраняет
своё закреплённое определение результата дня: realized минус все комиссии.

Примеры `examples/performance`: partial/cooldown/duration × v1–v6,
по 160 баров, параметр Units 1…3. В ранних версиях duration использует явный
счётчик входа; в v5/v6 читает индекс входа открытой сделки. Статистика максимума
сделки, строковые методы, margin/FX и исполнение на незакрытых свечах остаются
за пределами этого среза. [Приёмка](PERFORMANCE_PLAN.md).
