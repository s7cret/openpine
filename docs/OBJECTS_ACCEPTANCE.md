Реализован ограниченный профиль UDT для v5/v6: scalar-поля, new/copy,
алиасы, номинальные UDF и методы, история ссылок, field-level varip и общее
хранилище с массивами. Старые программы сохраняют свои IR records и схемы;
UDT используют закрытый `ObjectProgramIR` `.14`.

Проверки после каждого бара и события сравнивают непрерывное исполнение с
восстановлением, включая все четыре типа полей, missing values, aliases,
обычный rollback, varip-поля, создание ссылки на незакрытом баре и замену
обычного alias. Проверены подмена IR/defaults/порядка аргументов, общая квота
массивов и объектов, отказ restore без утечки общего storage account и
невозможность продвинуть обычное поле через intrabar checkpoint.

В v1–v4 UDT отвергаются, scalar routing-программы продолжают исполняться.
Reference-поля, вложенные UDT, object-arrays/tuples, object loop results,
object equality и object-dependent requests остаются за границей профиля.
Прямая история поля в v6 недопустима, ошибочное историческое поведение v5
намеренно не эмулируется. Constructor baseline для новой intrabar varip-ссылки
явно закреплён как интерпретация OpenPine. Совпадение с TradingView не заявляется.

Первый Windows-suite `lots` завершился `JOB_TIMEOUT`: v3 conditional после
восстановления обработал 354 из 400 баров за лимит 120 секунд. Ошибка возникла
до сравнения его итогового результата с oracle. Отдельный локальный контроль всех 18 lot-сценариев
прошёл; затем тот же installed suite успешно повторён на Windows. Исходник,
общий wheel, worker timeout и остальные лимиты оставались прежними. Первичная
ошибка и успешный повтор сохранены в машинном свидетельстве; первый прогон
не выдаётся за успешный.
