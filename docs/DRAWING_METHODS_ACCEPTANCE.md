# Приёмка методов графических объектов R6

[Исходник fe1f15131996](https://github.com/s7cret/openpine/commit/fe1f151319960edcfd6ccb4dedbccb8ed6bb9bce) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42837161271) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42837161380)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 971 тестов. Conformance охватывает 4 510 сценариев, корпус — 180 программ.

- Для Pine v5–v6 проверены вызовы через объекты `table`, `line`, `label`,
  `box`, `linefill` и `polyline`. Для v1–v4 подтверждены отказы.
- Парные программы выбрали одинаковые контракты Typed IR и дали одинаковые
  результаты. Проверены именованные аргументы, defaults, цепочки геттеров,
  выбор по типу объекта и однократное вычисление объекта перед аргументами.
- Установленный wheel на обеих ОС подтвердил одинаковые снимки и журналы
  линий, меток, боксов и полилиний после возобновления истории и в replay.
  Прошли 19 браузерных регрессионных сценариев.
- На Windows прошло 1 971 тестов, на Linux — 1 970.
  На Linux пропущена проверка псевдонимов файлов Windows 8.3.
  Прошли четыре сценария восстановления.
- Сохранены наблюдения всех 4 495
  прежних сценариев. Добавлено 15 сценариев.
  Отчёты conformance совпадают между Windows и Linux.

В первой попытке установленный воркер Windows в сценарии stop-limit Pine v1 возобновился с бара 2 и обработал 327 из 400 баров за лимит 120 секунд. На последней отметке продолжал передавать heartbeat. Сценарий повторён на том же SHA, wheel и лимите.
