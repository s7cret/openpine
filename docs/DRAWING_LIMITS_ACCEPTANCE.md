# Приёмка лимитов графических объектов R6

[Исходник 4165c2c40a09](https://github.com/s7cret/openpine/commit/4165c2c40a0909f8f6cd02ce4e55fd3aaf186610) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42684056450) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42684056885)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 938 тестов. Conformance охватывает 4 425 сценариев, корпус — 180 программ.

- Проверены `max_lines_count`, `max_labels_count` и `max_boxes_count`
  в Pine v4–v6 и `max_polylines_count` в v5–v6. Проверены отказы в ранних
  версиях, типы, константные выражения, лимит по умолчанию 50 и верхние
  пределы 500 и 100, включая восстановление снимков с такими объёмами.
- Установленный wheel на обеих ОС подтвердил вытеснение по ID после
  возобновления worker, удаление зависимой заливки и сохранение журнала
  подтверждённых баров при replay.
- Прошли 19 браузерных сценариев. Сценарий линий и заливок
  проверяет отрисовку оставшихся линий и исчезновение заливки в истории
  и preview.
- На Windows прошло 1 938 тестов, на Linux — 1 937.
  Linux пропустил проверку псевдонимов файлов Windows 8.3.
  Прошли четыре сценария восстановления.
- Сохранены наблюдения всех 4 417
  прежних сценариев. Добавлено 8 сценариев.
  Отчёты conformance совпадают между Windows и Linux.

OpenPine использует точное вытеснение по порядку создания.
Параметры декларации принимаются у стратегий, исполнение рисуемых объектов
ограничено индикаторами. Сверка модели с TradingView проводится отдельно.
