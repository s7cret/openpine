# Переменные, выражения, условия и var

Все пять возможностей работают в профилях v1–v6. Критерий этого этапа — выполнение согласованной модели по найденным артефактам. Результаты проверяются собственными независимыми ожиданиями; точное сравнение с TradingView относится к отдельному этапу.

```pine
//@version=6
indicator("Variables and state")
length = 3
src = close
average = ta.ema(src, length)
difference = src - average
var float total = 0
if src > 20
    total := total + src
else
    total := total - src
plot(difference)
plot(total)
```

Запуск из корня на Python 3.14.8:

```sh
python -m apps.openpine run --source conformance/language/v6-five-points.pine --bars conformance/language/fixed.json
python -m apps.openpine compile --source conformance/language/v6-five-points.pine --profile historical
python -m tools.release_gate
```

Для каждой версии есть собственный `vN-five-points.pine`. Имена функций выбираются по версии: `study/abs/ema` в v1–v4, `indicator/math.abs/ta.ema` в v5/v6.

## Переменные и присваивание

`name = expression` объявляет переменную, `int/float/bool/string name = expression` задаёт её базовый тип явно. `name := expression` изменяет ближайшую ранее объявленную переменную, сохраняя её базовый тип. Int допускает преобразование в float; float в int, bool в число и несовместимые строковые присваивания не выполняются автоматически.

Имена разрешаются до исполнения. Повторное объявление в той же области — ошибка; локальное затенение внешнего имени допустимо. Инициализатор нового локального имени может читать одноимённую внешнюю переменную. Читать имя до объявления или после выхода из его блока нельзя. Ветка проверяется на ошибки даже тогда, когда её условие постоянно false.

Обычный инициализатор выполняется при каждом достигнутом исполнении декларации на баре. Поэтому `x = 0; x := x + 1` даёт 1 на каждом баре (на отдельных строках, без точки с запятой). Переменная `length = 3`, которую не меняют, сохраняет const qualifier и подходит для длины EMA. Если где-либо есть `length := ...`, Binder заранее отмечает этого владельца как series и отвергает его в параметре, требующем simple или слабее. Это не зависит от порядка первого чтения и последующей записи.

`var` инициализирует значение только при первом достигнутом выполнении своей декларации. `var count = 0` с последующим `count := count + 1` выдаёт 1,2,3,4. Внутри блока первый вход может случиться на третьем баре; инициализация произойдёт тогда. При следующих входах инициализатор, включая его вызовы функций, пропускается. Новый запуск через тот же Session начинает с нового состояния.

## Выражения и блоки

Поддержаны числовые `+ - * /`, строковый `+`, скобки, унарные `+ - not`, сравнения `== != < <= > >=`, логические `and/or`, условное выражение `condition ? a : b`. Умножение/деление имеют приоритет над сложением/вычитанием; арифметика левоассоциативна, вложенный ternary — правоассоциативен. Числовые ветки ternary приводятся к общему int/float типу.

`if`, `else if`, `else` поддерживают вложенные блоки с четырьмя пробелами на уровень. Пустые строки и комментарии не создают блоков. Перенос внутри круглых скобок разрешён; табы и другие размеры отступа дают диагностику. Блок должен содержать хотя бы одну инструкцию. Возвращающие формы if и функций добавлены последующим [профилем функций](FUNCTIONS.md).

`if/else` и `?:` выполняют только выбранную ветку. Невыполненный вызов EMA не обновляет своё состояние. Однажды вычисленная переменная хранит значение текущего исполнения: два `plot(average)` читают его, а не повторяют вызов EMA из инициализатора. `plot` и `study/indicator` остаются глобальными вызовами.

| Политика модели | v1–v5 | v6 |
|---|---|---|
| `int / int` | Int, усечение к нулю | Float |
| Деление с float | Float | Float |
| `and/or` | Оба операнда | Сокращённое вычисление |
| Числовое условие | 0 и na → false, другое → true | Требуется bool |
| `if`, `?:` | Только выбранная ветка | Только выбранная ветка |
| `var` | Первое достигнутое исполнение | Первое достигнутое исполнение |

`float missing = na` и `int missing = na` создают типизированный числовой пропуск. `missing = na` без типа отвергается. Арифметика с na и деление на ноль возвращают числовой na; сравнение с na даёт false в нашей модели. В JSON это `null`, не NaN/Infinity. Функции `na/nz` и legacy bool na добавлены последующим [профилем рядов](SERIES.md).

## Путь исполнения и границы

Parser строит AST инструкций и выражений. Один Binder сначала разрешает лексических владельцев и находит записи, затем проверяет типы и qualifiers. Lowering записывает в `openpine.typed-ir.5` таблицу переменных, Load/Store IDs, Binary/Conditional/If и политику версии. Runtime допускает весь IR до первого эффекта: проверяет типы, области видимости, владельцев присваиваний, глобальные вызовы и выбранную политику. Повторного разрешения исходных имён нет.

Execution задаёт порядок баров; Runtime сбрасывает обычные ячейки и сохраняет var только внутри текущего запуска. Metadata indicator обрабатывается один раз. Профиль `pine-language-20261021.1` и его связи с core/version-review/grammar закреплены lock. Semantic identity программы включает ядро и политику языка. Предыдущие immutable bundle сохранены побайтово.

Лимиты текущей реализации: 64 KiB исходника, 4096 токенов, высота выражения 48, вложенность блоков 24, конечные float, signed 64-bit int и строки до 65536 символов. Не входят: циклы, массивы и `varip`. [Составной профиль](COMPOSITE.md) добавляет плоские результаты и распаковку; [replay](REALTIME.md) и [checkpoint/resume](CHECKPOINTS.md) описаны отдельно.

Корпус `conformance/language` содержит 84 случая для всех шести версий. Unittest дополнительно проверяют области видимости, reset/persistence, пропуск инициализаторов и вызовов, статические ошибки до Runtime и отказ подменённому IR. Ожидания не получают из результата OpenPine.

Операции `%`, история `[]`, OHLCV и новые функции описаны в [SERIES.md](SERIES.md). Для bool na в v1–v5 действуют дополнительные правила этого профиля.

Пользовательские функции, локальные параметры и if как выражение описаны в [FUNCTIONS.md](FUNCTIONS.md).
