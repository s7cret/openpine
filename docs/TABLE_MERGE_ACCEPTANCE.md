# Приёмка объединения ячеек таблиц R6

[Исходник 531b87953158](https://github.com/s7cret/openpine/commit/531b87953158e774dce1c4391224a0833c4eb9cc) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42812016676) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42812016689)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 966 тестов. Conformance охватывает 4 495 сценариев, корпус — 180 программ.

- Проверено `table.merge_cells()` в Pine v5–v6 до и после заполнения.
  Для v1–v4 подтверждены отказы. Неверный порядок координат, выход за
  границы и пересечения отклоняются до изменения состояния.
- Подтверждены сохранение диапазонов после очистки, совместимость со
  старыми записями, перенос, применение оформления и замена ID таблицы.
- Установленный wheel на обеих ОС подтвердил возобновление исторического
  задания и независимость диапазонов открытого бара в replay.
  Прошли 19 браузерных сценариев, включая размеры
  объединения, сетку по периметру, подсказку и `force_overlay`.
- На Windows прошло 1 966 тестов, на Linux — 1 965.
  На Linux пропущена проверка псевдонимов файлов Windows 8.3.
  Прошли четыре сценария восстановления.
- Сохранены наблюдения всех 4 480
  прежних сценариев. Добавлено 15 сценариев.
  Отчёты conformance совпадают между Windows и Linux.

В OpenPine очистка верхней левой ячейки скрывает объединение
до повторного заполнения. Диапазон сохраняется. Пиксельная сверка и
частичная очистка в TradingView относятся к отдельному этапу.
