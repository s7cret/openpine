# Паспорт программы

Паспорт `openpine.program-passport.1` объясняет уже связанный IR Pine v1–v6: операции, профили, inputs, контексты, историю и условия исполнения. Он использует существующие компилятор, подготовку и правила допуска движка. Отдельного binder или разрешения на исполнение здесь нет.

## CLI

```console
python -X utf8 -m apps.openpine passport --source examples/pipeline/v6.pine --source-name v6.pine --output passport.json
python -X utf8 -m apps.openpine passport --artifact program.json --primary-context primary.json --inputs inputs.json --options modes.json
```

`--source` и `--artifact` взаимоисключающие. Источник ограничен 64 КиБ. `--source-name` задаёт стабильное имя диагностики при чтении исходника. Код завершения 2 означает отказ компиляции или подготовки паспорта; отдельные режимы могут быть отклонены внутри успешно составленного отчёта. Выходной файл не может совпадать со входом.

`primary.json` содержит существующий `MarketContext`: `context_id`, `symbol`, `timeframe`, `source`. Эти метаданные позволяют разрешить цели запросов, но не удостоверяют наличие снимка. Созданные `passport.request.N` — имена планируемых контекстов, не идентичности наборов свечей.

В `modes.json` разрешены `broker_settings`, `environments`, `lower_tf`, `cycle_settings`, `magnifier`, `lower_context`, `execution_mode`, `event_profile`, `broker_profile`, `calculation_profile`; значения проверяют действующие контракты соответствующего режима. Для каждого режима отчёт явно перечисляет использованные и неиспользованные параметры. `selection` описывает конкретный выбранный режим; [проверка закреплённых входов и квитанция запуска](BOUND_LAUNCHES.md) продолжают эту цепочку.

## Режимы и границы проверки

| Режим | Что проверяется без исполнения свечей |
| --- | --- |
| history | Брокер, фазы стратегии, допустимость интервалов запросов |
| replay | Конструктор действующего ReplayEngine с обычным брокером |
| observed | Тот же движок с брокером наблюдаемых цен |
| intrabar | Тот же движок с профилем расчёта внутри свечи |
| cycle | Тот же движок с профилем фаз стратегии |
| magnifier | Закреплённая конфигурация и метаданные младшего контекста |

`needs_configuration` требует метаданных/настроек. `rejected_configuration` сохраняет исходную диагностику и координаты, если они есть. `configuration_admitted` подтверждает только проверенную конфигурацию. Magnifier возвращает `requires_bound_plan`: соответствие OHLCV, покрытие и видимость запрошенных данных проверяет настоящий план с данными.

Паспорт не загружает свечи, не создаёт задания, не резервирует ресурсы и не подтверждает покрытие данных. `unvalidated`, `data_checked`, `resources_reserved` и `readiness` делают эти ограничения машинно читаемыми. Требуемые поля инструмента перечисляются отдельно, без заявления об их наличии.

## HTTP и веб

Существующий `POST /api/launches/requirements` принимает опциональные `explain: true` и `mode_options`. В ответ добавляются `passport` и `passport_json`; без opt-in прежний контракт сохраняется. Обычный CLI `requirements` также остаётся прежним.

`GET /api/launches/<id>/passport` объясняет сохранённую подготовку, не продвигая её состояние. `saved_preparation` указывает совместимость сохранённого плана и ранее записанную проверку данных. `data_checked_now: false` означает, что текущие файлы, диск и ресурсы заново не проверялись.

Карточка веба использует тот же отчёт, защищает выбор от позднего ответа и сбрасывает паспорт при изменении программы/inputs. Скачивание сохраняет серверный `passport_json` без повторной сериализации JavaScript, включая различие JSON `2` и `2.0`.

## Инвентарь и свидетельства

Канонический `profile_inventory` строится из загруженного Snapshot и закреплённых профилей; это описательная проекция с происхождением и SHA-256. `tools.capabilities.report` остаётся совместимой ссылкой на общий отчёт приложения, включая прежние поля. Обход признаков IR общий с conformance, без новой семантики.

`admission_profiles` содержит идентичности допуска IR и фактически нужные overlay-профили; `selected_execution_profiles` — контракты выбранных режимов. Это не утверждение об использовании всех возможностей каталога. Неустановленная доступность по версиям остаётся неизвестной.

`recorded_corpora` показывает пересечение операций с сохранёнными прошедшими сценариями текущей реализации. Проверяются SHA исходника, ожиданий, корпуса и вычислительной реализации. Такое свидетельство не означает исполнения загруженной программы целиком: в описательном паспорте `whole_program_execution_verified` остаётся `false`. Для сохранённого успешного задания отдельная [квитанция исполнения](BOUND_LAUNCHES.md) может подтвердить именно его программу/план/результат. Импортированные правила, допуск компилятора, записанные наблюдения и реконструированные правила представлены отдельно. Эквивалентность TradingView и процент поддержки Pine не заявляются.

Приёмка включает все прежние 56 программ корпуса, v1–v6, CLI/HTTP и установленный wheel, браузерные гонки и продолжение состояния предыдущей сборки при неизменной вычислительной идентичности.
