# Заявки на наблюдаемом потоке

`openpine.observed-broker.1` — отдельная модель симуляции для Pine v1–v6.
Она подключает существующий lot/economics/risk/performance-брокер к logical
replay и received/live, сохраняя прежние модели истории и market-only replay.
Правила закреплены в `spec/observed-broker-profile.json`; ранние сигнатуры
сохраняют прежние оговорки реконструкции. Сравнение с TradingView отдельно.

## Что считается доступной ценой

Каждый основной `open/update/close` предоставляет одну цену — свой `close`.
Это последняя цена полученного кадра. Даже первое позднее cumulative-сообщение
не превращается в давно прошедшее исполнение по его полю `open`.
Накопленные high/low служат свечой и входом Pine на закрытии, но не создают
вымышленный путь и не повторяют уже прошедшие касания уровней.

На известной цене выполняются уже существующие заявки: сначала наблюдение
риска, затем входы и market-закрытия по порядку заявок, затем защита. Исполнение
использует существующие правила количества, лотов, fees/slippage, FIFO/ANY,
OCA и точных остатков. Stop-limit может активироваться и исполниться в одном
событии только если обе проверки удовлетворены его одной известной ценой.
Защита, привязанная к pending-входу, связывается с фактическим лотом и может
сработать на той же известной цене. Trailing использует только наблюдаемые
экстремумы; пропущенные тики и порядок старых high/low не восстанавливаются.

Pine и новые команды рассчитываются только на подтверждённом `close` основного
контекста. `calc_on_every_tick`, `calc_on_order_fills`, биржевые заявки и
частичные исполнения по доступному объёму этот профиль не добавляет.
Прогрев и восстановленный одиночный close дают одну close-цену, без
реконструкции внутрисвечного пути. Поэтому результат не обязан совпадать с
историческим OHLC-брокером: способы наблюдения цены различаются явно.

## Два независимых состояния

Pine count/история/`var`/ядра обновляются на закрытии бара. Broker state,
исполнения, комиссии, OCA, risk и trailing фиксируются после каждого принятого
основного события. Их не откатывает следующий пересчёт незакрытой свечи.
Дополнительные контексты сохраняют прежнюю причинность и не создают отдельную
цену исполнения основного инструмента.

`bar_index`, времена сделок и верхний `time` журнала остаются координатами
свечи. У немаркерных событий `value.observation` отдельно сохраняет глобальный
sequence, revision, context, kind и фактический `event_time` доступности.
Это позволяет различать бар сделки и момент получения ценового кадра.
Исполнение может быть сохранено, пока его свеча ещё не закрыта.

Сводка содержит `observed_execution`: число основных наблюдений, последнее
наблюдение, `broker_committed`, `bar_confirmed`. Веб показывает эти состояния
отдельно, активные заявки/защиту, количества и последние исполнения с ценой,
комиссией и временем получения. Полный журнал по-прежнему читается страницами.

## Восстановление

Используются прежние inbox, общий бюджет worker и короткая атомарная публикация
replay. Одним переключением ссылок публикуются input cursor, runtime, текущий
брокер и префикс журнала/выходов. Объекты записываются раньше каталога; падение
до commit оставляет только неподтверждённый файловый хвост для GC.

Новый `openpine.output-prefix.3` разделяет число подтверждённых Pine-баров и
границу журнала, который может включать активный бар. Число наблюдений задаёт
предел записей плотного потока; прежний предел событий на один исторический
бар сохраняется для прежних префиксов. Поддерживается checkpoint ещё до первого
закрытия. Брокер проверяет бухгалтерское равенство, лоты, таргеты, OCA, trailing,
историю сделок и соответствие активному наблюдению. Дисковый индекс сделок
восстанавливается из журнала, включая исполнения внутри открытой свечи.

Новые профили не переписывают прежние bundles и не переопределяют старые
checkpoints. Совместимость реализации проверяется обычной execution identity;
неподходящая реализация требует новой компиляции/новой сессии.

## Запуск и примеры

В `examples/observed-broker` — 36 собственных программ: limit, stop-limit,
partial, trailing, OCA и risk во всех шести версиях. Там же находятся шесть
лент, явные ожидаемые цены/количества/комиссии и общая конфигурация.

```sh
openpine replay create --source examples/observed-broker/v6-trailing.pine --contexts examples/observed-broker/contexts.json --broker-profile observed
openpine replay append --id ID --events examples/observed-broker/trailing.ndjson
openpine replay advance --id ID --max-events 3 --checkpoint-every 1
openpine replay advance --id ID
openpine replay ledger --id ID
```

HTTP creation replay/live принимает необязательное
`"broker_profile":"openpine.observed-broker.1"`. Отсутствие поля сохраняет
прежнее поведение, включая отказ в защите для market-only replay. В live-вебе
новую модель выбирает флажок «Симулировать заявки по поступающим ценам».
Настройка закрепляется при создании сессии. Export recording сохраняет её;
офлайн replay записи использует ту же модель без сетевого провайдера.

Профиль и исходники примеров проверяет `python -m tools.observed_broker_spec --check`.
Нагрузочный прогон: `python -m tools.observed_broker_soak --events 100000 --directory NEW_DIRECTORY`.
