# Строки и преобразования интервалов

`openpine.scalar-targets.1` добавляет закрытый набор чистых встроенных функций
к целям запросов. Те же ядра работают в обычном runtime. Реестр, типы, effects,
qualifiers и стоимость находятся в `packages/contracts/scalar_functions.py`;
runtime не содержит второй реализации. Исходные записи Wiki и текстовые
свидетельства закреплены в `spec/scalar-targets-evidence.json`, решения — в
`spec/scalar-targets-profile.json`. Выпуски Wiki и `spec/lock.json` сохранены.

| API | v1–v3 | v4 | v5–v6 |
|---|---|---|---|
| `tostring` | число, формат | scalar, числовой формат | отсутствует |
| `str.tostring` | — | — | scalar, числовой формат |
| `str.length`, `str.replace_all` | — | есть в сохранённом каталоге | есть |
| `str.substring`, `str.contains` | — | — | есть |
| `timeframe.in_seconds`, `timeframe.from_seconds` | — | — | есть |

```pine
//@version=6
indicator("Computed interval")
minutes=input.int(60)
interval(value) => str.tostring(value, "#")
plot(request.security(syminfo.tickerid, interval(minutes), close))
```

`tostring`/`str.tostring` без формата возвращает строку без изменений, bool
как `true`/`false` (с v4), числовое NA как `NaN`. Ранние версии принимают
только число. Явный формат принимает числовой scalar: один `#` или `0`,
затем необязательная точка и до десяти десятичных мест (`0`, затем `#`).
`0` сохраняет завершающие нули, `#` убирает необязательные. Значение по
умолчанию `#.##########`. Округление принято как decimal HALF_UP, включая
отрицательные половины; отрицательный ноль удаляется. Коллекции, enums,
группировка разрядов и `format.mintick/percent/volume` не реализованы.

Длина и индексы считаются по Unicode code points. Сочетание буквы и combining
mark занимает два места; emoji вне BMP занимает одно. Нормализации текста нет.
Substring: `0 <= begin <= end <= length`, конец исключается, равные индексы
дают пустую строку; отсутствие конца означает длину источника. Ошибочные
границы отклоняются. Поиск чувствителен к регистру. Replace_all заменяет
неперекрывающиеся совпадения; пустая цель вставляет замену на всех границах,
включая начало и конец. Эти детали Unicode/пустых строк и HALF_UP — явно
принятые правила там, где текст артефактов недостаточен.

Для const аргументов length/substring/contains сохраняется const overload;
input повышается до simple. Остальные выбранные функции имеют simple floor,
series аргумент даёт series. Ранние qualifiers — ограниченное восстановление.
NA остальных функций распространяется; недоступный bool v6 даёт false.

Преобразования интервалов принимают секунды `1S/5S/10S/15S/30S/45S`, минуты
`1..1440`, дни `1D..365D`, недели `1W..52W`, месяцы `1M..12M`; `D/W/M`
также принимаются. Месяц в этом scalar API — документированные 2628003 секунд.
Реальные месячные свечи по-прежнему используют календарные границы.

`from_seconds` принимает int, округляет вверх до представимой длительности;
при точном равенстве выбирается более крупная единица, при округлении —
более мелкая. Примеры: `2 → 5S`, `61 → 2`, `604799 → 7D`, `604800 → 1W`.
Значения ≤1 дают `1S`, значения >366 суток ограничены `12M`. Артефакт
недостаточен для полной исторической сертификации всех промежуточных случаев.
`in_seconds()` связывает существующую ссылку основного `timeframe.period`;
без метаданных основного рынка требования возвращают `needs_primary` до I/O.
Явный пустой аргумент `in_seconds("")` не входит в выбранный subset.

Данные и запросы пока поддерживают прежние минутные интервалы и одиночные
`D/W/M`. Новый resolver переводит только `1D/1W/1M` в эти канонические имена;
другие результаты конвертации, например `5S` или `7D`, отклоняются до загрузки
свечей. Наличие scalar-конвертера не расширяет возможности провайдера.

Профиль имеет собственные overload IDs `.scalar.function.primary.prepared`.
Все аргументы, ветки и тела UDF проверяются до I/O. Допускаются только APIs
закрытого реестра: произвольные numeric/TA kernels, state, история, циклы,
коллекции и вложенные запросы по-прежнему исключены из целей. Старые профили
не начинают принимать новые вызовы. Строковые результаты запросов не добавлены.

Общий бюджет вложенных вызовов: 262144 единицы работы на вычисление цели
или один runtime bar; 4096 code points на строку. Предполагаемая длина
replace_all и конкатенации проверяется до выделения результата. Цель сохраняет
128 IR-узлов, глубину 16 и 12 вложенных UDF. Классификатор исходного DAG
мемоизирован до разворачивания IR. Граф закрепляет kernels, UDF/call sites,
сырые inputs, основной контекст и program hash; worker/replay/live/research
используют этот resolver. Стоимость заново не выдаётся каждой вложенной функции.

Независимые примеры находятся в `conformance/scalar-targets`, сквозной прогон —
`tools.scalar_targets_flow`, миллион событий с восстановлением —
`tools.scalar_targets_soak`. Точное сравнение с TradingView остаётся отдельным
этапом; здесь проверяется объявленная модель по сохранённым артефактам.
