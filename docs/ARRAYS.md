# Массивы и ссылки

`pine-arrays-20261024.1` закрепляет ограниченный профиль `openpine.arrays.vN.1`
для каждой версии. Arrays доступны в v4–v6; v1–v3 получают `ARRAY_VERSION`.
Generic-конструкторы, generic-аннотации и `for…in` допускаются с v5.
Основа — сохранённые справочники wiki и официальные страницы
[arrays](https://www.tradingview.com/pine-script-docs/language/arrays/),
[loops](https://www.tradingview.com/pine-script-docs/language/loops/) и
[migration v6](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-6/).
Точное выполнение на TradingView не проверено; применение современных деталей
к старым срезам и поведение resizing в v5 явно отмечены как реконструкции.

```pine
//@version=6
indicator("Array queue")
var array<float> window = array.new<float>()
array.push(window, close)
if array.size(window) > 3
    array.shift(window)
plot(array.avg(window))
```

Для close 10, 20, 30, 40 результат равен 10, 15, 20, 30.

Сохранить IR и выполнить пример через worker:

```sh
python -m apps.openpine compile --source examples/arrays/queue-mean-v6.pine --profile historical --output .runtime/array-ir.json
python -m apps.openpine job --artifact .runtime/array-ir.json --bars examples/arrays/bars.json --contexts examples/arrays/contexts.json --state-dir .runtime/array-demo
```

## Типы и операции

Элементы — int, float, bool или string. Тип массива инвариантен: массив int
нельзя присвоить переменной массива float. Отдельный int-элемент можно явно
привести компилятором к float при записи в массив float.
В контракте это закрытые базовые типы `array.int`, `array.float`, `array.bool`,
`array.string` с qualifier series; вложенные массивы не допускаются.

В v4 используйте `float[] values = array.new_float(0)` и соответствующие
`new_int/new_bool/new_string`. Эти конструкторы доступны и в v5/v6;
дополнительно работают `array<float>` и `array.new<float>()`.
У new_* в v4 размер обязателен, в v5/v6 он по умолчанию равен нулю.
Начальное значение по умолчанию — na, для bool в v6 — false.

`array.from` принимает 1…32 позиционных scalar-значения. Смешанные int/float
приводятся к float; из одних bare na тип вывести нельзя. Основные операции:

| Операции | Результат |
| --- | --- |
| size, get, set | Размер, чтение и изменение элемента |
| push, pop | Добавление и извлечение с конца |
| unshift, shift | Добавление и извлечение с начала |
| clear, copy | Очистка объекта и создание независимого объекта |
| sum, avg, min, max | Числовые агрегаты; na-элементы пропускаются |

Пустой или полностью неопределённый числовой массив даёт na при агрегации.
Sum/min/max сохраняют тип элемента, avg возвращает float. Min/max поддерживают
первый ранг; перегрузки с nth исключены. Выход int за signed 64-bit или
непредставимый float даёт диагностику вместо нечислового JSON.

Get/set используют определённый int-индекс. В v4/v5 допустимы 0…size−1;
в v6 также −size…−1. Индекс вне диапазона, неопределённый индекс, отрицательный
размер, извлечение из пустого массива и операция над na-ссылкой дают отдельные
runtime-ошибки с позицией исходника. `na(reference)` проверяет отсутствие
массива; na-строку из getter также можно проверить через `na`.

## Владение, функции и история

`b = a` сохраняет ссылку: изменение через b видно через a. `array.copy(a)`
создаёт другой объект. Очистка a очищает объект для всех его алиасов.
Чтение глобального массива и изменение его элементов внутри UDF разрешены.
Переприсваивание самого глобального имени или параметра внутри UDF по-прежнему
запрещено. Функция может принимать и возвращать массив; simple-параметр не
принимает series-ссылку. Tuple с массивами и коллекции в requests исключены.

Обычный инициализатор создаёт новый объект при каждом достижении; var сохраняет
один объект до переприсваивания. История `a[1]` возвращает объект, который был
записан в переменную на прошлом баре. Это не снимок содержимого: если var a
продолжает указывать на тот же объект, a[1] видит изменения этого объекта.
У создаваемого заново на каждом баре a предыдущий объект остаётся отдельным.
Отсутствующая история даёт na-ссылку.

## For…in

```pine
values = array.from(1, 2, 3)
total = 0
for [index, value] in values
    total := total + index * value
plot(total)
```

Результат — 8. Одно имя получает элемент; пара получает индекс и элемент.
`_` отбрасывает соответствующее значение. Имена локальны и неизменяемы в этом
профиле. Запись в имя элемента не заменяет array.set.
Коллекция вычисляется один раз; перед каждой итерацией проверяется её текущий
размер и читается текущий элемент по индексу. Append может продлить обход,
clear завершает его, shift может сдвинуть следующий элемент мимо текущего
индекса. Переприсваивание исходной переменной не меняет объект обхода.
Пустой массив не выполняет тело. Break/continue, возвращаемое значение,
локальный var и повторные TA-вызовы используют общий профиль циклов.
Строковые и ссылочные результаты самого цикла пока исключены.

## Хранение, восстановление и лимиты

Новые программы используют typed IR `.9`, runtime-state `.5`. В IR присутствуют
ArrayIR и ForInIR; runtime проверяет операции, типы, порядок аргументов,
конструкторские defaults, области и цели управления до первого эффекта.
Потребитель не выполняет Python eval и не загружает выбранные JSON классы.

Каждый запуск и контекст владеет своим heap. В checkpoint сохраняются объекты
и типизированные ссылки; алиасы после восстановления продолжают указывать на
один объект. Размеры, типы, ID, корни, история и бюджеты проверяются до
присоединения heap к evaluation. Неизвестные, висячие и недостижимые объекты
отвергаются. Буферы не разделяются с переданным JSON.

Preview получает отдельные таблицы ссылок и копирует буфер при первой записи.
Изменения preview не попадают в подтверждённое состояние. Удаление недоступных
объектов происходит в конце успешного бара по persistent/history-корням.
Временные объекты одного бара также занимают бюджет до этой границы.
Для истории ссылок с постоянным offset сохраняется только нужная глубина;
динамический offset сохраняет прежний максимальный диапазон истории.

| Лимит одного evaluation | Значение |
| --- | --- |
| Элементов в одном массиве | 100 000 |
| Живых объектов, включая временные текущего бара | 100 000 |
| Элементов во всех массивах | 1 000 000 |
| Суммарных UTF-8 байтов string-элементов | 16 МиБ |
| Общая работа на бар | 1 000 000 операций |
| Общие итерации на бар | 100 000 |

Копирование, сдвиги, агрегаты, выделение и освобождение буферов учитываются
по количеству затронутых элементов и проверяют отмену. Лимиты истории и worker
сохраняются отдельно. Preview может временно держать подтверждённый буфер и
его частную копию; общий предел процесса обеспечивает worker policy.
Незаконченный бар не публикует результаты и не сохраняется для продолжения.

Methods, вложенные коллекции, матрицы, map, графические объекты, varip и
dynamic/lower-TF requests остаются вне профиля. Все прежние bundles сохранены.

Проверки: [план приёмки](ARRAYS_PLAN.md), 91 независимый conformance-сценарий,
`test_arrays.py`, `test_arrays_state.py`, `test_arrays_pipeline.py`,
[шесть стратегий](../examples/arrays/). Инструменты `tools.installed_array_smoke`
и `tools.array_soak` проверяют установленный пакет, задания и восстановление.

При совместном использовании с [окружением](ENVIRONMENT.md) программа
использует typed IR `.10`, а checkpoint `.6`; alias/copy, heap и rollback
сохраняют проверки профиля массивов.
