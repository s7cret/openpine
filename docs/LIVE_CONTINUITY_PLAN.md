# Длительная воспроизводимая сессия R6

Все изменения выполняются последовательно в `r6-rebuild`, Python 3.14.8.
Поддержанные конструкции Pine v1–v6 сохраняют общую цепочку. Точное сравнение
с TradingView остаётся отдельной задачей.

- [x] 1. Переносимый пакет сессии: source/IR, настройки, прогрев, raw journal,
  нормализованный опубликованный префикс и независимые хеши результатов.
  Офлайн-воспроизведение в новом хранилище с разными размерами пакетов.
- [x] 2. Один UTC-календарь для провайдера, контекстного исполнения и replay;
  D/W/M, понедельник, реальная длина месяца, календарные checkpoint.
- [x] 3. Несколько live-контекстов: общие подписки, устойчивый порядок получения,
  прогрев всех контекстов, совместное продолжение и запросы без будущих данных.
- [x] 4. Измерения задержки/CPU/RSS и стоимости запуска worker; оптимизация
  только по измерению, с сохранением бюджетов, изоляции и durable checkpoint.
- [x] 5. Сегментация журналов, продолжение между сегментами, явная retention,
  preview освобождения места и защита живых/экспортируемых данных.
- [ ] 6. Веб: сохранённые диапазоны, пропуски, размеры, потоки, отставание,
  ошибки/причины остановки и обслуживание с предварительным просмотром.
- [ ] 7. Длительная сквозная приёмка нескольких сессий: обрывы, рестарты,
  backup/restore, ротация и офлайн-воспроизведение; wheel и общий gate.

Сетевая приёмка использует только публичные рыночные данные. Продолжительность
модельного времени и реального ожидания фиксируется отдельно. Нагрузочная
проверка хранения не заменяет проверку исполнения Pine на той же нагрузке.
