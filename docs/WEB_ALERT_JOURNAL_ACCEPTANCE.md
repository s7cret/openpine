# Приёмка журнала оповещений в веб-интерфейсе R6

[Исходник b074426d3c0e](https://github.com/s7cret/openpine/commit/b074426d3c0e93e01132acf672777f59e8520ac5) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/43296526087) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/43296525808)

SHA b074426d3c0e. CI 57/57, Python 3.14.8. В реестре каждой ОС 2 007 тестов. В conformance проверен 4 591 сценарий, в корпусе 180 программ.

- При создании одиночного и многоконтекстного наблюдения профиль входит в паспорт replay. Прогрев вычисляет историю. После остановки и возобновления опубликованная запись сохранилась, следующее закрытие добавило одну запись.
- В Chrome 157.0.8103.51 на локальном стенде с записанными данными прошли загрузку Pine, выбор подстановок, открытие оповещений и переход к исполнению записанного replay. Браузерные сценарии проверили пагинацию и запоздалые ответы при смене сессии.
- На общем wheel Windows и Linux HTTP-поиск по `fill_id` вернул точную строку торгового журнала для оповещений об исполнении. Проверки подстановок и восстановления журнала прошли повторно.
- На Windows прошли 2 007 тестов, на Linux — 2 006. На Linux пропущена проверка коротких путей Windows 8.3. Подтверждены четыре отчёта восстановления.
- Все отчёты conformance совпали с предыдущей приёмкой и между Windows и Linux.

Сверка с исполнением TradingView проводится отдельно.
