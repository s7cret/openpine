# Цвета и параметры plot

Профиль `openpine.colors.1` задаёт ограниченную модель цвета и вывода.
Спецификация воспроизводится `tools.colors_spec`; ручные ожидания —
`tools.colors_fixtures`. Старые bundles и профили остаются неизменяемыми.
Решение о представлении и совместимости: [ADR 0006](adr/0006-color-values-and-plot-presentation.md).

| Возможность | v1 | v2/v3 | v4 | v5/v6 |
| --- | --- | --- | --- | --- |
| Имена констант | `red`, `blue`, … | `red`, `blue`, … | `color.red`, … | `color.red`, … |
| HEX `#RRGGBB`, `#RRGGBBAA` | Реконструкция | Реконструкция | Да | Да |
| Тип `color`, переменные, `na`, сравнение, UDF, tuple | Реконструкция | Реконструкция | Да | Да |
| Прозрачность `color(c, transp)` | Нет | v2: реконструкция; v3: справочник | Заменена `color.new` | Заменена `color.new` |
| Приведение `color(c)` / `color(na)` | Нет | Нет | Да | Да |
| `color.new/rgb/r/g/b/t/from_gradient` | Нет | Нет | Да | Да |
| Массивы цветов | Нет | Нет | Да | Да |
| UDT, методы, map/matrix с цветом | Нет | Нет | Нет | Да |

Для v1–v3 архивные имена не доказывают точные RGB каждого исторического
рендерера. Здесь явно выбрана палитра v5 как реконструкция. В v4/v5 `red` имеет
значение `#FF5252`, `teal` — `#00897B`, `yellow` — `#FFEB3B`; в v6 —
`#F23645`, `#089981`, `#FDD835`. Изменение трёх констант описано
[в официальной миграции v6](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-6/#color-changes).

## Значение и операции

Цвет — отдельный скалярный тип. Каноническое значение имеет вид
`#RRGGBBAA` с прописными HEX-цифрами; `AA=FF` означает непрозрачность,
`AA=00` — полную прозрачность. В Pine строка с таким текстом остаётся строкой:
неявных преобразований цвета в строку/число и обратно нет.
Допустимы равенство/неравенство, `na`, присваивания и ветвления. Арифметика,
упорядочивание и использование цвета как условия отклоняются.

`color.rgb` принимает конечные RGB-компоненты 0–255 и прозрачность 0–100;
у прозрачности default 0. `color.new` заменяет alpha, сохраняя RGB. Дробные
компоненты и alpha округляются к ближайшему целому, половина вверх.
Alpha вычисляется как `255 * (100 - transp) / 100`, чтобы целые значения
прозрачности на половине байта не терялись при вычитании из единицы.
Выход за диапазон — `COLOR_RANGE`; скрытого ограничения значений нет.
`color.r/g/b` возвращают float-компонент 0–255, `color.t` — прозрачность,
вычисленную из сохранённого 8-битного alpha. Поэтому после квантования она
может отличаться от исходного дробного аргумента. Квалификатор результата —
сильнейший аргумент; `from_gradient` всегда возвращает series color.

Градиент линейно интерполирует RGBA между возрастающими конечными границами,
используя точное отношение числовых входов до квантования каналов. Смешанные
int/float интервалы выше 2**53 не схлопываются из-за промежуточного приведения.
За границами возвращает крайний цвет. Missing числовой аргумент или оба missing
цвета дают missing. Один missing цвет заменяется прозрачным цветом с RGB другого
конца. Равные/обратные границы отклоняются. Это явная модель OpenPine;
точное поведение платформы на этих границах отдельно не измерялось.

Цвет проходит через существующие правила UDF/перегрузок, `if`/`switch`, tuple,
циклов, истории, `var`/`varip`, алиасов коллекций и UDT-полей. Доступность самих
конструкций сохраняется: for с v2, while/for-in и UDT/map/matrix с v5, массивы
с v4. Пустой цветовой результат — `na`. История написанного вызова зависит от
его исполнения на предыдущем баре; условный вызов не получает пропущенные
наблюдения автоматически. Прямые вложенные коллекции и целый tuple в истории
остаются вне профиля.

## Выход и график

Поддержаны первые пять параметров `plot(series, title, color, linewidth, style)`.
Цвет может меняться по барам; `na` или alpha 0 скрывает точку/сегмент.
Ширина и стиль требуют const/input. Ширина ограничена 0–64 до v6 и 1–64 в v6;
веб-график отображает старую ширину 0 как 1 пиксель.
Для v1/v2 шестой позиционный параметр — `transp`; в v3–v5 он допускается
только по имени, чтобы не менять значения пропущенных аргументов Pine.
В v6 `transp` отклоняется. Этот параметр принимает input/const int 0–100 и
заменяет alpha только у исходно непрозрачного цвета.

Стили: line, linebr, histogram, columns, circles, cross, area; stepline с v3.
До v4 используются старые имена, с v4 — `plot.style_*`.
Дополнительные параметры plot, plot-handle в переменной и графические объекты
`line`/`label`/`box`/`table` в этот этап не входят. `input.color`, `nz(color)`,
цветовые requests и строковое форматирование цветов также не заявлены.

В памяти выход содержит обычный числовой `values`, параллельный `colors`,
`linewidth` и `style`. Потоковый результат хранит постоянные параметры в
метаданных выхода, а `{value,color}` — внутри существующего JSON-столбца
Parquet. Дескриптор имеет версию `openpine.plot-presentation.1`.
Обычные читатели получают числовой ряд; читатель диапазона графика
запрашивает представление явно. Цвета не загружаются целиком для большого ряда.
Старые числовые выходы и файлы сохраняют прежний формат.

Новые программы получают typed-ir.21 и runtime-state.13. Heap остаётся общим,
цветовые значения в полях/коллекциях проверяются по их объявленному типу.
Checkpoint восстанавливает параметры и цветовой префикс; realtime preview
изолирован и не публикует незавершённые точки в подтверждённый ряд.

```pine
//@version=6
indicator("Dynamic color")
c = close > close[1] ? color.green : color.red
plot(close, "Close", c, 2, plot.style_line)
```
