# Этап 2: воспроизводимые Pine-imports — локальный кандидат

База OpenPine: `85fa14ee7b95fa5c18314ba82c07379e8e0e2f80`. Это продолжение
этапа 2, не его окончательная приёмка. Исходные 36 задач и восемь этапов сохранены.
Предыдущий совместный CI в stage2-progress относится только к опубликованному
скалярному блоку; он не приписывается новым изменениям.

## Связанный путь исполнения

Подготовлены три согласованных слоя:

1. Pine2AST захватывает оригинальные исходники и проверяет их по заранее
   закреплённому lock; связывает точные публикации, транзитивные зависимости,
   экспортируемые функции и частные зависимости по AST и лексическим областям.
2. Ast2Python проверяет воспроизводимость связывания и соответствие consumer
   bundle; идентичность сборки включает все достижимые библиотеки и карту связи.
3. NativeRC6CompilerAdapter принимает `library_store`, сохраняет provenance
   в compile_meta и направляет связанный код по обычному compiler/runtime пути.
   Worker получает уже проверенный Python-артефакт, а не библиотечные файлы.

Нет второго интерпретатора, брокера или загрузчика Python-модулей из Pine.
Не добавляются сеть/файловые разрешения sandbox. В источниках с настроенным store,
но без настоящего import, прежняя идентичность артефакта сохраняется. Строка
`"import ..."` в комментарии или строковом литерале не запускает связывание.

## Как пользоваться

```python
from pathlib import Path
from pine2ast.libraries import LibraryStore
from openpine.compile.native_rc6 import NativeRC6CompilerAdapter

# Этот хеш должен быть сохранён ранее при осознанном создании/обновлении lock.
store = LibraryStore.from_directory(
    Path("project/libraries.lock.json"), expected_hash=reviewed_lock_hash,
)
result = NativeRC6CompilerAdapter().compile(
    root_pine,
    source_name="main.pine",
    library_store=store,
    producer_commits={"pine2ast": exact_frontend_sha, "ast2python": exact_compiler_sha},
)
if not result.success:
    raise RuntimeError(result.errors)
```

Создание нового lock — явная операция `LibraryStore.create({ref: text})`.
Admission полученных файлов должен использовать ранее закреплённый hash, не
бесконтрольно создавать новый lock поверх любой замены. Lock не подтверждает
авторство или права на библиотеку: доверие к первоначальным данным обеспечивает
пользователь. Зависимости не скачиваются автоматически и не заменяются latest.

Для подготовки виртуального Pine без запуска worker есть команда:

```sh
python -m pine2ast.libraries --source main.pine --lock libraries.lock.json \
  --expected-lock-hash sha256:REVIEWED_HASH --output new-linked-output
```

Она сохраняет связанный код и linkage.json в новой папке. Существующие результаты
и исходные файлы не перезаписываются. Автоматическая настройка реестра через
основной OpenPine CLI/gateway/UI ещё не подключена; сейчас это API плюс команда
frontend для явно подготовленного offline-проекта.

## Семантика и идентичность

Поддержанный профиль: один язык по всему графу (5→5 или 6→6), typed scalar function
exports, private helpers и literal/arithmetic constant globals. Работают несколько
публикационных версий одной библиотеки, aliases и общие транзитивные зависимости.
Публикационная версия из owner/Name/2 не означает Pine v2. Строки, комментарии,
локальные shadowing-имена и независимые места вызова не переписываются глобально.
Демонстрационный глобальный plot библиотеки в потребителе не исполняется.

Вызванные функции работают через существующие UDF/state/history/TA механизмы.
В проверках счётчики count(1) и count(10) идут независимо, вызов внутри цикла
сохраняет одно место состояния, inputs меняют импортированную SMA, а JSON checkpoint
продолжается той же последовательностью событий. Изменение транзитивной библиотеки
меняет artifact/build identity и запрещает восстановление чужого checkpoint.
Посторонняя библиотека, которую никто не импортирует, не меняет результат сборки.

Схема generated_artifact.v3 уже имела зарезервированное поле
external_library_dependency_hashes; теперь оно содержит точные refs и @linkage.
Непустая карта входит в существующую формулу build identity. Старая пустая карта
сохраняет прежнее поведение. Перехеширования только внешнего артефакта недостаточно
для сокрытия изменённой зависимости. Полная cache hit/miss-служба не реализуется
под видом этой связи идентичностей.

Исходный hash корневого артефакта относится к связанному виртуальному Pine.
Оригинальный корень, тексты библиотек и проекции хранятся в linkage receipt;
`original_location(offset)` возвращает исходный файл/строку/колонку. Её можно
компоновать с Python source-map. Автоматическая перепроекция всех диагностик UI,
trade source_span и сообщений компилятора остаётся работой пользовательского слоя.

При связывании найдена и исправлена ошибка владельца AST/layout: виртуальный
DEDENT захватывал следующий export/identifier. Теперь это нулевая граница перед
следующим токеном; многострочные объявления не захватывают соседа. Изменение может
изменить AST/source-map hashes: старые артефакты следует перекомпилировать.

## Безопасные границы и незавершённая приёмка

Файлы читаются один раз через POSIX no-follow/dir_fd. Не допускаются symlinks,
traversal, pipes/devices и чужие source hashes. Ограничены глубина, число модулей
и размер исходников. Верификация linkage заново строит проекцию, поэтому простая
подмена её полей с новым внешним checksum недостаточна.

Смешанные Pine-версии, exported UDT/enum/method/reference/generic/const, одноимённые
перегрузки, request-выражения внутри библиотек и произвольные глобальные константные
выражения не приняты. Это ограничения OpenPine, не запреты TradingView. Синтаксис
imports не добавляется в v1–v4. Full OP-31 и полный этап 2 остаются открытыми.

Официальное описание для сверки правил (не execution oracle):
https://www.tradingview.com/pine-script-docs/concepts/libraries/

Для новой реализации добавлены и оставлены обязательными четыре защищённых worker
теста. Локальная среда без Bubblewrap не заменяет их успешный CI. Frozen inventory
обновляется явно, без удаления прежних case IDs или ослабления Stage 1 gates.
Полная процессная матрица 3.11/3.13, внешний TradingView-oracle и финальная поставка
не объявляются принятыми по локальным регрессиям. GitHub-запись в этом проходе
недоступна; новые pins указывают на сохранённые локальные коммиты, не опубликованные
ветки. Их нельзя использовать для сетевой установки до совместной публикации.
