# Защитные выходы исторических стратегий

Профили `openpine.exits.v1.1` … `v6.1` закреплены выпуском
`pine-exits-20261023.1`. Он содержит ссылки и SHA записей локальных каталогов.
Старые bundles не изменены. Для v1/v2 неполные сигнатуры реконструированы;
это явно отражено в контракте и compatibility notes. В v1–v5 доступен `when`,
в v6 условие выражается обычным `if`.

```pine
//@version=6
strategy("Protection", default_qty_type=strategy.fixed, default_qty_value=1,
         initial_capital=1000)
if bar_index == 0
    strategy.entry("L", strategy.long)
    strategy.exit("X", from_entry="L", stop=95, limit=110)
plot(strategy.equity, title="Equity")
```

Запуск: `openpine job --source examples/protection/v6.pine
--bars examples/protection/bars.json --state-dir .runtime/protection`.
В том же каталоге есть примеры всех шести версий с изменяемыми input-уровнями.

## Границы первого профиля

`openpine.protective-broker.1`: одна позиция, одна защитная группа, полный выход.
Уровни stop/limit абсолютные, положительные, вычисляемые на подтверждённом close.
Если задан tick_size, каждый уровень должен быть ему кратен. Одного уровня
достаточно; оба `na` при достигнутом вызове дают ошибку.

`id` и `from_entry` — непустые литералы до 128 символов. `from_entry` обязателен
в нашем срезе. Позиционны только эти два аргумента; цены задаются по имени.
Частичные выходы, qty/qty_percent, profit/loss, trailing и несколько OCA-групп
пока отклоняются. Для long требуется stop < limit, для short — stop > limit.
Каждый достигнутый вызов, включая cancel, входит в общий лимит 16 команд на бар.

Наличие exit/cancel выбирает новый брокер при построении сохранённого RunPlan.
Стратегии только с market entry/close сохраняют прежнюю политику и формат
результата. Runtime создаёт типизированные intents; чистый broker не зависит
от файлов, SQL, веба или worker. Используются прежние очередь и ресурсные лимиты.

## Порядок исполнения

1. Команды close предыдущего бара применяются со следующего имеющегося бара.
   Сначала на open исполняются ожидающие market-заявки в порядке команд.
2. Защита ожидающего входа активируется по его точному fill ID. После market
   исполнений проверяются OHLC текущего бара, затем выполняется программа
   на подтверждённом close и публикуется mark/checkpoint.
3. Пересечение уровня уже на open исполняется по open. Иначе касание исполняется
   по уровню. Если обе цены коснулись уровней и порядок неизвестен, выбирается
   stop, событие получает `ambiguous=true`. Известное пересечение на open
   имеет приоритет перед последующим касанием другого уровня.
4. Market и stop получают закреплённый adverse slippage; limit — без slippage,
   с улучшением цены при благоприятном гэпе. Каждый fill платит комиссию.
   Учёт денег, сделок и Decimal-округление используют прежние правила.

Это детерминированная историческая OHLC-модель. Она не восстанавливает путь
тиков и не подтверждает соответствие TradingView. Observed replay/live с такими
программами явно отклоняется `PROTECTION_CONFIRMED_ONLY`: исполнение по
обновлениям незакрытой свечи требует отдельного профиля.

## Жизненный цикл и восстановление

Exit связывается с существующей позицией или уже созданным ожидающим входом.
Отсутствующий вход даёт `ignored/no_matching_entry`; будущий одноимённый вход
не наследует такую заявку. Повтор того же exit ID заменяет уровни со следующего
бара; другой активный exit ID требует предварительной отмены.

`strategy.cancel("X")` удаляет совпавшую защиту или ожидающую market-заявку.
`strategy.cancel_all()` отменяет обе категории. Они не закрывают позицию и
не отменяют исполнения, уже произошедшие внутри текущего бара. Удаление или
замена входа, закрытие/разворот позиции отменяют связанную защиту. После fill
одной ноги вторая отменяется с причиной `bracket_peer_filled`.

`openpine.broker-state.2` сохраняет уровни, точный target, call site, счётчики,
идентичность программы и политику. Восстановление проверяет их вместе с учётной
идентичностью капитала. Смена реализации или спецификации требует явной
перекомпиляции; автоматической миграции старого checkpoint нет. Состояние .1
сохраняется для прежнего market-профиля.

## Результаты и исследования

Новый `openpine.simulation.2` содержит явную execution_model, статистику,
ожидающую защиту и прежний Parquet-журнал. `chart-window.2` читает события
только заданного диапазона и предыдущий mark для начальных уровней. Ответ
ограничен 5000 событиями, переполнение помечается `truncated`; полный ledger
читается страницами. Большие журналы не копируются в SQLite или весь веб-ответ.

График показывает stop, take-profit и исполнения; таблица объясняет изменения,
отмены и неоднозначные касания. Experiments, search, holdout и walk-forward
используют те же plans/jobs и прежние критерии выбора. Исследовательский отчёт
сохраняет защитную политику, параметры, результаты и показатели сделок.

Проверки: независимая арифметика long/short/гэпов/fees/slippage; корпус exit
v1–v6; CLI/HTTP; замороженный IR; pause/resume; реальные завершения worker и
координатора; backup/restore; подбор на отдельных временных окнах; wheel вне
checkout. Полная приёмка закрепляется в [плане этапа](PROTECTION_PLAN.md).
