# Сквозной путь R6

Цель: на Python 3.14.8 из чистой установки загрузить Pine v1–v6, выбрать
подтверждённые исторические OHLCV, сохранить компиляцию, исполнить её в отдельном
процессе и увидеть график/диагностику в браузере. Используется существующий срез
языка и закреплённая спецификация. Все модули остаются в одном репозитории.

## Этапы и приёмка

1. **Сценарий.** Собственные программы `examples/pipeline/v1.pine` … `v6.pine`,
   общие OHLCV и вручную рассчитанные ожидания. Все шесть профилей проходят один
   путь; ошибки исходника имеют позиции. Начальная проверка: `test_pipeline`.
2. **Прикладной API.** Общие запросы, ответы, диагностики и состояния задания;
   CLI использует тот же сервис, что worker и HTTP. Существующие CLI сохранены.
3. **Данные.** Контракт провайдера, файловый адаптер, полуоткрытый диапазон UTC,
   неизменяемые снимки и provenance. Нет молчаливого заполнения/ресемплинга баров.
4. **Артефакт.** Версионированный JSON без исполняемого Python/pickle. Строгая
   загрузка, проверка целостности, спецификации/реализации и всего IR до эффектов.
   Один артефакт исполняется повторно на разных данных без компилятора.
5. **Worker.** Один локальный процесс на задание, bounded concurrency, прогресс,
   отмена, таймаут, восстановление статуса после падения хозяина и сохранённые
   результаты. Отдельные запуски не разделяют вычислительное состояние.
6. **Реальные котировки.** Один исторический HTTP-провайдер после изучения старого
   кода и первичного API. Закрытые бары, пагинация, явные ограничения, снимок для
   повторного офлайн-исполнения. Сетевые проверки отделены от офлайн gate.
7. **Веб.** Локальный интерфейс: Pine-файл/редактор, данные, запуск, отмена,
   прогресс, диагностики с позицией, цена/plot, экспорт результата. HTTP вызывает
   общий сервис. Интерфейс проверяется в настоящем браузере.
8. **Приёмка.** CLI и HTTP дают одинаковые вычислительные значения и идентичности
   на одном артефакте/снимке. Проверяются неверный Pine, плохие данные,
   несовместимый артефакт, timeout/cancel/crash, повторный запуск и чистая
   установка вне исходного дерева. Общий gate и CI на Windows/Linux проходят.

Каждый этап: реализация, содержательные проверки, документация, отдельный
коммит и push в `r6-rebuild`. Отметки локальной wiki относятся только к реально
завершённому объёму. Итоговая инструкция запуска и доказательства приёмки
будут в `PIPELINE.md`.

## Границы

Один исторический контекст на запуск; вычисления выполняет существующий Typed
IR runtime. Realtime, стратегии, оптимизация, кластер, распределённая очередь и
новые конструкции Pine относятся к следующим целям. Изоляция subprocess
отделяет сбои и состояние; она сама по себе не является ОС-песочницей.
