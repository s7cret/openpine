# Расширенные операции массивов v4–v6

Профиль `openpine.array-operations.1` добавляет восемь операций к существующим
[массивам](ARRAYS.md), [UDT-массивам](OBJECT_ARRAYS.md) и [enum](ENUMS.md).
Правила и исходные записи справочников закреплены в
`spec/array-operations-profile.json`. Неизменяемый первоначальный bundle массивов
и прежний methods profile сохраняются побайтно.

| Операция | Поведение |
| --- | --- |
| `insert(id, index, value)` | Вставить до указанной позиции; `index=size` дописывает в конец |
| `remove(id, index)` | Удалить и вернуть выбранный элемент |
| `reverse(id)` | Развернуть содержимое того же массива |
| `fill(id, value, index_from=0, index_to=na)` | Заполнить диапазон `[from,to)`; `na` означает текущий конец |
| `includes(id, value)` | Вернуть bool наличия значения |
| `indexof(id, value)` | Первый индекс совпадения, иначе `-1` |
| `lastindexof(id, value)` | Последний индекс совпадения, иначе `-1` |
| `concat(id1, id2)` | Дописать второй массив в первый и вернуть ID первого |

Namespace-вызовы доступны в v4–v6, методы — в v5/v6. V1–v3 явно отвергают
массивы. Примитивные элементы следуют существующему профилю, enum и плоские
UDT допускаются в v5/v6. Конкатенация требует одинакового типа элементов:
`array<int>` не преобразуется в `array<float>`, разные nominal-типы не смешиваются.

В v6 `insert/remove` допускают отрицательные индексы с нормализацией по текущему
размеру; v4/v5 их отвергают. Вставка в пустой массив допускает индекс 0.
Диапазон fill всегда неотрицателен: `0 <= from <= to <= size`. Равные границы,
включая полный fill пустого массива, ничего не меняют. Omitted и явный `na`
для `index_to` используют размер после вычисления всех явных аргументов.
Receiver и аргументы вычисляются ровно один раз в порядке исходника,
включая named arguments и побочные эффекты UDF.

Сравнение поиска использует значения примитивов, номинальный enum и идентичность
UDT-ссылки. Две разные записи с одинаковыми полями не равны. Missing совпадает
с missing; bool missing остаётся запрещён в v6. Сопоставление missing и пустой
fill — явно закреплённые интерпретации OpenPine для неуточнённых руководствами
деталей. Поведение generic-примитивов v4 наследует прежнюю историческую
реконструкцию. Внешняя эквивалентность TradingView не заявляется.

`concat(a,a)` удваивает исходное содержимое один раз. Второй массив сохраняет
содержимое, если это другой контейнер. Элементы UDT остаются общими ссылками:
изменение поля видно через все содержащие эту запись массивы. Удаление слота
освобождает ровно одно ребро, а контейнер удерживает свои слоты независимо от
числа aliases к нему. Обычный GC освобождает недостижимые записи.

Изменения используют общий heap, ArrayIR, Binder и runtime. Сначала проверяются
границы, работа, логические квоты и память временного буфера; затем одним
действием заменяются слоты. Ошибка до публикации сохраняет старое содержимое,
COW-владение и счётчики ссылок. Отмена проверяется при учёте работы и перед
публикацией буфера. Временная память освобождается и при ошибке.

Сохраняются прежние типизированные IR records и checkpoint schemas. История
хранит ID массива, COW изолирует previews, varip переносит структуру и только
помеченные поля UDT. Лимиты не повышаются: 100 тысяч элементов в массиве,
миллион логических ячеек и прежний общий бюджет задания. Отдельно проверяются
durable restore self-concat 50 тысяч ссылок в 100 тысяч, незакрытый бар и
отсутствие дальнейшего checkpoint IO после восстановления.

`conformance/array-operations` содержит 127 ручных случаев: 60 исполнений и
67 отказов. В owned corpus добавлены routing v1–v6 и стратегии v5/v6:
v1–v3 используют scalar-аналог, v4 — примитивные массивы, v5/v6 — UDT и enum.
Все прежние 104 записи сохраняются полностью. Оракулы фиксируют значения,
индексы, размер, порядок сделок и комиссии независимо от runtime.

`array.slice`, сортировки, вложенные коллекции и новые типы request-выражений
остаются вне этого профиля. Slice требует общей памяти представлений и будет
отдельным этапом. Источники: [v4 arrays](https://www.tradingview.com/pine-script-docs/v4/essential/arrays/),
[v5 arrays](https://www.tradingview.com/pine-script-docs/v5/language/arrays/),
[v6 arrays](https://www.tradingview.com/pine-script-docs/language/arrays/).
