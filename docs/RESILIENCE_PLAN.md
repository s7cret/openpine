# Приёмка устойчивого запуска и CI

- [x] Единый контракт занятости, причины и Retry-After.
- [x] Ограниченные безопасные повторы CLI и сохранение диагностик.
- [x] Атомарные ключи создания experiment/search/walk-forward, lookup и backup.
- [x] Лёгкий прогресс, управление и резерв соединений под тяжёлой нагрузкой.
- [x] Ожидание и восстановление отправки в вебе.
- [x] Один wheel, отдельная спецификация, модели шардов каждой ОС и проверка полного покрытия.
- [x] Полная регрессия, независимая приёмка и публикация.

База — `b4535e8`: 855 тестов в 92 модулях, 2074 conformance-примера.
Приёмка относится к исходникам `b972e3f` на Python 3.14.8.
[Машинные доказательства](evidence/resilience-20261026.json) закрепляют SHA
исходников, квитанций и wheel. Изменения относятся к HTTP, клиентам,
каталогу, интерфейсу и CI; execution identity сохранена.

## Полнота проверки

Локальные три шарда прошли 889 уникальных тестов в 95 модулях. Все прежние
855 test IDs сохранены; добавлены 34 проверки. Каждый шард связан с одной
полной спецификацией и теми же исходниками. Установочные группы core и
research проверены отдельно вне checkout из одного локального wheel.

Все 2074 прежних conformance-наблюдения совпали с базой: 1381 успешное
исполнение и 693 ожидаемых отказа. Не изменён ни один из 79 файлов bundles.
Новых правил Pine этот этап не добавляет.

[GitHub Actions](https://github.com/s7cret/openpine/actions/runs/40285638227): 33/33 jobs прошли. На каждой из Windows/Linux
проверены 889 test IDs в 95 модулях, вся спецификация и все 11 установочных
групп. Окончательный acceptance повторно сверил состав модулей, отсутствие
дублей/пропусков, все helpers и общий SHA wheel. Исходные ZIP-артефакты
скачаны после CI; RECORD, файлы wheel и квитанции дополнительно проверены
локально. Все отчёты conformance обеих ОС сопоставлены с прежними наблюдениями.

Общий CI wheel: `c11394ced97753bfb5b241eff7b8f84a3ea4baef5a3eeadc6cca18c12b0cf2e1`.
Отдельный локальный wheel может иметь другой SHA из-за ZIP-метаданных платформы сборки;
это самостоятельный прогон с тем же source identity. В CI все 22 установки
используют один и тот же опубликованный artifact.

## Сбои и восстановление

Проверены потеря ответа после commit для трёх типов исследований,
одновременное создание, завершение процесса сразу после commit, откат,
перезапуск сервера с неподтверждённым клиентским файлом, backup/restore,
удаление с сохранением ключа, выявление коррупции и миграция schema 13 → 14.
Шесть удерживаемых тяжёлых HTTP-чтений не занимают резерв коротких запросов:
прогресс и управление остаются доступны, лишнее тяжёлое чтение получает
структурированную занятость. Проверки не ослабляют лимиты памяти.

В браузере прошли девять сценариев повторов, отмены ожидания и восстановления.
В отдельном реальном запуске проверочный сервер потерял восемь ответов о
создании после commit. После перезагрузки восстановилась ровно одна серия,
два задания и два результата 40/80. Независимая сверка SQLite и Parquet
проверила все восемь значений, контрольные суммы объектов и закреплённые
исходник, настройки, IR и сборку. Реальный отчёт исследования открывается,
ошибок JavaScript нет.

## Изменение работы CI

Спецификация выполняется два раза на матрицу вместо шести, сборка общего
wheel — один раз вместо отдельных сборок в 22 установочных jobs. Проверки
не сокращены. Баланс тестовых шардов рассчитывается по отдельным измерениям
Windows/Linux из предыдущей принятой поставки. Фактические длительности
новых шардов сохранены в evidence; время очереди GitHub и новый этап
проверки артефактов не позволяют обещать постоянный выигрыш общего времени.

## Исправления, найденные при приёмке

Первая сборка `df73f0f` не принята: браузер обнаружил конфликт глобального
имени с существующим скриптом отчётов, а старый тест восстановления v1
оставлял новую таблицу schema 14 перед воспроизведением миграции. Конфликт
устранён; тестовая заготовка восстановлена корректно без изменения самой
миграции. Полная приёмка повторена для исправленной сборки `b972e3f`.

## Практические границы

Автоматически повторяется только безопасное чтение и создание исследования
с сохранённым ключом. Остальные POST не переотправляются автоматически.
После исчерпания восьми попыток занятость остаётся явной диагностикой;
принятая работа продолжает выполняться. Для восстановления нужен сохранённый
файл операции CLI либо localStorage того же origin браузера. Точное
сопоставление Pine с TradingView остаётся отдельным этапом.
