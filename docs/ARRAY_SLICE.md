# Общие окна массивов

Профиль `openpine.array-slice.1` реализует `array.slice(id, index_from, index_to)`
для v4–v6 и instance-вызов `id.slice(...)` для v5/v6. V1–v3 отвергают array API;
целые контрольные программы используют scalar-аналоги. Поддержаны существующие
int/float/bool/string, с v5 — enum и плоские UDT. Детали generic-примитивов v4
сохраняют прежнюю историческую реконструкцию. Внешнее исполнение TradingView
не проверено.

Все три аргумента обязательны, вычисляются один раз в исходном порядке.
Receiver метода вычисляется первым. Границы — определённые int:
`0 <= index_from < index_to <= size`. Правая граница исключена. Отрицательные
границы запрещены и в v6; отрицательные индексы уже готовых get/set/insert/remove
сохраняют свои прежние правила. Создать пустое окно нельзя.

```pine
//@version=6
indicator("Shared window")
a = array.from(0, 3, 1, 2, 9)
b = a.slice(1, 4)
b.sort()
plot(a.get(1))  // 1: изменён диапазон исходного массива
b.push(7)      // a = [0, 1, 2, 3, 7, 9], b = [1, 2, 3, 7]
plot(b.size())
```

## Идентичность и изменение размеров

Срез получает отдельный ArrayRef и хранит ссылку на корневой массив плюс
абсолютные границы. Присваивание среза сохраняет его ID. Элементы не копируются;
каждый физический слот и его ссылка на UDT учитываются один раз, у корня.
`copy(slice)` создаёт независимый контейнер; UDT внутри остаются общими.

Запись видна через все окна, покрывающие соответствующую позицию. Вставка,
удаление, push/pop/unshift/shift, clear и concat через окно заменяют его диапазон
в корне и меняют размер только окна-получателя. После удаления всех элементов
оно остаётся пустым, в него можно снова вставить элемент. Другие окна сохраняют
свои абсолютные границы. Вставка в родителя перед окном меняет наблюдаемые
элементы, сохраняя позиции окна.

Срез от среза нормализуется до корня: изменение размера внутреннего окна не
меняет границы внешнего. Пересекающиеся concat/self-concat читают исходные
слоты до публикации результата. Эти подробности вложенных и пересекающихся
окон являются явной интерпретацией OpenPine там, где закреплённые артефакты
не задают их достаточно точно.

## Противоречие источников

[Текущий раздел v6 о срезах](https://www.tradingview.com/pine-script-docs/language/arrays/#slicing-arrays)
показывает уменьшение видимого размера при сокращении корня и последующий рост.
[Раздел ошибок той же страницы](https://www.tradingview.com/pine-script-docs/language/arrays/#slice-is-out-of-bounds-of-the-parent-array)
описывает отказ при выходе фиксированного окна за границы родителя. Старые
[v4](https://www.tradingview.com/pine-script-docs/v4/essential/arrays/) и
[v5](https://www.tradingview.com/pine-script-docs/v5/language/arrays/) также
описывают фиксированное позиционное окно и такую ошибку.

Профиль сохраняет фиксированные границы. Если окно выходит за текущую длину
корня, любая операция доступа, включая size/clear/copy, даёт
`ARRAY_SLICE_BOUNDS`. Изменение родителя само по себе не вызывает эту ошибку;
достаточный последующий рост делает окно снова доступным. Проверка na(ref)
по-прежнему проверяет только отсутствие ссылки. Checkpoint сохраняет и
временно недоступное окно, не обрезая его границ. Это выбранное правило
ограниченного профиля, а не утверждение о текущем поведении TradingView.

## Общий runtime и бюджеты

Все прежние операции, агрегаты и for-in читают единый доступ к диапазону.
Индексы поиска, sort_indices и for-in считаются от начала окна. Сортировка,
reverse и fill меняют только диапазон получателя. Корень удерживается живыми
окнами и освобождается после удаления последних roots/history/view edges.
Граф ацикличен: окно → корневой массив → плоские записи; элементами массивов
по-прежнему не могут быть другие коллекции.

Для просмотра размера/слота и бинарного поиска окно не материализуется.
Создание окна занимает постоянную дополнительную память. Мутация окна
использует транзакционную замену корневого буфера, поэтому её работа и временная
память зависят от длины корня. До сборки и публикации учитываются конечная
длина корня, физические ячейки/UTF-8, staging окна и корня, COW metadata,
работа и отмена. Ошибка не публикует новый ID, границы, буфер или частичные
счётчики ссылок. Лимиты не повышены: 100 тысяч элементов, 100 тысяч объектов,
миллион физических ячеек, 16 MiB строк; сложная операция может исчерпать
прежний общий бюджет.

Закрытые enum-значения представлены строковыми токенами существующего codec.
Они участвуют в UTF-8 счётчике корня, включая copy/clear/concat окна. Проверены
все операции enum-окон и восстановление; счётчик совпадает с содержимым,
а частичный размер окна не подменяет размер физического буфера.

## История и восстановление

ArrayIR сохраняет прежний layout с закрытой операцией slice. Программы,
содержащие slice, используют `openpine.runtime-state.9` и
`openpine.array-heap.2`; программы без slice сохраняют прежние форматы.
Новый heap хранит окна как `id/element/parent_id/start/end`, корневые массивы и
UDT — в существующих layouts. Reader проверяет типы, предельные границы,
ссылку на более ранний корень того же element-типа, physical counters и roots.
Старые форматы не принимают новые view-records.

История хранит прежний ID, а не копию содержимого. Preview получает отдельный
корневой буфер при первой записи; aliases внутри preview остаются общими.
Varip переносит достижимый граф окна и корня, а в UDT — только помеченные
varip-поля. Streaming checkpoint после restore полностью принадлежит runtime
и не требует дальнейшего чтения файлов checkpoint.

Проверки: `tests/test_array_slice.py`, независимые ожидания
`conformance/array-slice/cases.json`, восемь программ `array-slice-*`
общего корпуса. Неизменяемые Wiki bundles и прежние profiles сохраняются.
Три прежних `v4/v5/v6-reject-slice-excluded` сохраняют ID/исходник, но теперь
исполняют прежний `plot(1)` с const qualifier; переходы фиксируются отдельно.
