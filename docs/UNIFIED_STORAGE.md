# Единый учёт памяти R6

Внутренний профиль хранения `openpine.history-storage.2` расширяет доказуемую
глубину на SMA, change и `[]`. Это изменение ресурсов исполнения, а не новая
трактовка Pine. Версии 1–6 сохраняют собственные правила NA, bool и EMA.
Совместимость сохранённых программ и заданий закрепляется execution identity;
checkpoint дополнительно проверяет план, вычисленный заново из IR и inputs.

| Владелец | Что сохраняется | Граница и учёт |
| --- | --- | --- |
| `[]` | Завершённые бары, включая пропуски | Максимальный доказанный offset для одного series ID; offset 0 не требует буфера |
| SMA | Точные префиксные суммы определённых образцов | Доказанная длина + один якорь; пропущенный вызов не обновляет состояние |
| change, MOM/ROC | Достигнутые вызовы, включая NA | Доказанная глубина; change с длиной 0 не сохраняет образцы |
| Меняющиеся окна и семь сигналов | Префиксы, пары, индексы | Доказанный горизонт; геометрический рост деревьев |
| Фиксированные окна | Листья, деревья, очереди событий | Проверенная фиксированная длина и отдельная квота логических ячеек |
| EMA v1–v4 | Прогрев определёнными образцами | Общая байтовая квота; неизвестная длина не обрезается до 100 тысяч |
| Остальные скалярные TA | Скаляры, точные суммы, несколько составных состояний | Резерв на экземпляр написанного вызова в контексте |
| Массивы | Элементы, объекты, строки, корни | Собственные квоты и общий ledger; копирование preview учитывается отдельно |
| varip | Снимок корней и массивов между проходами | Общий ledger, включая одновременное существование старого и нового снимка |
| Preview | Изменённые ячейки и временные копии | Освобождение при отбрасывании; при выборе ветви перенос подтверждённого владения |
| Restore | Временный проверяемый владелец | Публикация после полной проверки; ошибка освобождает и частично восстановленную кучу |
| Свечи и файловый вывод | Порции чтения и DuckDB caches | Общий IO-бюджет, поделённый между одновременными readers/writer |
| Кодек checkpoint, SQLite trade index, Python overhead | Временные буферы и ограниченные caches | Базовый резерв и существующий жёсткий контроль RSS процесса |
| Прямой API без sink | Все возвращаемые значения | Его результат намеренно находится в памяти; production workers используют файловый sink |

Неизвестный offset/длина, изменение переменной, неподдержанное доказательство,
переполнение или исчерпание анализа сохраняют полный разрешённый горизонт.
Для старой EMA нет языкового лимита длины 100 тысяч: неизвестный прогрев явно
помечается неполной статической оценкой и ограничивается ресурсами задания.

Профиль задания `openpine.job-memory.1` выделяет половину бюджета общему ledger
состояний, массивов, preview и restore; четверть — IO; четверть — базовым и
временным расходам. Половина области состояния обозначена как резерв возможного
restore: это планировочный ориентир, а не дополнительная память поверх бюджета.
Реальная загрузка проверяется по совокупному живому владению, поэтому чрезмерный
restore может быть отклонён до публикации. Supervisor продолжает проверять RSS.

Учёт различает значения, индексы, пары, точные целые, строки, array references,
объекты массива и preview. Стоимости консервативны и включают Python containers.
Зарезервированные байты и ячейки не являются измерением RSS; резерв прогрева
может сохраняться до завершения evaluation после освобождения seed-списка.

Worker сохраняет `resources.json`: план, причины retention, логические ячейки,
элементы массива, byte ledger по владельцам и отдельный образец RSS. Частные
запросы различаются по написанному request site, даже на одном рынке.

`python -m tools.unified_storage_soak --directory <новый каталог> --bars 333334`
запускает два последовательных процесса. Они используют production driver и
ResultSink, три рынка, семь сигналов, SMA, `[]` и change. Первый процесс сохраняет
runtime и незавершённый выходной префикс на диск и завершается; второй загружает
их. Независимый целочисленный/рациональный oracle проверяет каждое значение,
а чтение всех Parquet-блоков проверяет полные уникальные диапазоны каждого output.

CI сохраняет 18 установочных наборов на ОС и 53 задания. Перенос helper между
наборами и порядок старта основаны на исходных логах run 40681726120: длинные
неделимые проверки запускаются раньше, пять target helpers распределены по
существующим наборам. Набор helper сохранён без пропусков и дублирования.

Результаты полной приёмки и точные идентичности исходника публикуются отдельным
evidence после её завершения. Точное сравнение с TradingView остаётся отдельным
этапом; существующие ограничения восстановленной семантики сохраняются.
