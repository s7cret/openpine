# Перегрузки UDF

Профиль `spec/function-overloads-profile.json` допускает перегрузки в Pine
v5/v6. В v1–v4 разные сигнатуры одного имени дают `FUNCTION_OVERLOAD_VERSION`;
прежние одинаковые определения сохраняют `DUPLICATE_FUNCTION`.

## Различия версий

В [release notes v5, ноябрь 2021](https://www.tradingview.com/pine-script-docs/v5/release-notes/#november-2021)
сигнатуры различаются общим числом параметров либо комбинациями явно указанных
типов. [Описание v6](https://www.tradingview.com/pine-script-docs/language/user-defined-functions/#function-overloading)
сравнивает число обязательных параметров и их qualified types. Поэтому
`f(int x)` и `f(int x, int y=2)` допускаются как определения v5, но `f(1)`
неоднозначен; в v6 определения конфликтуют даже без вызова. Это явно разные
версионные политики. Wiki v6 содержит запись overload; для v5 закреплено
дополнение из первичного источника, а method overload не подменяет UDF evidence.

При одинаковой различающей арности требуются явные типы. Имена параметров и
результат тела не выбирают перегрузку. Сохраняется прежняя модель qualifiers
профиля OpenPine: без qualifier параметр наследует qualifier аргумента;
`simple` исключает series, `series` допускает все уровни. Ссылки на primitive
arrays всегда series. Автоматический выбор наиболее узкого qualifier не введён.

## Связывание и исполнение

Binder проверяет форму вызова, связывает явные аргументы один раз в исходном
порядке и сравнивает заголовки. Точные типы предпочтительнее `int → float`;
равная стоимость даёт `FUNCTION_OVERLOAD_AMBIGUOUS`, отсутствие кандидата —
`FUNCTION_OVERLOAD_NO_MATCH`. Тела кандидатов не исполняются и не пробуются.
После выбора добавляются уже проверенные закрытые литеральные defaults.
Именованные аргументы и их диагностики используют общий механизм параметров.

В typed IR `.12` записаны ID конкретного определения, типизированные параметры,
порядок вычисления и маска обязательных параметров. Runtime проверяет эти
контракты, scopes, типы, defaults и зависимости; выбора перегрузки во время
исполнения нет. Обычные функции сохраняют прежний wire-формат. Приватный
request-граф может содержать только выбранное определение из группы.

Captures и граф зависимостей принадлежат ID определений. Внутри перегрузки
одноимённые вызовы видят ранее объявленные перегрузки; рекурсия запрещена.
Структура, имена, записи и определённые зависимости проверяются даже в
неиспользованных телах. Зависимости с неизвестными типами выражений проверяет
Binder при специализации каждого написанного вызова, включая мёртвые ветки.
Это ограниченный профиль проверки, без второго интерпретатора типов.

`var`, `varip`, история и TA-ядра остаются независимыми для каждой написанной
цепочки вызовов. IR используется общей цепочкой history, replay, rollback,
checkpoint и requested contexts. Лимиты: 64 определения суммарно, 16 на имя,
16 параметров, 128 специализаций, глубина вызовов 12, 8192 узла и глубина IR 128.

## Свидетельства

`test_function_overloads.py`, проверки private graph в `test_context_graph.py`
и every-cut intrabar в `test_intrabar.py`; 40 независимых conformance-случаев
(20 исполнений, 20 отказов). В owned corpus добавлены восемь программ:
v1–v4 используют разные имена, v5/v6 — перегрузки; две стратегии проверяют
типизированный выбор количества заявки. Все прежние 64 записи сохраняются.

Методы, пользовательские типы, общие выражения defaults и точное совпадение
с исполнением TradingView остаются отдельными этапами. Эти проверки подтверждают
закреплённые правила и результаты собственных программ.
