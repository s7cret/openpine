# INT04 process and evidence resource lifecycle

Each logged verification command and campaign shard runs under a dedicated Linux subreaper. It owns descendants, including detached sessions, and cleans them after timeout, cancellation, controller death or root exit. Every newly enumerated task requires a stable kernel pidfd and a live parent chain to this supervisor; enumeration results and historical PID/create-time membership grant no authority to signal. Retained pidfds are reconciled on every observation path, including a successful empty traversal after an ancestor exits. Normal root exit permits a bounded two-second descendant grace period before cleanup. An orphan family fails the command even when cleanup succeeds.

The supervisor retains raw process-family evidence with declared argv/cwd, controller/supervisor/command PIDs, observed identities, cleanup signals, remaining processes and observation errors. Command and campaign admission requires this primary evidence, exact launch identity, successful cleanup and no observation errors. The reader rejects over-budget histories and duplicate or excessive cleanup signals even when the receipt was rehashed and resealed. Historical execution bindings still replay without requiring their original filesystem locations.

Linux pidfd support is checked before launching any child. Readiness uses `poll()` for both retained handles and every lineage admission check, so high descriptor numbers and caller `pass_fds` do not hit `select()`'s FD_SETSIZE ceiling. Invalid descriptors remain observation errors. Owned descendant signals target stable handles directly, never a checked integer PID. The controller also retains the guardian's direct-child pidfd until poll/wait completes; cancellation signals that handle without routing through a numerical process-group ID. A private launch gate prevents the declared command from starting until the controller acquires that handle. A post-spawn acquisition failure refuses the gate and performs bounded TERM/KILL escalation and reaping before returning an infrastructure error. Actual SIGINT immediately after read-end gate close, during gate write or final write-end gate close cleans the already launched family and retains cancelled command evidence. The cumulative receipt ledger is capped at 16384 identities, the normal live-handle pool at 4096 and a separate emergency overflow pool at 4096. A budget failure stops the admitted family and signals newly verified owned overflow tasks immediately; one shared cleanup deadline covers the family. Live overflow handles remain visible in survivor reporting. If emergency storage is exhausted, at most 64 exit-unverified identities are retained as conservative survivors; any omitted observations explicitly mark the survivor inventory incomplete. Every pressure path fails admission. Error text is bounded and normal signal history contains at most one TERM and one KILL per admitted identity.

Live owner tools and bound interpreters must remain executable regular files. Removing executable bits is rejected even when file bytes retain their hash. Inner exec syscall failures retain infrastructure-error classification and failed command/shard evidence. Denied psutil diagnostics remain failures while kernel handles retain safe cleanup authority. Kernel process names are parsed as bytes with filesystem surrogate handling. No security policy, service, user or global process-management configuration changes are introduced.

Original failure probes and later review failures remain outside sources. The targeted set covers actual sockets/flocks, concurrent campaign crash/cancellation, allocation-driven memory cancellation, physical disk-floor refusal, metadata/status denial with an unrelated non-UTF8-name neighbour, real inner exec failures, resealed evidence mutations, stale enumeration admission, stable pidfd signalling, successful traversal omissions, unavailable pidfd refusal, cumulative churn and actual overflow signal denial. PID reuse tests model deterministic interleavings using real owned subprocess targets; they do not force operating-system PID reuse.
