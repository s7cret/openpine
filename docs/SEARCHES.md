# Воспроизводимый подбор параметров

Поиск использует готовый IR, конечные варианты `input` и обычные experiments.
`packages/optimizer` содержит генерацию кандидатов, метрики и ранжирование;
прикладной сервис связывает их с существующим JobManager. Отдельного пула
исполнения или подключения к провайдеру внутри оптимизатора нет.

## Закреплённый состав

`openpine.search.1` сохраняет программу и её идентичность, input schema,
исходные снимки свечей/контекстов, срезы двух участков, базовые настройки,
нормализованные оси, метод, seed, бюджет, полный порядок кандидатов,
целевую метрику, ограничения и хеши всех планов подбора и проверки.
Отдельный `optimizer_identity` закрепляет реализацию генератора и оценки.
Несовместимая реализация при продолжении приостанавливает поиск; результаты
и состав не пересоздаются автоматически.

SQLite migration 10 добавляет `searches`, `search_holdouts` и
`search_assessments`. Состав, планы, оценки и принятое решение защищены
неизменяемыми записями. Создание поиска и его серии подбора атомарно.
Решение о победителе и серия из одного проверочного варианта также
публикуются одной транзакцией. Все проверочные планы закреплены заранее.

## Конечное пространство

- `grid`: полная декартова сетка должна помещаться в бюджет; усечения нет.
- `random`: выбор без повторений по seed, алгоритм
  `openpine.finite-search.sha256.1` (SHA-256, rejection sampling и Floyd sampling).
  Порядок заданий и завершения воркеров не влияет на кандидатов.
- Бюджет 1–256 кандидатов, seed 0–4294967295. Не более восьми работающих
  незавершённых поисков и прежних шестнадцати серий experiments.
- Ось — явный список или числовой `{min,max,step}`. Верхняя граница включается,
  если лежит на сетке. Шаг `input.step` остаётся шагом интерфейса и не задаёт
  пространство поиска. Десятичная сетка строится до преобразования во float.
- Имена и `input:имя` нормализуются; дубли осей/значений, неверные типы,
  неактивные параметры, выход за bounds/options и бесконечные значения отклоняются.
  Для больших int64 в списках используется `{"$int":"9007199254740993"}`.
- До 10000 значений на ось, 16384 суммарно, cardinality до int64,
  описание пространства до 1 MiB, закреплённые настройки кандидатов до 2 MiB.

## Временные участки и прогрев

`windows.selection` и `windows.holdout` задают UTC milliseconds:
`warmup_start_ms <= score_start_ms < end_ms`. Интервалы полуоткрытые.
Конец подбора не позже начала оценки на отложенном участке. Границы должны
укладываться в имеющиеся данные и оставлять оцениваемые свечи.

Срезы создаются из **конкретного исходного снимка**, без нового запроса
провайдеру и без копирования Parquet-блоков. Запрошенные контексты ограничены
концом соответствующего участка; прежняя причинная видимость сохраняется.
Прогрев отложенного участка может перекрывать историю подбора.

Каждый запуск получает независимое состояние runtime и брокера. На прогреве
runtime считает выражения и меняет свои переменные, брокер сохраняет начальный
капитал и нулевую позицию; заявки отбрасываются до `score_start_ms`. Первая
заявка оцениваемого участка исполняется по прежнему правилу next-open.
Оценки выходных рядов и просадки учитывают только оцениваемые свечи.
В конце нет принудительного закрытия позиции. Открытая позиция учитывается
по последней цене закрытия. Это отдельная исследовательская политика,
она не заявляет точного соответствия TradingView.

Окно входит в job request `.7`, RunPlan `.6` и его хеш checkpoint.
Итоговый summary `.7` и небольшой экспорт result `.6` сохраняют окно.
Прежние запросы/планы без окна сохраняют старое кодирование.

## Оценка и выбор

Контракт `openpine.search-metrics.1`:

| Метрика | Определение |
|---|---|
| `net_profit` | Последний equity минус начальный капитал, с комиссиями и открытой позицией |
| `max_drawdown` | Наибольшее падение equity от предыдущего пика, в деньгах; начальный пик — начальный капитал |
| `trades` | Количество закрытых сделок |
| `commission` | Накопленная комиссия |
| `output_last/mean/min/max` | Последнее, среднее, минимальное или максимальное числовое значение ряда на участке оценки; `na` пропускается, числовой ноль включается |

Для выходного ряда обязателен `output_index` (0–31), направление —
`maximize`/`minimize`. Индикатору требуется явно выбранная метрика ряда.
Ограничений до 16: `{metric,operator:gte|lte,value}`, для ряда также индекс.
Денежные оценки и ранжирование используют десятичные значения, без
преобразования денежного текста в binary float. Среднее вычисляется с
точностью Decimal 700; это закреплённая политика конечной точности.
Порядок ненулевых десятичных значений ограничен диапазоном −300…300,
текстовое представление — 1024 символами. Выход за этот профиль при расчёте
метрики сохраняется как `invalid_metric`.

Отсутствующие/нечисловые метрики, ошибки исполнения и нарушенные ограничения
не участвуют в выборе. Отсутствие закрытых сделок само по себе не исключает
вариант: для этого задаётся ограничение `trades >= 1` или другое явное значение.
Равные оценки разрешаются порядковым номером кандидата. Если подходящих
вариантов нет, сохраняется `no_eligible_candidate`, проверочное задание не создаётся.

Сначала оцениваются **все** результаты подбора и закрепляется решение.
Только после этого запускается один победитель на отложенном участке.
Его оценка, ошибка или невыполненное ограничение не меняют победителя.
`holdout_failed` сохраняет принятое решение и диагностирует проверку.
Повторное использование уже просмотренного holdout не делает его новой
независимой проверкой: пользователь выбирает новые границы явно.

## Продолжение и хранение

Поиск не создаёт собственный executor. Кандидаты и проверка проходят через
общие очередь, лимиты процессов/потоков/памяти, retry, heartbeat и checkpoint.
Оценка читает Parquet потоково под бюджетом чтения координатора и может
прерываться при остановке. Занятый бюджет вызывает повторную попытку позже.
Завершённые варианты, оценки и решение при восстановлении не повторяются.

Pause/resume/cancel применяются через поиск; отдельное управление его
дочерними сериями отклоняется. Отмена окончательная. Остановка приложения
сохраняет незавершённые задания для продолжения. GC и backup учитывают
исходные снимки, ещё не запущенные проверочные планы и результаты.
Отдельное удаление истории поисков в этот профиль не входит.

## CLI, HTTP и веб

```sh
python -m apps.openpine search run --source examples/search/v6.pine --bars examples/inputs/bars.json --request examples/search/request.json --state-dir .runtime/search
python -m apps.openpine search status --id SEARCH_ID --state-dir .runtime/search --start 0 --limit 25
python -m apps.openpine search pause --id SEARCH_ID --state-dir .runtime/search
python -m apps.openpine search run --id SEARCH_ID --state-dir .runtime/search
python -m apps.openpine search rerun --id SEARCH_ID --ordinal 2 --phase holdout --state-dir .runtime/search
```

Также доступны `create`, `list`, `resume`, `cancel`. `resume` сохраняет желаемое
состояние; исполнение ведёт работающий сервер или `search run`.
`rerun` создаёт обычную серию из одного **сохранённого** плана. Её можно
продолжить через `experiment run --id EXPERIMENT_ID`. Подбор можно повторить
для любого кандидата, holdout — только для уже выбранного победителя.
При `serve --state-dir DIR` тот же каталог для последующего запуска CLI —
`DIR/jobs`. CLI и сервер владеют им поочерёдно. Пока сервер работает,
просмотр и управление доступны через HTTP/веб; второй локальный координатор
отклоняется блокировкой владельца.

`GET/POST /api/searches`, `GET /api/searches/ID?start&limit`,
`POST /api/searches/ID/{pause,resume,cancel,rerun}`. Управление принимает `{}`,
повтор — `{ordinal,phase}`. Страницы до 100 строк. Прежние Host/Origin/token
и бюджеты подготовки/чтения применяются к новым маршрутам.

Веб-форма строит оси из input schema, задаёт критерий, бюджет, seed,
ограничения и UTC-периоды. Таблица показывает оценку подбора и место;
отложенная проверка отображается отдельно. Доступны график и повтор
сохранённых настроек. Длинные оценки показаны в сокращённой научной записи;
точное значение сохраняется в подсказке и API и используется для ранжирования.
Примеры есть для всех поддержанных профилей v1–v6.

`tools.release_gate` включает независимые ожидаемые оценки, v1–v6,
восстановление/прогрев, проверку CLI/HTTP и реальные падения процессов.
`tools.install_check` проверяет поиск на установленном wheel вне checkout.
Аварийные сценарии отдельно:

```sh
python -m tools.search_soak --directory NEW_DIRECTORY --cut selection
python -m tools.search_soak --directory ANOTHER_NEW_DIRECTORY --cut holdout
```

Байесовский поиск, генетические алгоритмы и walk-forward остаются за пределами
первого профиля. Сверка семантики Pine с TradingView выполняется отдельным этапом.
