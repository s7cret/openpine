# Приёмка мест вывода числового plot в R6

[Исходник bf7dcd9588ba](https://github.com/s7cret/openpine/commit/bf7dcd9588ba418e6ffcfc052bcb245853c8bd24) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42543587313) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42543587278)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 918 тестов. Conformance охватывает 4 372 сценариев, корпус — 180 программ.

- Для числового `plot()` в Pine v5–v6 проверены `display.pane`,
  `display.status_line`, `display.price_scale`, `display.data_window`
  и сочетания с `+` и `-`. Версионные границы и поддержка двоичных
  режимов других слоёв проверены соседними сценариями.
- Прошли 17 браузерных сценариев. Числа в строке
  статуса и окне данных относятся к исходной свече с учётом
  `show_last`. `offset` влияет на рисунок. На шкале проверены
  актуальное значение, отсутствие метки для `na` и положение при
  прокрутке истории и переключении между превью и подтверждением.
  Заливка сохраняет связь с опорой без `display.pane`.
- Установленный wheel на обеих ОС подтвердил сохранение списка
  мест при изменении пресета и возобновлении worker, доступ через
  Parquet, историю и экспорт, а также равенство полных результатов
  CLI и HTTP.
- На Windows прошло 1 918 тестов, на Linux — 1 917.
  На Linux ожидаемо пропущена проверка псевдонимов файлов Windows 8.3.
  Обе ОС использовали один wheel. Прошли четыре сценария восстановления.
- Сохранены наблюдения 4 357
  прежних сценариев. Три случая из ожидаемого отказа переведены
  в успешное исполнение с теми же исходниками. Добавлено
  12 сценариев. Отчёты совпали между Windows
  и Linux. Внешняя сверка с TradingView проводится отдельно.
