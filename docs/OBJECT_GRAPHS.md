# Ссылочные поля UDT v5/v6

`spec/object-graphs-profile.json` задаёт дополнительный профиль
`openpine.object-graphs.1`. Он расширяет [плоские объекты](OBJECTS.md):
поле может содержать ID другого UDT, своего типа, массива, map или матрицы
с уже поддержанными типами элементов. В v1–v4 остаётся `UDT_VERSION`.

```pine
//@version=6
indicator("Linked values")
type Node
    float value
    Node previous
type Book
    Node head
    array<float> closes
var book = Book.new(na, array.new_float())
book.head := Node.new(close, book.head)
book.closes.push(book.head.value)
plot(book.head.value)
plot(book.closes.size())
```

Поддерживаются собственный тип и ранее объявленные типы. Forward type names
не добавлены. Ссылочный default — типизированный `na`. Вызовы в defaults полей
по-прежнему исключены; объект или коллекция передаётся явным аргументом
конструктора. Аргументы выполняются один раз в исходном порядке, включая
именованные; затем подставляются закрытые defaults.

Цепочки полей, их изменение, UDF и методы используют существующий Binder.
Номинальные типы не взаимозаменяемы. Ссылки сохраняют qualifier `series`.
Присваивание копирует ID. `copy()` создаёт новый внешний объект с теми же
значениями и ID полей. Изменение общего дочернего объекта видно всем алиасам;
замена поля меняет только внешний объект, которому принадлежит поле.

## Куча, циклы и ресурсы

Все объекты используют прежний heap с едиными IDs, квотами, ledger и COW.
Допускаются ссылки на себя, циклы нескольких экземпляров и косвенные циклы
через коллекцию в UDT. GC graph-программ обходит достижимые объекты итеративно,
учитывая persistent bindings, историю, preview и constructor baseline.
Недостижимые циклы освобождаются. Память обхода, работа и отмена проверяются
до публикации сборки; прежние лимиты не повышаются.

Для новых коллекций сохраняется исходный буфер конструктора. Перед первой
записью COW защищает его и учитывает дополнительную память. На закрытии бара
transient baseline освобождаются до GC. Стоимость GC/переноса растёт с графом;
это ограниченная reference-реализация, а не обещание постоянного времени.

## История, rollback и varip

История ссылки хранит ID, а не глубокую копию. `(node[1]).child.value` читает
содержимое объекта по прошлому ID. Прежняя граница прямой истории полей
`object.field[1]` сохраняется.

Обычные поля возвращаются к confirmed baseline, а для нового объекта внутри
незакрытого бара — к baseline конструктора. Только помеченное `varip` поле
переносит своё значение или ID. Перенос ID дочернего UDT не продвигает обычные
поля дочернего объекта: его поля требуют собственных пометок.

Обычные коллекции восстанавливают confirmed/constructor буфер. Если тот же
ID достигнут через переносимый маршрут, например помеченное поле или
`varip`-коллекцию, переносится содержимое общего контейнера для всех алиасов.
Это явно выбранная трактовка взаимодействия полей и графа; внешняя сверка
TradingView ещё не выполнена.

`varip`-коллекция допускает значения либо UDT с полями-значениями и коллекциями
значений. Прямое UDT-поле в элементе такой коллекции, включая рекурсивное,
отклоняется `VARIP_GRAPH_TYPE`. `varip` у самой переменной UDT переносит ID;
он не заменяет пометки полей. Допуск проверяется для помеченного коллекционного
поля и при приёме сохранённого IR.

## Совместимость и граница

Только программы со ссылочными полями используют typed-ir.19,
runtime-state.12 и array-heap.5. Старые программы сохраняют свои форматы.
Checkpoint содержит типизированные ID; два прохода восстанавливают backing
objects и затем рёбра. Проверяются номинальные типы, достижимость, счётчики,
обычные поля и constructor buffers. Некорректное состояние не публикуется.
Восстановленный runtime владеет своими буферами и не зависит от checkpoint-store.

Прямая вложенность `array<array<...>>`, графика/color, object-dependent requests,
object tuple-results и рекурсивные функции остаются вне профиля.
Коллекция объектов с коллекциями в полях — поддержанная косвенная вложенность.

Причины и трактовки: [ADR 0004](adr/0004-reference-fields-and-cyclic-heap.md).
Независимые ожидания: `conformance/object-graphs`; восемь целых программ:
`examples/corpus/object-graphs-*`. Внутренние проверки не устанавливают
эквивалентность TradingView.
