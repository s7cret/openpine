# Приёмка меток в стратегиях R6

[Исходник 167f0c035190](https://github.com/s7cret/openpine/commit/167f0c0351903bac0c414a345c664b4507bbfb8e) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42901607281) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42901607057)

SHA 167f0c035190. CI 57/57, Python 3.14.8. В реестре каждой ОС 1 977 тестов. Conformance охватывает 4 525 сценариев, корпус — 180 программ.

- Для v4–v6 проверены метки на барах подачи заявок, в том числе вместе с таблицей капитала. В v4 проверены вызовы `label.*`, в v5–v6 — методы объекта. Для v1–v3 подтверждён `LABEL_VERSION`.
- Сравнение с той же стратегией без меток подтвердило те же заявки, исполнения и капитал. В историческом задании после перезапуска совпали оба журнала, метки и таблица. Установленный wheel подтвердил этот сценарий через HTTP на обеих ОС.
- Replay с `calc_on_every_tick` возобновился из checkpoint до первого закрытия и посреди открытого бара. Подтверждённые и предварительные метки, их перемещение и вытеснение сверены с непрерывным прогоном. Chrome подтвердил отображение меток в истории и предпросмотре.
- На Windows прошло 1 977 тестов, на Linux — 1 976. На Linux пропущена проверка псевдонимов Windows 8.3. Аудит подтвердил общий wheel и четыре отчёта восстановления.
- Сохранены все 4 516 предыдущих наблюдений. Добавлено 9 сценариев. Отчёты conformance совпадают между Windows и Linux.

В установленном наборе Linux performance сценарий duration Pine v1 потерял heartbeat после запуска возобновления с бара 3. Проверка повторена на том же SHA, wheel и лимитах.
