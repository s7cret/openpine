Добавлены sort (v4–v6), sort_indices, три binary_search и min/max с nth (v5/v6).
Instance-формы доступны с v5; в v6 работают поля плоских UDT по const sort_field.
V4 order является bool, v5/v6 — закрытым sort_order. Проверены переменные,
UDF-параметры/defaults, source order, receiver once, saved IR и hostile records.

Сортировка учитывает сравнения, длины строк, scratch и конечные слоты. Ошибки
памяти, работы, логических квот и отмена не публикуют частичное изменение или
новый ID. Проверены COW previews, aliases, stable ties, nominal layouts и GC.
Лимиты не увеличены. 100 тысяч упорядоченных элементов проходят в прежнем бюджете;
сложный вход может получить атомарный OPERATION_BUDGET.

Проверены worker, CLI/HTTP, history/replay, every-bar/every-event restore,
varip структуры и UDT-поля. Durable checkpoint и активный бар сохраняют
100 тысяч ссылок на одну UDT-запись без размножения объектов. После restore
runtime не читает checkpoint IO. Прежний бюджет задания — 512 МиБ.

Восемь новых программ дополнительно прошли 24 локальных задания воркеров:
58 сравнений совпали, два различия моделей явно not_equivalent. Перед CI
прошли проверки каталога, HTTP, всего паспорта и паспорта корпуса.

Три исходника v4/v5/v6-uncovered-sort и их ID сохранены. Их ожидаемые отказы
ARRAY_OPERATION/PROFILE_UNCOVERED заменены исполнением с plot(1); исходники,
bars и остальные поля сохранены. Пары старых/новых наблюдений и их хеши входят
в машинное свидетельство. Иных переходов ожиданий нет.

Rightmost может вернуть size. Пустой поиск возвращает -1; отсутствующие ранги
дают ARRAY_RANK. Эти и другие неуточнённые границы отмечены как интерпретации
OpenPine. Для UDT string-search приоритет имеет закреплённая типизированная
перегрузка, несмотря на numeric-only prose. Внешнее сравнение с TradingView
остаётся отдельным этапом. Slice и вложенные коллекции исключены.
