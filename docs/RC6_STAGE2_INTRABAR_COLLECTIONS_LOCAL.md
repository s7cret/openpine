# Этап 2: varip-коллекции и типизированный обход map/matrix

Дата: 2026-09-07. Статус: **локальный кандидат, публикация и совместный защищённый CI не подтверждены**. Полный этап 2 остаётся `in_progress`.

## Исходная линия

Изменения продолжают совместно проверенный runtime OpenPine `8607d23871cdcb79bf7470616970646645448290`, дерево `96eecddb8d9904601e49b8918cc46e03fda8012d`. Текущая прочитанная удалённая RC6 `465cee7a3b6a09555db714edbe98bb56410d92b4` дополнительно содержит документационную публикацию. При переносе следует объединить линии, сохранив эту документацию, а не записывать прежнее дерево поверх RC6. Старые отчёты в исходном снимке описывают свои исторические версии; они не являются результатами этого локального кандидата.

Исходники незавершённого предыдущего сеанса в рабочем каталоге не сохранились. Этот блок восстановлен и реализован поверх точного опубликованного архива; новая работа закреплена отдельными коммитами. Шесть исходных номеров стадий не добавлялись: остаётся прежний план из восьми этапов и 36 OP-пунктов.

## Реализованный объём

### Объектная intrabar-политика вместо отключения rollback

Раньше `varip` сохранял скалярный slot, но heap откатывал все коллекции. Новый режим хранит политику на конкретном объекте heap: допускаются фундаментальные элементы `int`, `float`, `bool`, `string`, `color` в array/map/matrix в профиле v5/v6. Это не поддержка произвольных UDT, объектов графика, вложенных коллекций и enum-ключей `varip`.

Обычные объекты по-прежнему откатываются между неокончательными callback. У допущенного `varip` сохраняется объект и его изменения; общие ссылки видят ту же политику, копия сама по себе её не наследует. Срез массива сохраняет связь с backing-объектом; оба проверяются до установки флага. Переназначение ссылки не подменяет историю прежнего объекта глубокой копией.

На четырёх тиках одного бара счётчик коллекции даёт `1, 2, 3, 4`, обычный `var` — `1, 1, 1, 1`. Это проверено для всех трёх видов коллекций, двух версий и локальных переменных UDF. Следующий бар начинается с зафиксированного предыдущего значения. Политика завершения/abort следует существующему scalar-varip режиму runtime, включая deferred callbacks; не утверждается, что произвольный пользовательский exception всегда отменяет эффекты `varip`.

Новые необязательные поля checkpoint записываются только для persistent-объектов. При восстановлении проверяются типы, политики рабочего/committed состояния, backing-ссылки и соответствие varip-слотов heap. Перехеширование несогласованного внешнего состояния не делает его допустимым. Проверка завершается до замены текущей сессии. Обычный формат heap без intrabar-флага сохраняется; совместимость всего checkpoint по прежнему ABI-хешу не предполагается.

### Generic constructors и области видимости

`array.new<T>`, `map.new<K,V>` и `matrix.new<T>` связываются с точным шаблоном активного каталога, сохраняя специализированный тип результата. Ключ/элемент/число параметров проверяются обычным frontend. Исправлена неполнота семантических фактов у базового callee generic-конструктора; gate полного AST не ослаблен.

Поздние проверки коллекций раньше могли заново прочитать локальную переменную UDF из плоского глобального словаря. Одноимённый глобальный scalar тогда подменял локальный массив/map/matrix и приводил к ложным ошибкам количества аргументов. Теперь известный тип и квалификатор конкретного identifier сохраняются из лексического обхода. Сквозной тест намеренно использует одинаковые локальные и глобальные имена.

Отдельно исправлена frontend-типизация `nz(int,int)` и числового продвижения при float, включая переставленные именованные аргументы. Каталог перегенерирован без изменения архивных migration inputs. **Runtime-binding `nz` этим блоком не добавлен:** корректная типизация не означает принятую полную поддержку вызова. Исполняемые map-счётчики используют явно поддержанные `map.contains`/`map.get` и условный выбор. Это ограничение не скрывается заменой runtime-ожиданий.

### Типизированные обходы и проекции

Прямой обход map выдаёт пары в порядке вставки и видит изменения значений существующих ключей. Во время него нельзя менять набор/порядок ключей: добавление, удаление или очистка отклоняются до мутации. Lexical guard освобождается при нормальном завершении, `break`, исключении и вложенных обходах. Для структурных изменений можно работать с отдельной проекцией ключей/копией, а не обходить тот же map.

`map.keys`/`map.values` через ABI теперь возвращают настоящие отдельные Pine-массивы, не Python tuple. У проекций собственные object IDs и корректные типы; их изменение не переписывает исходный map. Native helper, используемый внутри брокерного Python API, не заменён другим механизмом.

Обход matrix возвращает массив строки, а не один scalar. Поддержан `[index,row]`. Для фундаментальных элементов строка независима от parent-matrix; последующие строки считываются при переходе, и размер обхода может изменяться по действующей runtime-политике. Обходы используют существующий общий бюджет итераций callback. Удаление произвольных полных копий не выдаётся за замер ускорения всего бэктеста.

### Закреплённые импорты

Для библиотечных функций с fundamental map/matrix-параметрами введён явный профиль `same_version_collections_v3`. Старые scalar-v1 и array-v2 не переименовываются и сохраняют прежнюю идентичность; профиль повышается монотонно по графу зависимостей. Перестановка/последующий импорт array-функции не понижает уже выбранный collection-v3.

Проверены same-version Pine5/6, типизированные параметры, функции со своим varip-state, обычный linked-source hash и воспроизводимость. Типы/методы/enum, межверсионное исполнение, сложные reference/UDT-формы и UI-реестр не объявляются готовыми.

## Проверяемая интеграция

Два записанных вызова функции независимо накапливают значения сразу в array, map и matrix. Исторический сценарий получает на третьем баре `3,3,3` и `30,30,30`, отправляет один entry с qty=3 и исполняет его по 102 при on-close либо 103 без него. Сопоставляются команды, сделки и капитал bulk/interactive, прямого и импортированного вариантов, Pine5/6 и обоих вариантов fill-recalculation.

В generated-host realtime-сценарии суммы qty на четырёх тиках — `33,66,99,132`; история основного бара фиксируется один раз. JSON checkpoint сохраняет состояние; три разделения исторического расчёта дают те же последующие команды и конечный экспорт. Это проверка runtime/generated-session, не полное восстановление broker/worker/IPC после аварии.

В репозитории остаются четыре обязательных реальных worker-теста. Локально они падают с `bubblewrap is required for isolated execution`; защита не отключена, skip/xfail не добавлены. Полный реальный realtime-транспорт по-прежнему не объявляется принятым: intrabar-сценарий здесь вызывает admitted generated-session напрямую, а protected-worker варианты проверяют исторический путь и fill-recalculation.

## Проверки и принятие

Полные локальные Python 3.13.5 наборы: Pine2AST 628, PineLib 405, Ast2Python 636. Полные Contracts/Engine и offline Provider проверяются отдельно; все исходные test IDs сохраняются, состав новых наборов записан в `verification/inventory.json`. 5573 — **собранный обязательный состав**, не число пройденных случаев. Фактические XML, ошибки среды и незавершённые прогоны включаются в архив поставки отдельно.

Общий CI Python3.11/3.13, protected-worker приёмка, frontend/browser и внешний TradingView oracle не подтверждены для этого кандидата. Предыдущие удалённые результаты не приписываются ему. Архитектурная проверка и исходный инженерный корпус не заменяют эти gates. Нет утверждения о принятии всего этапа 2.

## Остаток исходных критериев

`versioned_catalog`: полный согласованный каталог, сигнатуры и отрицательные пары, а не только исправленные generic-формы.

`stateful_language_matrix`: UDT/generic/reference-формы вне фундаментального профиля, varip-поля объектов и сложные связи, полная `once`-семантика исторических пересчётов; независимая сверка всех взаимодействий коллекций с состоянием.

`imports`: экспорт типов/методов/enum, межверсионные зависимости и полный потребительский путь.

`independent_builtin_expected`: независимые ожидаемые данные для всей заявленной поверхности builtins. Инженерные регрессии не становятся внешним oracle автоматически.
