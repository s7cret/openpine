# Младшие свечи в replay и live

`request.security_lower_tf` v5/v6 работает в логическом replay и в потоке фактически
полученных событий. Вычислитель частных TA/UDF, типы и выделение массивов общие
с историческим исполнением. Сохранённая Wiki подтверждает API; правила доступности,
прогрева и опозданий ниже — явная локальная политика `openpine.lower-events.1`.
Точная эквивалентность TradingView остаётся отдельным этапом.

Массив содержит полученные **закрытия** младших свечей текущего основного интервала.
Открытие и промежуточное обновление младшей свечи не добавляют значение и не двигают
частные TA/UDF. При расчёте на обновлении, исполнении заявки и закрытии основного
бара используются уже доступные закрытия. Каждый проход получает собственные Pine-массивы;
изменение массива не меняет сохранённые младшие значения. Пустой интервал даёт пустые массивы.

Прогрев фиксируется до первого принятого события. Live получает существующие
исторические снимки провайдера и записывает число фактических строк каждого младшего
контекста. `calc_bars_count=N` выбирает последние N строк этого конечного префикса;
TA/UDF начинают с выбранной строки. Последующие live-закрытия продолжают это состояние.
Окно не сдвигается при каждом новом событии. На переходе повторные закрытия отсекает
существующий mapper; общий журнал задаёт порядок прихода всех контекстов.

В ручном replay `lower_tf` в файле `--contexts` необязателен. Без `warmup` вычисление
начинается с первого закрытия, без отсечения неизвестного будущего префикса.

```json
{"schema_version":"openpine.lower-events.1","late":"reject",
 "warmup":{"lower":{"count":16,"end_ms":960000}}}
```

Это значение поля `lower_tf` вместе с обычными `contexts` и `primary_id`.
Пример: `examples/lower-events/contexts.json`, источники v5/v6 и `events.ndjson`.

```powershell
python -m apps.openpine replay create --source examples/lower-events/v6.pine --contexts examples/lower-events/contexts.json --state-dir .runtime/lower-events
python -m apps.openpine replay append --id REPLAY_ID --events examples/lower-events/events.ndjson --state-dir .runtime/lower-events
python -m apps.openpine replay advance --id REPLAY_ID --max-events 13 --checkpoint-every 2 --state-dir .runtime/lower-events
python -m apps.openpine replay advance --id REPLAY_ID --state-dir .runtime/lower-events
```

По умолчанию опоздавшее младшее закрытие уже опубликованного основного бара
останавливает исполнение до изменения состояния. Наблюдаемая незакрытая младшая
свеча также запрещает строгое закрытие основного бара. Полностью отсутствующие свечи
не синтезируются. В логическом replay при равном времени закрытие младшего идёт первым;
в received/live сохраняется настоящий порядок получения.

Явный `late="drop_with_metadata"` пропускает опоздавшее значение из опубликованных
массивов, продолжает частный контекст для будущих расчётов и увеличивает счётчик.
Прошлые результаты не пересчитываются. Live выбирает эту политику только при
существующем разрешении пропусков `allow_with_metadata`; режим `fail` остаётся строгим.
Закрытые свечи неизменяемы, конфликтующие повторы и нарушения хронологии отклоняются.

Статус `lower_tf` содержит `closed_children` по написанным запросам, `pending_cells`,
`late_closes`, `incomplete_primary_closes`, последнее опоздание и закреплённый прогрев.
Веб показывает счётчики в существующей live-панели; start/stop/resume остаются общими.
HTTP `/api/replays`, CLI, импорт сохранённого IR и переносимые live-recordings
сохраняют одну политику. Новые схемы: replay-config.6, replay-state.5, session-recording.5.
Схема SQLite не меняется. Старые профили продолжают использовать прежние форматы.

Буферы держат только ещё не опубликованные основные окна: максимум миллион ячеек
на все запросы, включая компоненты tuple. Сохраняются частные состояния, окна,
курсоры, фазы и счётчики; восстановление проверяет типы, время и доступность.
Превышение бюджета и несоответствие прогрева отклоняются до приёма события.
Действуют общие лимиты heap, истории, процессов, памяти и времени.

Ограничения API и минутных интервалов совпадают с [историческим профилем](LOWER_TF.md).
Bar Magnifier остаётся исторической моделью; live не создаёт скрытые тики и цены исполнений.
