# Массивы младших свечей

`request.security_lower_tf` реализован в ограниченном историческом профиле
`openpine.lower-tf-profile.1`. Сохранённая Wiki подтверждает имя и параметры
в v5/v6; v1–v4 получают `LOWER_TF_VERSION`. Точная сверка с TradingView — отдельный этап.

```pine
//@version=6
indicator("Младшие свечи")
[prices, rising] = request.security_lower_tf("TEST:LOWER", "1", [close, close > open])
plot(array.sum(prices))
```

Основной таймфрейм должен быть большим и кратным младшему; первый профиль
поддерживает минутные интервалы UTC 1–1440. Оба инструмента задаются явно.
Запрошенный инструмент может отличаться от основного; их OHLCV не сравниваются.
Источники закрепляются существующими context bindings на неизменяемые Parquet-снимки.

Выражение вычисляется на младших свечах в отдельном runtime: доступны int,
float, bool, tuple до 16 компонентов, TA, история выражений, неизменяемые глобальные
зависимости, замороженные inputs и поддержанные чистые UDF с частными состояниями.
Результат — массив либо tuple массивов. Запрос должен быть безусловным глобальным;
динамические, вложенные и локальные запросы, коллекции внутри expression,
торговые эффекты и валютная конвертация отклоняются.

В массив попадают только фактически присутствующие, закрытые младшие свечи
текущего основного интервала, в хронологическом порядке. Пустой интервал даёт
пустой массив. Пропуски не заполняются; повторные/неупорядоченные свечи являются ошибкой.
При расчёте после исполнения заявки в Magnifier учитываются только уже закрытые
младшие свечи. Обычного расчёта Pine на каждой модельной точке не добавляется.
Полученный массив принадлежит общему heap программы: работают alias, copy,
история ссылок, циклы, передача в функции, rollback, varip и checkpoint.
Новый расчёт создаёт свежий объект; изменение массива не меняет данные контекста.

Параметры после expression:

- `ignore_invalid_symbol=false`: необходим явный закреплённый источник; true отклоняется.
- `currency=""`: собственная валюта инструмента; непустое значение отклоняется.
- `ignore_invalid_timeframe=false`: некорректная пара интервалов вызывает ошибку;
  при true запрос возвращает пустые массивы, но binding по-прежнему обязателен.
- `calc_bars_count=100000`: **явное правило OpenPine**, а не утверждение о спорном
  default Pine. Допускается literal 1–10 000 000. Выбираются последние N фактических
  строк, закрытых к концу этого исполнения. Будущие строки общего снимка за пределами
  исследовательского окна не сдвигают выборку. Более ранние основные интервалы пусты.
  Частные TA/UDF начинают вычисление с начала выбранного окна.

Сохранённый каталог и реестр содержат неоднозначные defaults `calc_bars_count`;
они сохранены без исправления immutable bundle. Локальное решение и исходные
свидетельства записаны в `spec/lower-tf-profile.json`.

До 16 запросов / 8 контекстов, до 100 000 младших элементов на основной интервал,
общий бюджет буферов — миллион ячеек; дополнительно действуют бюджеты heap,
истории, работы, отмены и процессов. Разные history windows одного снимка
учитываются как отдельные читатели DuckDB в бюджете памяти воркера.

Checkpoint содержит границы окна, курсор источника, времена/значения текущего
интервала и частные runtime. При восстановлении проверяются закреплённые входы,
типы, курсоры, времена и доступность. Ошибочный restore закрывает исполнение.
Новая схема SQLite для этого этапа не требуется.

CLI использует существующий `--contexts`:

```powershell
python -m apps.openpine job --source examples/lower-tf/v6.pine --bars examples/lower-tf/parent.json --contexts examples/lower-tf/contexts.json --state-dir .runtime/lower
```

В веб-форме после компиляции показывается младший контекст: загрузка файла,
сохранённый снимок либо существующий провайдер. CLI/HTTP, сохранённый IR,
подготовка, исследования, search/holdout и walk-forward используют один граф.
Received/live replay пока отклоняет этот исторический профиль до подключения источников.
