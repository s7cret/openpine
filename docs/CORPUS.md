# Корпус целых программ v1–v6

`examples/corpus/manifest.json` закрепляет 72 собственные программы OpenPine:
66 исполнений и 6 отказов изменяемого захвата. Исходные 24 ID сохранены.
Добавлены полный цикл сделки, активные заявки и частичные выходы v1–v6,
intrabar v1–v6 и lower-TF v5/v6. [Правила и состав расширения](REQUEST_ENVIRONMENT.md).
Это проверка цепочки приложения на выбранных примерах. Она не доказывает
совместимость со всем языком или совпадение с TradingView.

Следующая порция добавила восемь [семантических программ](SEMANTIC_CORE.md):
routing v1–v6 и стратегии с switch/defaults v5/v6. Прежние 56 записей сохранены.

Затем добавлены восемь [overload-программ](FUNCTION_OVERLOADS.md); прежние
64 записи сохранены целиком. Каталог ограничен 128 записями / 256 KiB,
один запуск — 64 программами, отчёт — 2 MiB. Каталог выдаёт конечные пакеты
64+8; UI предлагает пакет или отдельную программу. Параллелизм не увеличен.

Каждый файл закреплён путём внутри проекта и SHA-256. Манифест содержит версию
Pine, параметры, отдельные ожидаемые результаты и причину применимости сравнения
истории с replay. Источники не переписываются. Генератор
`python -m tools.corpus_inventory` пересчитывает пины и независимые ручные ожидания;
он не исполняет Pine и не подменяет ожидания фактическим результатом.

## Команды

Используется Python 3.14.8. Все команды выполняются из корня проекта или через
установленный `openpine`. После установки манифест и исходники читаются из wheel.

```text
python -m apps.openpine corpus catalogue
python -m apps.openpine corpus compile --output compilation.json
python -m apps.openpine corpus run --batch 1 --state-dir .runtime/corpus --output corpus-1.json
python -m apps.openpine corpus run --batch 2 --state-dir .runtime/corpus --output corpus-2.json
python -m apps.openpine corpus run --case strategy-v3 --state-dir .runtime/corpus
python -m apps.openpine corpus list --state-dir .runtime/corpus
python -m apps.openpine corpus report --run-id <32hex> --state-dir .runtime/corpus
python -m apps.openpine corpus run --case strategy-v3 --parent-id <32hex> --state-dir .runtime/corpus
```

`compile` возвращает для каждого файла версию и статус, код/category/span
диагностики и совпадение с закреплённым ожиданием. Ожидаемый отказ является
успешной проверкой границы профиля, но не считается выполненной программой.
Неожиданная компиляция такого примера также считается расхождением.

`run` передаёт программы в существующий JobManager с неизменяемыми RunPlan,
IR, снимками и лимитами процессов/RAM/диска. Отдельной очереди исполнения нет.
Один конечный контроллер корпуса допускает один пакет; независимые обычные
задания продолжают обслуживаться общей очередью. Для исполнения нужны
те же зависимости SQLite/DuckDB/Parquet, что и у приложения.

## Проверки и диагностика

Без `--case` команда `run` запускает первый пакет; `--batch` выбирает другой.
`compile` проверяет весь ограниченный каталог. Выбор более 64 программ для
одного исполнения явно отклоняется, программы не пропускаются молча.

Для каждой из 66 исполняемых программ выполняются семь сравнений:

1. Подача исходника и экспорт/импорт сохранённого IR: ряды, журнал, статистика.
2. Непрерывная история и история с восстановлением из середины.
3. Итоговое нативное состояние исторического исполнения после последнего бара.
4. Независимые ручные ожидания выходов.
5. Непрерывный replay и replay с восстановлением на той же ленте.
6. Итоговое нативное состояние replay.
7. История и replay для индикаторов с одним контекстом и только закрытиями.

У стратегий последний пункт отмечен `not_equivalent` с причиной: исторические
lookahead и брокер по событиям имеют разные модели. Это не провал и не
доказательство их эквивалентности. Версии v1/v2 и v3–v6 имеют разные ручные
ожидания по фильтру старшего контекста. Лента сортирует закрытия дополнительных
контекстов перед основным при одинаковом времени; числа OHLCV приводятся к
float согласно действующему контракту событий. Исходный файл данных сохраняется.

Часть исходников штатная подготовка компилирует до отправки воркеру: например,
стратегии и input-программы. `actual_source_route` указывает этот факт. Проверка
сравнивает два маршрута приложения и не выдаёт их за две реализации компилятора.

Сравнения точные, без скрытой погрешности; `null`, bool/int/float и знак нуля
различаются. Отчёт содержит хеши обеих сторон и первое расхождение. Для ряда или
журнала доступны бар, время, выход/событие, контекст, до пяти соседних записей
и соответствующие исходные call sites. Это ограниченная диагностика по
сохранённым результатам; пошаговый trace каждого выражения не записывается.
Большие значения заменяются хешем и размером.

Причины остановки разделяются на неподдержанный язык, отсутствие данных,
ожидание/исчерпание ресурсов, таймаут, отмену, ошибку исполнения или внутреннюю
ошибку. Сводка показывает измеренные случаи по каждой версии и известные пробелы;
процент поддержки всего Pine не вычисляется.

Отказ допуска до постановки задания в очередь сохраняет исходную причину
`resource_wait`. Запланированный ID ещё может отсутствовать в каталоге;
очистка учитывает это и завершает случай с точным статусом. Повтор запуска
остаётся явным действием после освобождения ресурсов.

## Веб и сохранность

Внизу локальной веб-страницы находится раздел «Корпус программ Pine v1–v6».
Откройте корпус, выберите все программы или одну, нажмите «Проверить».
Доступны ход проверки, остановка, подробности каждого случая, повтор одного
случая и скачивание отчёта. Предыдущие проверки открываются из списка.

API: `GET /api/corpus`, `GET/POST /api/corpus/runs`,
`GET /api/corpus/runs/<32hex>`, `POST /api/corpus/runs/<32hex>/cancel`.
POST создания принимает только `request_id`, `case_ids` и необязательный
`parent_id`; файловых путей в HTTP нет. Повтор одинакового ключа идемпотентен,
смена входов с тем же ключом отклоняется. Истёкший ключ не переиспользуется;
повтор принятого дочернего запуска работает и после удаления тела родительского
отчёта. Действуют общие проверки host/origin/token.

Маленький индекс хранится в SQLite settings, отчёт — неизменяемый объект с pin.
Каждая публикация атомарно заменяет индекс и корень отчёта; прежние промежуточные
объекты становятся обычными кандидатами GC. При перезапуске незавершённый пакет
получает `interrupted`, его частичные результаты сохраняются. Автоматического
повтора нет: нужен новый запуск, при желании с `parent_id`. Остановка сервиса
затрагивает только его задания и конечный replay-процесс.

Отчёт сохраняет диагностики, сравнения и provenance самостоятельно. Ссылки
на задания/replays нужны для дополнительной проверки; явная очистка их записей
может удалить исходные большие результаты. Общая команда очистки с
`expire_inputs` также удаляет старые pins, включая отчёты корпуса: перед такой
очисткой скачайте нужный JSON или сделайте резервную копию.
Удалённый по сроку хранения отчёт отмечается `expired`; он не препятствует
запуску сервера. Индекс сохраняет принадлежность заданий для отмены даже
после удаления тела незавершённого отчёта. Список ограничен
50 последними по времени запусками; каждый отчёт ограничен 2 MiB, корпус —
64 случаями, каждый файл — 64 KiB, вход — 4096 барами на контекст.

В установленной приёмке пять существующих suites делят корпус без пропусков
и повторов на Windows и Linux: `economics`, `observed`, `cycle`, `intrabar`,
`magnifier`. Дополнительные сравнения проверяют активные checkpoint, ручную
статистику сделок и внутрисвечные ожидания.
Прежняя матрица CI и conformance остаются обязательными.
