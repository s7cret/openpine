# ADR 0066. Именованные аргументы и числовые границы тригонометрии

Дата 2026-11-15. Статус accepted.

Гайд миграции v4 → v5 указывает `number` для `math.asin`,
`math.acos` и `math.atan`. Закреплённый справочник и справочники
TradingView v5 и v6 указывают `angle` во всех четырёх перегрузках.
OpenPine следует описаниям самих функций и допускает `angle=` в v5–v6.
Для `number=` действуют обычные правила неизвестного имени аргумента.
[Закреплённый справочник](../../spec/lock.json) ·
[Справочник v5](https://www.tradingview.com/pine-script-reference/v5/#fun_math.acos) ·
[Справочник v6](https://www.tradingview.com/pine-script-reference/v6/#fun_math.acos) ·
[Гайд миграции](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-5/#all-variable-function-and-parameter-name-changes).

Позиционные вызовы доступны во всех описанных версиях. В v1–v2
сохраняется режим позиционных аргументов. В v3–v4 тригонометрические
функции принимают `x=`. Ранние записи с неполными квалификаторами
используют принятую числовую модель OpenPine. Перевод углов следует
закреплённой форме с результатом `series float`.

Функции используют общий числовой реестр и бюджет вычисления.
`asin/acos` возвращают `na` вне своего вещественного домена.
Тангенс вычисляется для фактического угла binary64, поэтому у
представимых точек рядом с полюсом результат может быть большим.
Неконечный результат вызывает числовую диагностику. Константы
понижаются до скалярных литералов, так что одинаково доступны
в основном и запрошенном контекстах.
