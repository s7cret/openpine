# ADR-0071. Наблюдаемая история для смещений времени

Дата 2026-11-16

Статус accepted

Документация Pine v5 вводит `bars_back`. В v6 появился
`timeframe_bars_back` и задан порядок применения двух смещений.
Профиль OpenPine должен также определить, как считать пропуски
в загруженных свечах и как восстанавливать отсчёт после остановки.
[Выпуск v5](https://www.tradingview.com/pine-script-docs/v5/release-notes/#march-2024) ·
[Выпуск v6](https://www.tradingview.com/pine-script-docs/release-notes/#october-2025).

Runtime сохраняет подтверждённые открытия свечей и по одному открытию
на каждый наблюдаемый целевой период, предусмотренный IR и настройками.
Запись привязана к закрытию свечи и выполняется даже при пропуске вызова
условной веткой. Временная ветка realtime использует существующую
накладку кольцевого буфера. Просмотр будущих границ использует календарь
UTC 24×7 и не требует данных за пределами обработанного префикса.
Календарный отсчёт по всей прошлой шкале учитывал бы пустые периоды,
поэтому здесь он применяется только для прогноза.

Смещения получили отдельные контракты вызова. Для программы с такими
вызовами checkpoint содержит кольца с открытиями. При двух независимых
смещениях нужно до 10 000 открытий на целевой интервал. Кольца используют
общий бюджет runtime. При восстановлении сверяются вместимость, порядок
открытий, границы UTC и курсор подтверждённого ряда. Формат состояния
программ без смещений сохраняет прежний состав полей. Правила
идентичности версии реализации действуют и для ранее сохранённых IR.
[Профиль и сценарии](../TIME_OFFSETS.md).
