# ADR-0085. Наследование рынка во вложенном запросе

Дата 2026-11-21. Статус принят для динамического профиля OpenPine R6.

Внутри выражения другого запроса пустой символ и `syminfo.tickerid` обозначают инструмент внешнего запроса. Аналогично пустой интервал и `timeframe.period` берут интервал снаружи. Поэтому при ротации A → B → A внутреннее `close[1]` на последнем шаге должно читать предыдущую свечу A. Это трактовка руководства для динамических запросов v5/v6. Сравнение результатов с работающим TradingView остаётся отдельной проверкой. [Руководство Pine](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/#nested-requests)

Сохранённый IR содержит каждый написанный вызов. При подготовке прямой цепочки из двух или трёх уровней OpenPine проверяет каждую пару аргументов отдельно. Если обе оси унаследованы или буквально совпадают с внешними, каждый уровень получает одну и ту же свечу. Для обычного внутреннего `security` с исходными настройками объединения достаточно выполнить конечное выражение в приватном состоянии внешнего рынка. Открывать второй курсор к тем же свечам в этом случае избыточно. В `job --plan-only` граф сохраняет идентификаторы вложенных вызовов, обе разрешённые оси и поля, полученные по наследованию.

Для независимых инструментов или окон у каждого вызова есть своё состояние. Когда обе свечи закрываются одновременно, исторический планировщик сначала вычисляет внутреннее выражение. На ленте replay результат зависит от порядка поступления закрытий. Внешний рынок наблюдает последнее доступное ему значение при получении собственной свечи. Если эта свеча пропущена, изменение внутреннего рынка станет видно на следующем закрытии внешнего. Для внутреннего интервала не короче внешнего проверены оба режима gaps при `lookahead_off`. При `gaps_on` внешний вызов получает значение, если с предыдущей свечи его рынка закрылась новая внутренняя свеча. Курсор этой проверки восстанавливается из checkpoint. При смене внешнего рынка унаследованный символ разрешается отдельно для каждого маршрута. Даже при общем явно указанном внутреннем инструменте пересчёт в `syminfo.currency` использует валюту выбранного внешнего рынка.

Каждое окно `calc_bars_count` отсчитывается по фактическим свечам своего рынка. Пересчёт валюты выполняется на закрытии каждого уровня. Внутренний `currency=syminfo.currency` читает валюту непосредственно вызывающего рынка. Если внешний вызов задаёт свою валюту, его вход уже выражен в валюте результата внутреннего. Для двухминутного A в USD и минутного B в GBP проверены обе пары USD→GBP→EUR с изменением обоих курсов в середине расчёта. На четвёртой минуте B пропускает свечу, и значение на графике остаётся 10 EUR. На следующей свече B получает сохранённые 10 GBP и применяет новый курс 3 EUR за GBP. [Исполняемые проверки истории, replay и worker](../../tests/test_nested_market_clocks.py)

На двухминутном графике пример с минутными свечами A получает суммы 22, 30 и 38. В примере с тремя рынками и тремя уровнями предыдущие цены равны na, 30, 70, 16, 66 и 36. Для обоих проверяется полное совпадение результатов непрерывного и возобновлённого worker. [Сценарии](../../examples/dynamic-requests)
