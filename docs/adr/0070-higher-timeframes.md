# ADR 0070. Календарные интервалы и представление периода в Pine v6

Дата 2026-11-16. Статус accepted.

Границы старшего интервала вычисляет существующий календарь UTC 24×7
по времени открытия физической свечи. Он уже определяет совместимые
интервалы и использует календарную длину месяца. Пропущенные свечи остаются
отсутствующими в истории. Для HTF выбран полный UTC-период с пустой
сессией или `24x7`. Ограниченный режим явных часов описывает текущую
минутную свечу с отсечением закрытия. Это сохраняет определённый
смысл границ при переключении интервала.
[Профиль HTF](../HIGHER_TIMEFRAMES.md) · [ADR торговых часов](0069-trading-sessions.md).

Pine v6 возвращает множитель в `timeframe.period`. Для новой компиляции
выбрали отдельный контракт ссылки. В IR прежняя ссылка обозначает
канонический интервал. Рыночный план хранит каноническое значение
`D/W/M`, а диагностика цели может показать `1D/1W/1M`, полученное
выражением Pine. У старых вызовов и календарных вызовов отдельные ID
контрактов IR. Такой выбор закрепляет семантику в артефакте. Общее
изменение значения по номеру версии Pine меняло бы смысл старой ссылки v6.
[Правило миграции Pine v6](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-6/#timeframes-must-include-a-multiplier).

Артефакт и контрольная точка проверяют идентичность исполнения сборки.
Для восстановления старого задания используется его закреплённый wheel.
Запуск на новой сборке начинается с новой компиляции. Приёмка проверяет
обе формы ссылок и восстановление на соответствующем wheel.
