# ADR 0058. Границы рангов и хранение окна

Дата 2026-11-13. Статус accepted.

[Закреплённый bundle](../../spec/lock.json) содержит три функции ранга
в v1–v6 и медиану и моду в v4–v6. Для медианы и моды тип источника
определяет тип результата. Отбрасывание дробной части целочисленной
медианы в чётном окне — выбранное правило OpenPine.

Примечания v5–v6 различают окна, которые пропускают `na` или возвращают
`na` при пропуске. Эту модель применяем во всех допущенных версиях.
Описание `percentrank` говорит о предыдущих значениях, поэтому
текущий отсчёт исключён из выборки. Для линейного процентиля выбрана
интерполяция в позиции от 0 до `length - 1`, с минимумом и максимумом
на концах. Сравнение этих правил с исполнением TradingView остаётся
отдельным этапом. [Справочник Pine](https://www.tradingview.com/pine-script-reference/v6/) ·
[Изменение квалификатора длины](https://www.tradingview.com/pine-script-docs/release-notes/).

Каждый вызов использует существующий кольцевой буфер с пределом из
плана хранения. Динамическое окно может расти после уменьшения.
Нативная сортировка используется для медианы и процентилей, счётчик
частот для моды, прямой проход для ранга. В бюджет входят просмотр
отсчётов, обход частот и оценка сортировки
`ceil(length * ceil(log2(length)) / 8)`. Временная память учитывается
в бюджете задания и освобождается при завершении расчёта.

На Python 3.14.8 медианы локального замера линейного процентиля на
случайных данных составили 0,19, 2,39 и 29,14 мс на окнах из 1 000,
10 000 и 100 000 отсчётов. На 100 000 отсчётов мода заняла 45,24 мс,
ранг — 15,38 мс. Замер относится к одному вызову ядра на прогретом окне.
