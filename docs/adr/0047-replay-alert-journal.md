# ADR 0047. Журнал оповещений наблюдаемого replay

Дата 2026-11-11. Статус accepted.

Вызов `alert()` может сработать на открытой свече, после чего очередное
наблюдение откатывает переменные и рисунки preview. Публикация вместе
с закрытой свечой потеряла бы порядок и время таких оповещений.
[Модель срабатывания Pine](https://www.tradingview.com/pine-script-docs/concepts/alerts/#alert-function-events)

Runtime собирает намерения в порядке вызовов за проход. Replay применяет
частоту и хранит набор уже сработавших мест вызова до закрытия свечи.
Формулировка Pine о первом вызове на баре и пример с первым достижением
каждого места вызова допускают разные прочтения. Для OpenPine выбрано
первое достижение каждого места, как в примере. Условия `alertcondition()`
наблюдаются на закрытии. Точная эквивалентность остаётся предметом внешней
сверки. [Пример TradingView](https://www.tradingview.com/pine-script-docs/concepts/alerts/#using-all-alert-calls)

Воркеры сохраняют журнал оповещений в тех же неизменяемых блоках, что и
журналы рисунков. Ключ сортировки — номер входного события и порядковый
номер вызова внутри него. Состояние частоты, журнал и курсор публикуются
одной транзакцией. Повтор входного события сохраняет прежний журнал.
Блоки журнала участвуют в backup и сборке мусора.

Для replay с оповещениями используется `openpine.replay-checkpoint.2`.
`openpine.replay-checkpoint.1` сохраняет прежние правила чтения.
Подтверждённые ряды и рисунки используют действующие форматы префикса
вывода. [Профиль](../ALERTS.md)
