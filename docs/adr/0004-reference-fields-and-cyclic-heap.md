# 0004: Ссылочные поля UDT и циклическая общая куча

Статус: accepted. Дата решения и записи: 2026-11-02.

## Основание

Пользователь одобрил семь пунктов этапа ссылочных полей после матриц.
Общий heap уже хранит массивы, maps, матрицы и плоские UDT, но его прежний
подсчёт ссылок не освобождает недостижимые циклы. Раздельная куча объектов
потребовала бы повторить идентичности, алиасы, учёт ресурсов и восстановление.

[Система типов v5](https://www.tradingview.com/pine-script-docs/v5/language/type-system/)
и [v6](https://www.tradingview.com/pine-script-docs/language/type-system/)
описывает поля других UDT и коллекций, в том числе ссылки на свой тип.
[Objects v5](https://www.tradingview.com/pine-script-docs/v5/language/objects/)
и [v6](https://www.tradingview.com/pine-script-docs/language/objects/)
различает shallow copy и собственные `varip`-пометки полей.
Прямые коллекции коллекций не допускаются: дополнительное измерение задаётся
через поля UDT. Новый профиль сохраняет SHA записей неизменяемого Wiki bundle.

## Решение

`openpine.object-graphs.1` расширяет поля в v5/v6: scalar/enum, ранее объявленный
UDT или свой тип, существующий закрытый array/map/matrix. Forward type names,
прямая вложенность коллекций и рекурсия функций остаются за границей профиля.
Ссылочный default — типизированный `na`; вызовы в defaults не добавляются.
Конструктор вычисляет явные аргументы один раз в исходном порядке. `copy()`
создаёт новый внешний объект с теми же значениями и ID в полях.

Остаётся один heap. Подсчёт ссылок учитывает рёбра и внешние корни, а для
graph-программ GC вычисляет достижимость итеративно. Корни включают persistent
bindings, историю и необходимые preview-поля. Сначала проверяются память,
работа и отмена, затем публикуется сборка. Недостижимый цикл освобождается целиком.
Обходы ограничены существующими квотами; очередь содержит ограниченное число
ID, а повторные ссылки не размножают очередь пропорционально числу алиасов.

Перед переносом intrabar выбираются обычные поля из confirmed/constructor
baseline и помеченные поля из текущего объекта. Только затем обходится граф.
Сохранённая ссылка на UDT не продвигает его обычные поля. Обычная коллекция
восстанавливает baseline; коллекция, достигнутая через переносимый маршрут,
сохраняет содержимое для всех алиасов той же идентичности. Это явная ограниченная
интерпретация совместного действия rollback и ссылочных полей.

Для новых коллекций хранится constructor buffer. До первой записи он разделяет
буфер с живым объектом; перед записью COW защищает baseline и учитывает память.
Рёбра этих baseline участвуют в достижимости. На подтверждении бара transient
baseline удаляются до GC и не попадают в confirmed checkpoint.

Допуск `varip`-коллекций следует ограниченному прочтению
[v5 arrays](https://www.tradingview.com/pine-script-docs/v5/language/arrays/):
значения или UDT с полями-значениями и коллекциями значений. Прямое UDT-поле
в элементе такой коллекции отклоняется, включая рекурсивный тип. `varip` у самой
UDT-переменной переносит ID; поля UDT требуют собственных пометок. Этот допуск
не является доказательством всех сочетаний из текущего справочника v6.

Только программы со ссылочными полями используют typed-ir.19/runtime-state.12/
array-heap.5. JSON содержит типизированные ID, а восстановление идёт в два прохода.
Проверяются backing type, nominal type, достижимость от корней, счётчики и
constructor baseline. Временное состояние строится отдельно и публикуется после
успешной проверки. Старые профили, bundles и форматы сохраняются.

## Последствия и проверка

GC и перенос состояния имеют цену обхода графа. Restore с constructor buffers
требует дополнительного staging в прежнем бюджете памяти. Все лимиты остаются
прежними. Графика/color, object requests и object tuple-results не добавляются.

Независимые примеры: `conformance/object-graphs`; проверки: `test_object_graphs.py`.
Проверяются общие и циклические ссылки, удаление недостижимых циклов, shallow copy,
история, COW, every-event-cut replay, повреждённые checkpoint и атомарность отказов.
Восемь целых программ проходят общую цепочку приложения. Внешнее исполнение
TradingView остаётся отдельным этапом; при расхождении трактовок этот ADR уточняется.
