# ADR 0062. Окна ALMA, HMA и COG

Дата 2026-11-14. Статус accepted.

Динамическая длина ALMA и COG есть в закреплённом справочнике начиная с v4.
У HMA длина постоянна в пределах запуска. Справочник v5 содержит две записи
ALMA, v6 содержит одну запись с `floor` и значением по умолчанию `false`.
В OpenPine обе формы вызова v6 связываются с одной сигнатурой и используют
одинаковое состояние. [Длина ALMA](https://www.tradingview.com/blog/en/pine-functions-support-dynamic-length-arguments-20554/) ·
[Длина COG](https://www.tradingview.com/blog/en/more-pine-functions-support-dynamic-length-arguments-22719/) ·
[Справочник Pine v6](https://www.tradingview.com/pine-script-reference/v6/#fun_ta.alma).

Для COG выбрано окно определённых значений. Позиции весов считаются внутри
этого окна. Так правило игнорирования `na` применяется и к числителю, и к
знаменателю. HMA округляет половину длины и квадратный корень по формуле
Алана Халла. Для длины 1 укороченное окно также равно 1. При пропуске HMA
сохраняет результат и не добавляет повторный промежуточный отсчёт в сглаживание.
Пограничные результаты подлежат отдельной сверке с исполнением TradingView.
[Справочник COG](https://www.tradingview.com/pine-script-reference/v6/#fun_ta.cog) ·
[Формула HMA](https://alanhull.com/the-hull-moving-average/).

COG и HMA используют общий расчёт из точных префиксов WMA после приведения
входов к binary64. HMA хранит один буфер для обеих исходных WMA и второй
для сглаживания. Checkpoint сохраняет компактные входы и проверяемые якоря
через существующий кодек префиксов.

ALMA хранит один буфер отсчётов. При динамической длине актуальные веса
пересчитываются без долгоживущего кэша. Нормировка относительно ближайшего
отсчёта сохраняет ненулевой вес при узком распределении. Экспонента
вычисляется с фиксированной точностью для воспроизводимого результата на
Windows и Linux. Пересчёт проверяет бюджет и прерывание до записи в окно.
