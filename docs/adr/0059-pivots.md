# ADR 0059. Подтверждение экстремумов и границы окна

Дата 2026-11-14. Статус accepted.

В [закреплённом bundle](../../spec/lock.json) для v1–v2 записаны только
имена. В этих версиях OpenPine допускает обе позиционные формы с
`simple int` для плеч по аналогии с v3. В v3–v4 описаны обе формы
и `series`-аргументы. Профиль использует для плеч `series int`.
В v5–v6 справочник перечисляет и `float`, поэтому OpenPine принимает
его целочисленные значения. Для дробных плеч установлена диагностика.
[Справочник v3](https://www.tradingview.com/pine-script-reference/v3/#fun_pivothigh) ·
[Справочник v4](https://www.tradingview.com/pine-script-reference/v4/#fun_pivothigh) ·
[Справочник v6](https://www.tradingview.com/pine-script-reference/v6/#fun_ta.pivothigh).

Результат доступен при вычислении правого края окна. Руководство
описывает максимум как вершину с более низкими значениями по обе стороны.
В OpenPine из этого следует строгое сравнение, при равенстве кандидата
отбрасываем. При пропуске источника окно сохраняет позицию и даёт `na`,
а нулевое плечо оставляет соответствующую сторону пустой. Эти пограничные
правила и исторические сигнатуры требуют отдельной сверки с исполнением
TradingView. [Операторы Pine](https://www.tradingview.com/pine-script-docs/language/operators/) ·
[Метки на прошлых барах](https://www.tradingview.com/pine-script-docs/concepts/repainting/).

План истории ограничивает сумму плеч 100 000 предыдущих отсчётов.
Кольцевой буфер принадлежит вызову и его контексту. Запись отсчёта
происходит после проверки границ и расчёта. Replay использует существующий
слой изменённых ячеек, а checkpoint сохраняет счётчик, предел и значения
буфера. Существующие формы IR и checkpoint расширены новым видом состояния.
