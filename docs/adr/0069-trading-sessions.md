# ADR 0069. Границы пользовательской торговой сессии

Дата 2026-11-16. Статус accepted.

Пользовательская строка задаёт локальные часы и дни. По справочнику
Pine сессионные функции создают своё представление бара, включая
сокращённое закрытие. Для источника UTC 24×7 выбрали профиль текущего
минутного интервала и совпадения открытия бара с сеткой от начала
сессии. Так Pine-скрипт может фильтровать заявки на сохранённом
наборе свечей и получать закрытие последнего бара на границе окна.
Расчёт выполняется в runtime на основе закреплённых времени и интервала
исходного бара. Контракт IR проверяет обе ссылки.
[Руководство Pine по сессиям](https://www.tradingview.com/pine-script-docs/concepts/sessions/) ·
[Профиль OpenPine](../TRADING_SESSIONS.md).

Пояса загружаются из закреплённой IANA-базы. Каждую локальную границу
сопоставляем с UTC через проверку обратного преобразования. Пропуск
часа или два возможных времени на самой границе дают явную диагностику
для активного окна. Автоматический сдвиг или выбор первого повторения
мог бы переставить заявки на другие физические бары. Окно с однозначными
границами может проходить через переход DST и включать оба повторения
часа. Сопоставление с TradingView для границ DST и несовпадающих сеток
будет основанием для расширения профиля.
[ADR 0068](0068-time-format.md).

Запись v1 из закреплённого архива содержит позиционные формы
`time(x)` и `time(x, y)`. Для v2 используется документированная
совместимость с v1. Официальная миграция v4 → v5 подтверждает смену
дней по умолчанию. Будни для v1–v3 — принятое правило профиля на
основе исторического поведения v4. Явный суффикс дней позволяет
использовать один диапазон по всем версиям.
