# ADR 0038. Порядок рисования и положение относительно рынка

Дата 2026-11-09. Статус accepted.

Панель, шкала и порядок рисования определяют разные свойства слоя.
В общем рендерере истории и replay сначала определяем панель и шкалу,
затем составляем последовательность рисования для всей панели. Для рядов
и заливок сортировка использует позицию вызова из проверенного ID.
Для объектов одного вида действует порядок создания. Полилинии рисуются
после линий и перед прямоугольниками. Фон занимает нижнюю группу, таблицы
располагаются в отдельном интерфейсном слое над графиком. [Группы Pine](https://www.tradingview.com/pine-script-docs/visuals/overview/#z-index)

Справка устанавливает, что `force_overlay` имеет приоритет над
`overlay`, `behind_chart` и `scale` при размещении на главной панели.
В OpenPine принудительно наложенный ряд или рисунок находится перед
рынком. Для заливки с границами на одной шкале передний слой выбирается,
когда обе границы имеют принудительное наложение. Для смешанной пары
используем положение обычных слоёв скрипта. Фон панели всегда находится
под рыночным рядом. Положение полилиний, смешанных заливок и
принудительно наложенных объектов подлежит внешней сверке.
[Декларации Pine](https://www.tradingview.com/pine-script-docs/language/declaration-statements/#overlay-scale-and-behind_chart)

В новых исторических результатах Pine v4–v6 храним фактическую политику
`visual_order`, включая значения по умолчанию. В v4 поле
`behind_chart` внутри неё имеет значение `null`. Опции декларации
сохраняют позиции торговых параметров и совместимы со шкалой и форматом.
Чтение прежней декларации и старого диапазона сохраняет порядок
по отсутствию `visual_order`. Для Pine v1–v3 также используется этот
совместимый режим.
