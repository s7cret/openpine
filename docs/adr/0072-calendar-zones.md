# ADR-0072. Нумерация недель и преобразование локального времени

Дата 2026-11-17

Статус accepted

Справочники Pine v1–v6 содержат переменную и функцию `weekofyear`.
Они описывают номер недели времени открытия бара, но доступные
материалы оставляют правило первой недели года неоднозначным.
OpenPine использует ISO 8601: понедельник и первая неделя,
содержащая 4 января. Эта граница согласована с недельным началом в
UTC-календаре OpenPine и закреплена независимыми значениями на стыке
2015 и 2016 годов. [Справочник Pine](https://www.tradingview.com/pine-script-reference/v6/#var_weekofyear).

Ранние архивные руководства показывают обычный числовой `timestamp`,
а нормализованные списки параметров v3–v4 смешивают перегрузки. В
поле `syntax_spellings` закреплённого справочника v3 и v4 есть отдельная
запись с `timezone` первым параметром. Эта запись подтверждает
зональную форму в обеих версиях. В v3 необязательность подтверждена
для секунд. В v4–v6 зафиксированы нули для часа, минуты и секунды.
[Запись v3](../../spec/bundles/pine-spec-20261020.1/reference/v3.json) ·
[Запись v4](../../spec/bundles/pine-spec-20261020.1/reference/v4.json) ·
[Архив v3](https://www.tradingview.com/pine-script-docs/v3/essential/sessions-and-time-functions/).

При преобразовании локальной даты runtime использует закреплённую
IANA-базу и проверяет обратное преобразование для обеих сторон
перевода часов. Ноль подходящих UTC-моментов даёт
`TIMESTAMP_NONEXISTENT`, два — `TIMESTAMP_AMBIGUOUS`.
Фиксированное смещение даёт однозначный момент. Это решение OpenPine
сохраняет точность задания границы и оставляет сравнение особенностей
TradingView отдельной проверке.

Добавлены отдельные контракты для явного пояса. Они вычисляют
скалярные значения из закреплённых входов и не добавляют полей
в checkpoint. Действующие контракты UTC и строкового
`timestamp(dateString)` сохраняют прежние входы и диапазоны.
[Профиль и сценарии](../CALENDAR_ZONES.md).
