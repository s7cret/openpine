# ADR 0049. Оповещения защитных заявок и версия профиля replay

Дата 2026-11-12. Статус accepted.

`strategy.exit()` может закрыть часть позиции по одному из нескольких
уровней. Брокер уже выбирает сработавшую часть и разбивает исполнения по
целям, когда это требуется. В Pine v5–v6 выбор части определяет специальное
сообщение. [Журнал изменений Pine](https://www.tradingview.com/pine-script-docs/v5/release-notes/#may-2022)

Расчёт сообщения остаётся в replay. Брокер передаёт причину в момент
исполнения через внутренний callback. Это сохраняет порядок внутри
наблюдения и связывает текст с тем же `fill_id`, что и торговый журнал.
При отсутствующем специальном сообщении используется общий текст.
Флаг подавления хранится по идентификатору живой заявки и охватывает
защитные заявки, оставшиеся после частичного исполнения или сокращения OCA.

Replay с включёнными алертами для `order`, `close_all` или `exit`
использует `openpine.strategy-fill-alerts.2`. Такой replay начинается
с записи входных наблюдений, если прежний checkpoint использовал профиль
`.1`. Иначе опубликованный префикс мог бы содержать исполнения без алертов.
Для исходного набора `entry` и `close` сохраняется профиль из
[ADR 0048](0048-strategy-fill-alerts.md). Формат записей `order_fill`
и API чтения остаются прежними. Сверка с TradingView ведётся отдельно.
