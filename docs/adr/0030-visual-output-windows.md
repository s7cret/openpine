# ADR 0030. Окно отображения и координаты заливки

Дата 2026-11-08

Статус accepted

Закреплённый справочник v3–v4 объединяет обе сигнатуры `fill`
в одной записи. Первый вариант описывает заливку между `hline`,
а второй связывает `show_last` с заливкой между двумя `plot`.
В v5–v6 эти перегрузки уже записаны отдельно и подтверждают
ту же привязку. Поэтому `show_last` для пары `plot` доступен с v3.
В v3 требуется константа, а в v4 допускаем также `input` на основании
типа integer в источнике. V5–v6 указывают const/input явно.
[Справочник v3](../../spec/bundles/pine-spec-20261020.1/reference/v3.json) · [Справочник v4](../../spec/bundles/pine-spec-20261020.1/reference/v4.json) · [Руководство v4](https://www.tradingview.com/pine-script-docs/v4/annotations/filling-in-the-background-with-fill/) · [Сигнатуры v6](https://www.tradingview.com/pine-script-docs/visuals/fills/#plot-and-hline-fills)

Используем отсчёт окна от конца расчёта по исходным барам из ADR 0029.
Каждая граница `fill` сначала отбирает значения своего `plot` и
проецирует их в координаты после смещения. Сам `fill` отбирает цвет
и пары границ в координатах графика. Пропуски могут соединяться
только в пределах окна заливки и при `fillgaps=true`. Пересечение
левой границы окна потребовало бы использовать скрытую точку и
создавало бы видимую заливку вне заданного диапазона.
[ADR 0029](0029-signal-arrow-window.md)

Именованные параметры активируют отдельные ABI. Статический
сдвиг `plot` ограничен существующим пределом чтения смещённых
визуальных точек. Дескриптор результата содержит окно и сдвиг,
а строки Parquet хранят рассчитанные значения и цвет исходного
бара. Так полный экспорт остаётся пригоден для повторного
расчёта и сравнения, а пагинация читает только нужный диапазон.
Точная отрисовка граничных сегментов в TradingView проверяется отдельно.
