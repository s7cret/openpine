# ADR 0048. Оповещения при исполнении заявок стратегии

Дата 2026-11-11. Статус accepted.

Заявка может ожидать несколько наблюдений, быть заменена или отменена.
Документация Pine связывает `alert_message` с моментом исполнения.
`disable_alert` относится к заявке, которую создал вызов команды.
[Сообщение в Pine v4](https://www.tradingview.com/pine-script-docs/v4/essential/alerts/#order-fill-events) ·
[Справочник Pine v5](https://www.tradingview.com/pine-script-reference/v5/#fun_strategy.entry)

Брокер сообщает движку replay фактическое исполнение вместе с идентификатором
заявки и местом вызова. При построении локальной записи replay вычисляет
сообщение по первичной свече этого наблюдения. Для первого профиля выбраны
литералы, поля свечи, скалярные операторы и преобразование в строку. Этот
набор позволяет вычислять текст в изолированном контексте без повторного
расчёта стратегии. Сторона replay хранит только флаги подавления живых
заявок, привязанные к выданным брокером идентификаторам.

Включение профиля входит в идентичность replay. Внутреннее состояние
`openpine.replay-alert-state.2` проверяет флаги по восстановленным
заявкам. Записи `order_fill` используют существующий журнал, транзакцию
публикации и API чтения. Для replay с одними `alert()` и
`alertcondition()` действует состояние из [ADR 0047](0047-replay-alert-journal.md).
Профиль применяется к `strategy.entry()` и `strategy.close()`.
Сравнение порядка и текста с TradingView остаётся отдельной проверкой.
