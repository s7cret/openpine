# ADR 0064. Цвет события и сигнатуры `change`

Дата 2026-11-15. Статус accepted.

Закреплённый справочник v5 содержит отдельные однопараметрические строки
`ta.change`. Опущенная длина связывается как `1` через существующий ABI.
В матрице эти строки сопоставляются с допущенной формой по значению
аргумента по умолчанию. OpenPine сохраняет допуск изменяемой длины в
v1–v3 для уже компилируемых скриптов. TradingView объявил эту возможность
в v4. [Динамическая длина в Pine](https://www.tradingview.com/blog/en/pine-functions-support-dynamic-length-arguments-20554/).

Цветовая форма `ta.valuewhen` имеет отдельный ID в v5–v6 и использует
существующий runtime операции `signals.valuewhen`. Выбор формы опирается
на тип источника. Так `color(na)` попадает в цветовую форму, а обычный
`na` сохраняет числовой ABI. Пропущенный цвет учитывается как событие при
истинном условии. [Справочник Pine](https://www.tradingview.com/pine-script-reference/v6/#fun_ta.valuewhen).

В исполнении цвет хранится как канонический `#RRGGBBAA`. Checkpoint
записывает его одним целым в диапазоне 0…2³²−1 и сохраняет `null` для
пропуска. Это уменьшает расход памяти при разборе очереди из 100 000
событий. При восстановлении число проверяется и разворачивается в
исходный RGBA. Сверка с исполнением TradingView остаётся отдельным этапом.
