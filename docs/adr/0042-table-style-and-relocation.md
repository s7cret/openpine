# ADR 0042. Оформление и перенос таблиц

Дата 2026-11-10. Статус accepted.

Справочник Pine v4–v6 фиксирует операции и параметры стиля.
Документация сообщает, что в общей позиции отображается таблица,
созданная позже. Жизненный цикл ID при переносе в занятую позицию в
этом описании не задан. [Закреплённая спецификация](../../spec/lock.json) ·
[Ограничения Pine](https://www.tradingview.com/pine-script-docs/writing/limitations/#table-limits)

OpenPine сохраняет одну живую таблицу на позицию во всех панелях.
При коллизии ID с большим порядковым номером остаётся, другой удаляется.
Это распространяет действующее правило `table.new()` на перенос.
`table.all` и лимит ячеек используют то же состояние. Перенос в
свободную позицию сохраняет порядок создания и данные объекта.

Современная документация разрешает заполнять пустые ячейки через
`table.cell_set_*()`. Применяем общее правило для v4–v6, используя
умолчания `table.cell()` для незаданных полей. Пропуск цвета в setter
сбрасывает его к `na`, пропуск ширины задаёт ноль. Внутренние проверки
фиксируют эти решения. Наблюдения TradingView для v4 и поведения
вытесненного ID при переносе относятся к отдельной сверке.
[Справка по ячейкам](https://www.tradingview.com/pine-script-docs/visuals/tables/#creating-and-displaying-tables)

Тип записи расширяется только при задании полей рамки или сетки.
Старые записи и старые варианты вызова сохраняют форму. Для нового
состояния проверяются полный набор полей, значения и уникальность позиций.
Ширина рамки и сетки ограничена 64 пикселями в профиле OpenPine.
[Профиль OpenPine](../TABLE_STYLE.md)
