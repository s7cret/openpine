# Поиск и регистр строк в Pine v5 и v6

Функции доступны в выражениях исторического профиля. Сохранённый профиль вычисления символа и интервала для рыночных запросов сохраняет прежний список операций.

В закреплённом справочнике у каждой функции три перегрузки. Литеральные аргументы дают результат `const`, аргументы `input` и `simple` дают `simple`, а любой аргумент `series` даёт `series`. Тип каждого аргумента — `string`. Имена параметров сохранены для именованных вызовов.

| Вызов | Результат | Проверяемый пример |
| --- | --- | --- |
| `str.lower(source)` | string | `"AbAb"` → `"abab"` |
| `str.upper(source)` | string | `"Straße"` → `"STRASSE"` |
| `str.startswith(source, str)` | bool | `"AbAb", "Ab"` → true |
| `str.endswith(source, str)` | bool | `"AbAb", "AB"` → false |
| `str.pos(source, str)` | int | `"AbAb", "Ab"` → 0, `"AbAb", "AB"` → na |

`str.pos` возвращает индекс первого вхождения с нуля. Для пустой искомой строки индекс равен нулю, обе проверки края истинны. Сравнение чувствительно к регистру.

OpenPine считает индексы в кодовых точках Unicode и использует стандартное преобразование регистра Python 3.14.8 без нормализации. Отсутствующее строковое значение даёт `na`, кроме результата типа bool в v6, где оно даёт false. Действуют лимит 4096 кодовых точек на входную и выходную строку и общий бюджет работы скалярных функций. Поэтому статус всех 30 перегрузок — PARTIAL. Побарные примеры и ожидаемые ряды входят в [корпус](../conformance/scalar-targets/cases.json).
