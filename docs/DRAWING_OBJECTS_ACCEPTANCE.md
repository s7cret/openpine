# Приёмка копирования и перебора графических объектов R6

[Исходник 187748523bec](https://github.com/s7cret/openpine/commit/187748523becc96e876fa398eb843f2b874e43e1) · [Веточная проверка](https://github.com/s7cret/openpine/actions/runs/42711103707) · [Приёмка по тегу](https://github.com/s7cret/openpine/actions/runs/42711103817)

CI 57/57, Python 3.14.8. В реестре каждой ОС 1 946 тестов. Conformance охватывает 4 436 сценариев, корпус — 180 программ.

- В Pine v5–v6 проверены `line.copy()`, `label.copy()` и `box.copy()`,
  новый ID, наследование свойств и вытеснение на лимите. В v1–v4 проверены отказы.
- Все шесть переменных `*.all` проверены на живых объектах и после удаления.
  Покрыты порядок ID, стабильный перебор снимка, типы, индексы v5/v6,
  отказ при изменении массива и списание бюджета за прочитанные ID.
- Установленный wheel на обеих ОС подтвердил загрузку IR, возобновление
  исторического задания, совпадение журнала с replay, изоляцию preview
  и удаление зависимой заливки. Прошли 19 браузерных
  регрессионных сценариев.
- На Windows прошло 1 946 тестов, на Linux — 1 945.
  Linux пропустил проверку псевдонимов файлов Windows 8.3.
  Прошли четыре сценария восстановления.
- Сохранены наблюдения всех 4 425
  прежних сценариев. Добавлено 11 сценариев.
  Отчёты conformance совпадают между Windows и Linux.

Снимки относятся к текущему расчёту индикатора и перестраиваются
из восстановленных объектов. Для копии отсутствующего ID OpenPine
возвращает `na`. Сверка поведения с TradingView проводится отдельно.
