# Матрицы v5/v6

Профиль `openpine.matrices.1` добавляет прямоугольные `matrix<T>` для `int`,
`float`, `bool`, `string`, номинальных enum и плоских UDT. В v1–v4 используется
явный `MATRIX_VERSION`; скалярные контрольные программы остаются доступны.

Поддержаны `new`, `get`, `set`, `fill`, `rows`, `columns`, `elements_count`,
`copy`, `row`, `col`, `add_row`, `add_col`, `remove_row`, `remove_col`,
`swap_rows`, `swap_columns`, `reshape`, `transpose`, `na`, методы и UDF.
Порядок вычисления: receiver один раз, явные аргументы в исходном порядке,
затем закрытые defaults. Сохраняются общий Binder и выбор пользовательских методов.

```pine
//@version=6
indicator("Matrix")
var m = matrix.new<float>(1, 2, 0.)
m.set(0, 0, m.get(0, 0) + close)
m.set(0, 1, close)
plot(m.transpose().get(0, 0))
```

В общей куче каждый объект имеет одну идентичность, два размера и плоский
row-major буфер. Индексы определённые, неотрицательные в обеих версиях.
Каждое измерение 0…100000, произведение не более 100000. Общие лимиты кучи,
памяти и работы сохранены. Нулевые измерения сохраняются; только форма 0×0
выводит противоположный размер из вставляемого массива.

Defaults: конструктор 0×0 с типизированным missing, `bool` v6 — `false`;
вставка в конец; удаление последнего допустимого индекса; `fill` всей матрицы
с полуоткрытыми границами; отсутствующий `array_id` вставляет missing-вектор.
`remove_row/col` возвращают независимый массив. `reshape` меняет форму на месте,
сохраняя число и row-major порядок элементов. `transpose` создаёт новую матрицу.

Присваивание разделяет идентичность. `copy`, `transpose`, `row`, `col` и
вставляемый массив разделяют только UDT-объекты; их слоты и формы независимы.
Изменение поля UDT видно через все алиасы; замена слота — только в своём контейнере.

`for row in m` и `for [index,row] in m` фиксируют форму и число строк при входе.
Перед итерацией читается независимая копия текущей строки; изменения ячеек
матрицы видны последующим строкам. Изменение формы вызывает
`MATRIX_ITERATION_SHAPE` при следующей итерации; `break` завершает обход сразу.
Создаваемые строки входят в обычные ограничения кучи. Эта политика изменения
во время обхода — явная трактовка OpenPine, требующая внешнего сравнения.

Записи транзакционно подготавливают весь новый буфер. Для удаления заранее
проверяются и итоговая матрица, и возвращаемый массив. Ошибка бюджета или отмена
не публикует частичную форму, слоты или ID. Цена изменения/копии растёт с размером
буфера; это ограниченная reference-реализация, не обещание постоянного времени.

Программы с матрицами используют `typed-ir.18`, `runtime-state.11`,
`array-heap.4`; прежние программы сохраняют свои форматы. В checkpoint ссылки
на UDT упакованы как ID. Поддержаны COW preview, история идентичностей,
обычный откат и field-level `varip`, в том числе восстановление на срезах событий.

Вне исходного профиля остаются линейная алгебра за исключением trace, sum, diff и mult, `color`, графические типы, вложенные коллекции,
reference-поля UDT, матрицы в request-выражениях и tuple-результатах.

Источники и противоречия: [ADR 0003](adr/0003-matrices-on-shared-reference-heap.md),
`spec/matrices-profile.json`; независимые конечные ожидания —
`conformance/matrices`, восемь целых программ — `examples/corpus/matrices-*`.
Внутренняя приёмка не устанавливает эквивалентность TradingView.

[Квалификация и точные свидетельства](MATRICES_ACCEPTANCE.md).

Ссылочные поля UDT дополнительно поддержаны [профилем object graphs](OBJECT_GRAPHS.md).
Ограничения плоских объектов выше относятся к исходному профилю.

## Числовые результаты в v5/v6

Для min, max, avg, median, mode и trace принимаются матрицы int и float. Результат имеет тип элемента и квалификатор series. Целочисленные среднее и медиана округляются к нулю. Передача через id и вызов метода работают с той же матрицей и сохраняют порядок ячеек.

Закреплённый справочник явно исключает пропуски при расчёте median и mode. При нескольких модах выбирается наименьшее значение среди наиболее частых. OpenPine также исключает пропуски у min, max и avg. Если определённых значений нет, результат na. Медиана чётной выборки равна среднему двух центральных элементов. Среднее рассчитывается с точным промежуточным суммированием.

Trace суммирует только главную диагональ. В профиле OpenPine прямоугольная неквадратная матрица даёт MATRIX_SHAPE, пустая диагональ или пропуск на ней дают na. Пропуски за пределами диагонали на результат не влияют. Выход суммы за диапазон результата даёт MATRIX_NUMERIC. Эти граничные правила приняты как трактовки OpenPine. Все 24 версионные записи имеют статус PARTIAL.

## Арифметика матриц v5/v6

Первый аргумент `id1` — числовая матрица. Новый результат получает независимый буфер. Именованные аргументы и вызовы методов используют те же правила.

| Операция | Второй аргумент | Результат |
| --- | --- | --- |
| `sum`, `diff`, `mult` | Скаляр | Матрица той же формы, операция применяется к каждой ячейке |
| `sum`, `diff` | Матрица той же формы | Поэлементная сумма или разность в порядке `id1 - id2` |
| `mult` | Матрица K×N | Для первого аргумента M×K результат имеет форму M×N |
| `mult` | Массив длины K | Для первого аргумента M×K результатом служит массив длины M |

Профиль сохраняет тип `int` для двух целочисленных операндов и выбирает `float`, если хотя бы один операнд вещественный. Несовместимые размеры дают `MATRIX_SHAPE`. Пропуск в слагаемом или множителе даёт `na` в соответствующей ячейке. Скалярное произведение длины ноль равно нулю. Каждая вычисленная пара множителей расходует бюджет работы. Переполнение конечного результата даёт `MATRIX_NUMERIC`.

Продвижение типов и точное промежуточное суммирование с однократным округлением вещественного результата — трактовки OpenPine. Все 16 записей перегрузок имеют статус PARTIAL.

## Предикаты v5/v6

Все десять функций возвращают `series bool` и читают матрицу без копирования. `is_square` сравнивает размеры матрицы любого поддерживаемого типа. Остальные девять функций принимают `int` и `float`. Вызовы `matrix.is_square(id=m)` и `m.is_square()` эквивалентны.

| Предикат | Условие |
| --- | --- |
| `is_zero`, `is_binary` | Для любой формы все ячейки равны нулю либо, соответственно, принадлежат множеству {0, 1} |
| `is_identity` | На главной диагонали единицы, вне неё нули |
| `is_diagonal`, `is_antidiagonal` | Все элементы вне соответствующей диагонали равны нулю |
| `is_triangular` | Все элементы строго выше либо все элементы строго ниже диагонали равны нулю |
| `is_symmetric`, `is_antisymmetric` | Матрица равна своей транспонированной матрице либо её отрицанию |
| `is_stochastic` | Непустая квадратная матрица, значения каждой строки от 0 до 1 и сумма строки равна 1 |

Закреплённая wiki v5/v6 указывает квадратную форму для структурных проверок. Для стохастичности она называет свойство без направления суммирования. OpenPine проверяет строки, используя `math.fsum` и сравнение с единицей без допуска. Остальные сравнения также точные для хранимых значений. Значение `na` не удовлетворяет проверяемому равенству. Ячейки, свободные по определению свойства (например диагональ у треугольной матрицы), могут содержать `na`. Отсутствующая ссылка даёт `MATRIX_NA`.

Для формы 0×0 все предикаты, кроме стохастичности, возвращают true. У прямоугольной неквадратной матрицы true возможен только для `is_zero` и `is_binary`. Это граничные правила OpenPine. Бюджет работы учитывает проверку формы и каждое чтение ячейки.
