# Локальная спецификация Pine v1–v6

`lock.json` закрепляет локальный снимок `bundles/pine-spec-20261020.1`, его manifest, схему и шесть языковых профилей. Для чтения и проверки снимка достаточно файлов этого репозитория и установленных зависимостей из `requirements-dev.txt`. Читатель не использует сеть, внешние checkout или исходники прежних библиотек.

Состав снимка:

- `reference/v1.json` … `reference/v6.json` — 4631 справочная запись с исходными идентификаторами, написаниями сигнатур/типов/defaults и происхождением. У каждой записи `review_status=reference_only` и `executable_contract=false`. Полные текстовые пулы каталогов и интерфейс справочника не включены.
- `semantic/pine6.core-mvp.1-20261020.r2/` — исходный неизменяемый комплект из семи файлов, сохранённый побайтово. В нём машинные правила, грамматика ограниченного профиля, стабильные identities, сведения о проверках и примеры.
- `review/registry.json`, `review/grammar.json` — исходные канонические данные для проверки решений о правилах и соответствия опубликованной semantic-проекции.
- `attribution/` — исходные LICENSE, NOTICE и THIRD_PARTY.md. Их относительные ссылки описывают исходную поставку; полный исходный сайт сюда не переносился.
- `manifest.json` — состав снимка, SHA-256 каждого файла и использованных входов, исходная ревизия Git.

`profiles/pine-v1.json` … `profiles/pine-v6.json` — локальные профили OpenPine. Общий реестр хранит явные scope версий; профили не наследуют правила других версий автоматически. Только v6 ссылается на принятый срез `pine6.core-mvp.1`. Отдельные утверждения с областью v3–v5 и три неопределённых default v5 сохранены в реестре; это не готовые исполняемые профили старых версий.

Профиль без указанной версии выбирает v1. Compiler уже читает аннотацию версии; исполнение v1–v5 возвращает явный `IMPLEMENTATION_MISSING`.

`coverage.json` вычисляется из допущенных данных и описывает покрытие спецификации. Языковые профили версии схемы `openpine.spec.profile.2` содержат применимость правил, без статуса реализации. Покрытие исполнения и фактические результаты нового движка хранятся отдельно в [conformance](../conformance/README.md); исходный consumer, его сборка и результаты его тестов новому движку не присваиваются.

## Проверка

Используется Python 3.14.8:

```sh
python -m pip install -r requirements-dev.txt
python -m tools.release_gate
```

Для одной проверки данных: `python -m tools.verify_spec`. Все проверки данных после установки зависимостей работают офлайн.

Порядок аргументов, параметров и tuple остаётся значимым. Читатель отклоняет лишние/изменённые файлы, несовместимый профиль, повторные идентификаторы, JSON с повторными ключами или нечисловыми значениями и изменение принятого значения без соответствующего review decision.

## Повтор импорта

Импорт выполняется вручную из локального чистого checkout источника. Импортёр записывает его точный commit и сравнивает каждый использованный вход с Git blob на этом commit. Полученная копия исходного репозитория не входит в зависимости OpenPine.

```sh
python -m tools.import_spec --source /path/to/source-checkout --release pine-spec-20261020.1 --check
```

Команда с `--check` воспроизводит импорт без записи и сравнивает байты. Для обновления выбрать новый `--release` и убрать `--check`: существующий снимок с отличающимися байтами перезаписать нельзя. Перед принятием обновления нужно рассмотреть изменение правил, версии, defaults и новые источники; импортёр проверяет целостность и связи, но не выполняет независимую проверку истинности всех правил Pine.
