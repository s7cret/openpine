# Первый корпус OpenPine

`literal-harness/cases.json` задаёт восемь собственных программ и независимые ручные ожидания: три успешных исполнения и пять ожидаемых отказов. Числа 2.5, 7, 3.0 и 4.0 заданы непосредственно из определения абсолютной величины. Ожидаемые значения не вычисляются кодом OpenPine и не копируются из результатов запуска.

Каждый случай связан с исходником и версией языка. Корпус ссылается на принятые assertions/rules закреплённой спецификации. Результаты внешнего Pine Editor в этом корпусе не заявляются.

Запуск: `python -m tools.conformance`. Команда действительно компилирует и исполняет программы, проверяет точные типы и результаты, диагностические категории/коды и сравнивает полученный отчёт с `results/literal-harness.1.json`. Эталонные ожидания команда не изменяет.

После намеренного изменения реализации: рассмотреть изменения, затем выполнить `python -m tools.conformance --write-report` и проверить diff отчёта. Он содержит hashes исходников, ожиданий, типизированного IR, реализации, spec lock и Python 3.14.8. Изменение кода без обновления проверенного отчёта обнаруживается общим gate.

Три успешных программы проверяют только literal/call harness с одним синтетическим наблюдением. Пять отказов подтверждают границы: недопустимый bool, повтор аргумента, отсутствующие реализации v5/v1 и известная операция `math.round` без kernel. Это не процент совместимости с Pine и не тест временных рядов.
