# Первый корпус OpenPine

`literal-harness/cases.json` задаёт восемь собственных программ и независимые ручные ожидания: три успешных исполнения и пять ожидаемых отказов. Числа 2.5, 7, 3.0 и 4.0 заданы непосредственно из определения абсолютной величины. Ожидаемые значения не вычисляются кодом OpenPine и не копируются из результатов запуска.

Каждый случай связан с исходником и версией языка. Корпус ссылается на принятые assertions/rules закреплённой спецификации. Результаты внешнего Pine Editor в этом корпусе не заявляются.

`historical-bars/cases.json` добавляет 11 случаев: пять успешных программ и шесть отказов. Это `plot(close)`, EMA длины 3, независимые и вложенные вызовы, начальные/промежуточные пропуски и int → float. Отказы проверяют нулевую/отрицательную длину, неверные типы, v5 и отсутствие баров. Собственные входные данные находятся в `fixed.json` и `missing.json`; это синтетические close-only fixtures, не выгрузка рыночных данных.

Ожидания EMA заданы ручным расчётом: при длине 3 коэффициент равен 1/2, поэтому 10, 20, 30, 40 дают 10, 15, 22.5, 31.25. EMA этого результата даёт 10, 12.5, 17.5, 24.375. Отдельный unittest сравнивает другие длины с независимой формулой взвешенной суммы на точных дробях. Наблюдений внешнего Pine Editor эти проверки не заменяют.

Запуск: `python -m tools.conformance`. Команда компилирует и исполняет оба корпуса, проверяет точные типы и результаты, диагностические категории/коды и сравнивает полученные отчёты с `results/literal-harness.1.json` и `results/historical-bars.1.json`. Эталонные ожидания команда не изменяет.

После намеренного изменения реализации: рассмотреть изменения, затем выполнить `python -m tools.conformance --write-report` и проверить diff отчётов. Они содержат hashes исходников, ожиданий, типизированного IR, реализации, spec lock, входных баров и Python 3.14.8. Изменение кода без обновления проверенного отчёта обнаруживается общим gate.

Три успешных программы проверяют только literal/call harness с одним синтетическим наблюдением. Пять отказов подтверждают границы: недопустимый bool, повтор аргумента, отсутствующие реализации v5/v1 и известная операция `math.round` без kernel. Это не процент совместимости с Pine и не тест временных рядов.

Исторический корпус проверяет только Pine v6, последовательные подтверждённые бары одного контекста и реализованные операции. Он не заявляет realtime, request contexts, стратегий или совместимости v1–v5. Дополнительные unittest проверяют хронологию, целостность входов, отсутствие будущих данных, сброс состояния между запусками и несовместимый IR.
