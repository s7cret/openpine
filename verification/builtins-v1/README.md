# Independent builtin examples, revision 1

This corpus adds 47 engineering cases to the unchanged Stage 1 corpus. Expected
numbers were authored before execution from elementary identities and rational
moving-average calculations. No fixture was generated by importing PineLib or
running OpenPine. Every case retains source/data/settings/expected hashes,
explicit tolerance, exact Pine version and provenance through the existing
`openpine.conformance_corpus.v1` format. `lock.json` freezes the denominator.

The examples cover signed rounding ties, the v4+ precision overload, exp(0),
sqrt(4), integer power, SMA/WMA incomplete windows and rising RSI. The shared
input is `[1, 2, 4, 8, 16]`. SMA numerators are 7, 14 and 28 over 3. WMA
numerators are 17, 34 and 68 over 6. The first two observations have incomplete
three-value windows. RSI has two initial missing values followed by 100 after
strictly positive changes; that example does not establish general RMA seeding.

The test runner executes five paths for every example: direct ABI, generated
historical code, interim realtime updates followed by final values, explicitly
aborted callbacks followed by retries, and JSON checkpoint continuation. Final
values are compared to the same independent table. Interim callbacks deliberately
use a different value so failed rollback changes a stateful numerical result.
These in-process paths are labelled explicitly; they cannot be relabelled as a
protected-worker result. Worker integration is checked separately.

The exact frontend overload, actual compiler binding, target identity, catalogue
identity, execution path and parameter contract hash accompany observations.
`python -m openpine.verification builtin-surface --output surface.json` lists the
entire installed callable-signature denominator. `builtin-expected` joins
reviewed assignments and observations using the existing conformance comparator.
Rows without observations remain missing. A passing example count never marks a
whole signature, the full catalogue, or Stage 2 accepted.

catalogue; these mathematical cases are not external TradingView execution
exports. Modern EMA/MACD first-observation seeding is deliberately absent until
independent version-specific evidence settles it. NA-input policies, qualifier
variants, arbitrary periods, other builtin families and unsupported overloads
remain in the wider acceptance denominator. `tradingview_verified=false`.
